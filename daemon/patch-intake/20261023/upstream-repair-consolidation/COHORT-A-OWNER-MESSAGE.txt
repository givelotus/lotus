http: replace libevent evhttp with Boost.Beast HTTP/1.1 + async_detect_ssl + zstd server

The RPC/REST HTTP server now runs on Boost.Beast over a Boost.Asio
io_context (-rpciothreads, default 2) instead of libevent's evhttp.
Handlers still run on the existing -rpcthreads work queue with the same
-rpcworkqueue admission limit, and the public httpserver.h API
(HTTPRequest, RegisterHTTPHandler, HTTPEvent, EventBase) is unchanged for
callers: httprpc.cpp and rest.cpp need no changes.

Each accepted connection is classified with beast::async_detect_ssl, so
one port serves both plain http:// and TLS https://. TLS uses
-tlscert/-tlskey, or (default -tlsephemeral=1) a self-signed EC P-256
certificate generated once in <datadir>/node_tls_{cert,key}.pem.
-tlsmutual=1 requests, without requiring, client certificates and exposes
their SHA-256 fingerprint via HTTPRequest::GetClientCertFingerprint().

Replies of at least 512 bytes are sent with Content-Encoding: zstd (level
1) when the request's Accept-Encoding lists zstd, and request bodies with
Content-Encoding: zstd are decompressed (bounded by the body limit).

Behaviour kept from evhttp: keep-alive/Connection handling, 400 on
oversized headers, the ACL check, the -rpcservertimeout idle timeout,
default Content-Type, HEAD without body, and libevent's query-string
semantics (now parsed without libevent, including RFC 3986 validation).
libevent remains linked for torcontrol and bitcoin-cli.

Build: OpenSSL and zstd are now required for the server library; a
FindZstd module and a depends zstd package (static libzstd) are added.
