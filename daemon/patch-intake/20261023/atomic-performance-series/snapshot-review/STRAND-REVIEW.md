# Commit 12: per-peer Asio strand migration review

Read-only design review, 2026-10-23. Fixed shared `cbc4e72925652e3c8676ed0b24fce22874be0dc1`, native `a8e0eefd3e8f90120229cf7d12ed4100ddec8726`, inspected with Git object reads in the existing source checkout. No source edits, worktrees, clones, builds, tests, or benchmarks. References below are **shared** line numbers unless explicitly native. This report is uncommitted for parent review/staging.

## Decision

A strand serializes one peer's participating handlers; it provides neither protection for manager-wide state nor ordering against callbacks that bypass it. Commit 12 is too large to safely implement as one lock-removal commit. Introduce bounded scheduling first while retaining the global lock, then migrate explicit ownership groups in independently tested commits. Do not remove annotations or replace real mutex guards with comments claiming strand ownership.

Two immediate counterexamples to naive parallel dispatch:

1. `QueueTxForAdmission`, `src/net_processing.cpp:3410–3438`, relies explicitly on `g_msgproc_mutex` serializing all producers between `HasRoom` and `Push`. Two peer strands can both observe room, then one hits `Assert(pushed)` or escapes the intended capacity bound. Global in-flight dedup, queue capacity reservation/enqueue, per-peer pending accounting and producer shutdown fencing need one defined transaction, not separate atomic flags.
2. `PrepareMessageTurn:6451` clears/repopulates a single cross-peer preverification map, while `ProcessAvaResponseBatch:6620–6624` and AVARESPONSE dispatch `:8499` communicate using a single `m_preverified_ava_response`. Concurrent peer handlers can consume another peer's parsed response. Move scratch into explicit immutable turn/message objects bound to exact peer generation/key/hash/signature; do not simply put the optional on an arbitrary strand.

## Current serial boundary

`CConnman::ThreadMessageHandler`, `src/net.cpp:3384`, holds `g_msgproc_mutex` for its entire lifetime, including randomized peer traversal, cross-peer `PrepareMessageTurn`, receive then send for every interface, and waits. Interface annotations are `src/net.h:929–948`; public direct `PeerManager::ProcessMessage` test entry also requires this lock (`net_processing.cpp:996`). Initialization/finalization already happen on other paths (`net.cpp:2082,3328,3915`), so the old global lock never replaced their explicit lifetime/locking requirements.

## Bounded scheduling API and ordering

Propose node-owned `MessageExecutor` with fixed worker count, one `PeerDispatchState` per connection incarnation containing strand, owning node lease (`AddRef/Release`), `PeerRef`, generation, closing flag and a synchronized ready-reason bitmask plus `scheduled/running` state. Register it completely before making the node dispatchable. `RequestPeerTurn(id,generation,reason)` coalesces wakeups: at most one queued/running turn per peer, plus one coalesced continuation. Pending reason exchange and scheduled-clear/recheck form one synchronized state transition to prevent lost wakeups. Use a bounded ready-peer registry/queue sized to active connection limit and explicit limits for producers; plain Asio `post` per receive/timer event is unbounded despite a fixed worker count. If ready capacity is exhausted retain a coalesced ready bit and wake coordinator; never drop protocol bodies silently.

A turn has a bounded message/byte/time work quantum, preserves existing coalescing limits and receive-then-send ordering across **all interfaces**, checks interrupt/disconnect/backpressure between units, then yields. CPU-expensive work that waits on other pools must not starve all message workers; use owned preparation continuations or proven nonblocking pool fallback, never wait on a future requiring the same executor. Repeated timer events and admission completions wake a suspended peer through the coalesced registry; no polling spin while queue full or `fPauseSend`. Preserve randomized/fair peer selection and privacy tick scheduling rather than letting one flooding peer monopolize continuations.

Strands order only operations submitted with an established happens-before relation. Two unrelated producers posting messages do not establish application causal order. Give outbound protocol commands explicit per-connection sequencing at a common ingress when their relative order matters (handshake before capability-dependent data, request before response, admission verdict before later inbound message). `CNode::cs_vSend` (`net.h:491`) protects queue bytes; it does not establish these causal rules. Existing direct pushes from validation/Avalanche/transport paths must be audited and either sequenced or explicitly declared independent.

## Admission, callbacks and futures

Keep global commit-order admission-result processing on one bounded coordinator initially. `ProcessTxAdmissionDone:3442–3475` currently drains all peers in commit order while holding `cs_main`; routing immediately to unrelated strands would change reject/orphan/package/replay ordering. Split global bookkeeping from target peer completion only with explicit sequence numbers and proven equivalent semantics. The target may resume held inbound messages only after its earlier results and deferred malformed-prefix exception are handled. `DROPPED/REPLAY/RESULT` and duplicate-copy waiting must survive disconnects and queue pressure unchanged.

An atomic queue API should reserve admission bytes/slots and dedup before publishing; rollback all claims on failure. Stop admission through a producer gate that closes, waits for admitted producer critical sections to exit, then interrupts/joins admission. Current `StopTxAdmission:3323` uses global lock as exactly that gate; merely storing `running=false` is insufficient. Completion dispatch owns results/tx refs and bounded retained budgets; cancellation returns reservations and resolves pending promises exactly once. No handler holds chain, peer, queue or send lock while synchronously waiting for another strand/coordinator/admission result.

`NewPoWValidBlock:3619–3627` builds deferred shared futures with reference-capturing lambdas, safe only within current synchronous scope. If send work escapes to strands, eagerly serialize or capture owned shared block/compact objects by value. `PrecomputeTxRelayBatch:5857` also waits for worker futures; verify executor independence/inline fallback before running it on every peer strand. Validation callbacks and scheduler callbacks capturing `this` (`StartScheduledTasks:3487`, relay tick) must use a cancellation/lifetime token and never outlive executor/manager shutdown. No thread affinity assumptions: a strand can resume on a different worker.

## Removal, shutdown, exceptions

Ordinary removal: mark dispatch generation closing; refuse new turns, cancel timer/continuation scheduling, allow running handler to observe disconnect; queued handlers drop protocol work and release leases/budgets. Finalize exactly once after turn, admission and any async send/preparation owners are gone. `PeerRef` pins only Peer, not `CNode`; preserve node ref lease used by `TxAdmissionSender:1183`. `net.cpp:2181–2195` deletes disconnected nodes only when refs reach zero, but `StopNodes:3898–3907` deletes its nodes directly during shutdown: all async leases must be drained before it. A generation prevents a late completion addressing a different connection even if identifiers/pointers are reused. Never wait for drain on the peer strand or while holding domain locks.

Shutdown should fence all producers (socket notifications, scheduled callbacks, validation/Avalanche callbacks, relay and admission), stop new protocol turns, finish/cancel running admissions and deliver/drop owned completions, drain peer/coordinator handlers and release node leases, join message executor, then permit `CConnman::StopNodes/DeleteNode`, finally destroy PeerManager and dependencies. Coordinate with actual `init.cpp:315–365`: Avalanche loop stop, validation unregister, StopTxAdmission, connman Stop, scheduler stop, peerman reset. Scheduler currently stops **after** connman Stop, so introduce per-network cancellation fences rather than assuming scheduler has already stopped. Keep executor alive until all cancellation completion handlers have run; stopping its event loop early can strand owners/promises and deadlock drain.

Catch expected malformed-wire exceptions at existing message boundaries, preserving accepted decoded prefix then malformed attribution (`ProcessMessages:9963–9981`). Wrap turn exits with RAII that releases scheduled/running state and leases on every exception. Unexpected exceptions must reach node-owned error reporting/stop policy without killing a worker silently or fabricating success/misbehavior; fulfill any promise with exception/cancel once. Do not swallow exceptions and continue mutating partially completed protocol state. No raw `CNode*`, borrowed message span or stack reference may escape its lease/scope.

## Incremental commit gates

1. Add bounded executor/peer lease/coalesced-turn scheduler behind serial compatibility mode; retain `g_msgproc_mutex`. Unit-test wake coalescing, fairness, no lost wake, cancel/drain/exception cleanup and all-interface receive/send ordering. This stage has no concurrency speedup claim.
2. Introduce real guards/ownership for cross-peer fields and atomic admission producer API **while still serial**; eliminate scratch globals through explicit prepared-message data. Run annotation checks and current unit/P2P tests after each ownership group.
3. Route off-strand protocol writers and completion resumes through bounded ingress; add sequence/generation tracking, lifetime/cancellation and shutdown fence tests. Retain global serial dispatch until ownership audit passes.
4. Enable parallel turns for a small explicitly audited subset, keeping remaining operations on a coordinator; then broaden one message family at a time. Runtime strand assertions plus real mutex annotations must cover synchronous access. Avoid peer→peer locking; gather targets before taking protocol guards, and never hold manager registry mutex while taking protocol mutex (honor `m_peer_mutex` rule at `:1525`).
5. Remove global requirement only once all shared/native call sites and tests use the new contract, then full shared/native gates plus TSAN P2P stress. Migrating direct test entry requires a test helper that runs a real peer turn; deleting annotations or suppressing warnings is not validation.

Meaningful adversarial tests: two peers race same TxId and last admission slot; peers send TX/TX/PING and malformed coalesced suffix during delayed admission; queue saturation does not reorder or leak budgets; duplicate-copy replay after another peer admission; two AVARESPONSE batches with different peer keys/polls and concurrent PrepareMessageTurn; simultaneous child/parent relay and epoch/reorg preserve route inheritance; ADDR cross-relay against target's own address handling; compact block reconstruction during reject-ring mutation; block/request callbacks during peer removal; outbound handshake/capability sequencing under queued sends; saturating peer versus idle ping peer fairness; disconnect/reconnect with stale generation callbacks; shutdown at every stage with pending admission, ready turns, deferred serialization, scheduled tick and transport callbacks; injected expected/unexpected handler exceptions retain workers and release leases exactly once.

Run targeted `net_tests`, `txrelay_tests`, `v2_protocol_handler_tests`, denial-of-service, admission/parallel-admission functional cases, block/header/compact-block, address, Avalanche and transport P2P suites. TSAN stress must exercise RPC/validation/scheduler producers concurrently with several peers and repeated shutdowns; pair with assertions on memory bounds and causality. TSAN clean execution alone does not prove queue bounds or deadlock freedom. No tests were run for this report.

## Native extension and scope

Core scheduler/ownership belongs to shared. Native adds `m_full_recon` and atomic wake deadline (`native net_processing.cpp:1769`), native handshake capability, full reconciliation dispatch and reverse-peel notifications. Audit its Manager impl locks/continuations, protocol handler peer-node raw pointers and removal against the same leases/fences. Shared V2 handler already has its own `m_mutex` and cross-peer maps/swarm/scoped transaction state (`shared src/net/v2_protocol_handler.h:810–889`): retain that mutex and audit lock inversion/callback escape rather than relabeling it per-peer. Native transport changes also require their own receive/send completion ordering review. This report identifies those mandatory follow-on surfaces; it does not claim their whole internal lock graph is proven safe.

One bounded node-owned message pool must not accidentally become the script/signing/overlay pool; admission/preparation futures must never wait on work that requires exhausted message workers. Keep Commit 12 separate from the preceding performance algorithms and document any intentionally changed cross-peer interleaving, privacy behavior or admission-result ordering before enabling it.
