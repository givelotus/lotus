## Decision and blocking conditions

Proceed with immutable preparation followed by authoritative locked validation and commit. Do not merely unlock existing `PreChecksBatch`, extend `SpentOutputsMatch` to V7, or trust a snapshot success/failure. The existing snapshot routine is safe precisely because its outputs are signature warming hints only. Full Coin equality plus script flags is necessary for the requested conservative admission binding, but insufficient without transaction/witness identity, chain ID, rule profiles, complete deferred completion, signature completion, and current admission checks.

Shared snapshot currently contains no immutable UTXO snapshot or captured next-script flags (**shared** `src/node/snapshot.h:186–221`). Item 10 therefore needs a general owned-coin capture phase under the existing locks for confirmed shared inputs, or a separately reviewed immutable general UTXO provider. Do not import native SMT dependencies into shared, use live `CoinsTip` outside `cs_main`, or pretend existing shared snapshot fields resolve confirmed coins. A short locked coin-copy phase still moves expensive verification outside locks; claiming entirely lock-free shared coin resolution requires additional architecture.

## Existing contracts to preserve

- `MemPoolAccept::AcceptRawTxBatch`, `src/validation.cpp:2260`: package structural checks first (count, aggregate size, duplicate IDs, order, cross-input conflict), then **all** prechecks in package order, parallel scripts, deferred fee/entry checks, maximum fees, consensus verification, whole-package capacity, and submission. Exact precedence matters when multiple faults exist.
- `PreChecksBatch:1467`: current contextual finality, duplicate/conflict status (including finalized conflict), package→mempool→chain coin resolution, sequence locks, consensus inputs, standardness, fee deltas. It directly reads mutable chain/pool/cache state. It cannot simply run on workers unlocked.
- `FinalizeDeferredPreChecks:1633` constructs entries using current height/time, exact sigcheck count and lock points, then relay/mempool minimum fees. `CanFitRawTxBatch:2620` precedes `SubmitPackage:2641`. `ScopedSnapshotDefer:2383` batches publication; it is not a rollback transaction. No fallible script/state validation may migrate after first insertion.
- `ProcessRawTxBatch:3113` requires `cs_main`, preserves coin uncache and flush behavior. RPC `src/rpc/mempool.cpp:1419` test path and `:1701` send path currently acquire locks themselves. Keep this locked entry point for current P2P/tests; introduce an explicit unlocked wrapper instead of silently changing its lock contract.
- **shared** `AcceptRawTxBatch:1804`, `:1928`, `:2108`, `:2130`, `:2152` has independently required consensus flag verification, capacity reservation and its own atomic insertion/notification path. Preserve this boundary without borrowing native `SubmitPackage` internals indiscriminately.
- `AcceptToMemoryPoolStaged:3402` is ordered **individual** admission, with valid earlier transactions retained if a later transaction fails (`:3511`); it is not atomic package admission. Item 11 must preserve this separate API contract.

## Concrete proposed API and execution plan

1. Add `PrepareRawTxPackage(immutable tx refs, pinned shared_ptr<const Snapshot>, options)` with `LOCKS_EXCLUDED(cs_main, pool.cs)` returning an owned `PreparedRawTxPackage`. It contains package identity/order/topology, per-tx regular results, exact owned resolved coins and source descriptors, preparation context, separate standard/consensus outcomes, sigcheck counts, `deferred_complete`, `produced_records`, and `signatures_complete`. Use a typed `Unavailable/Prepared` status; stale snapshot missing inputs, fees, duplicate hints and `IsSpentFast` may suppress work but never manufacture authoritative rejection.
2. For shared coins, capture missing confirmed coins under a short caller-owned lock phase into owned vectors; release and uncache unowned fetches appropriately. Native can resolve a pinned SMT+entry tree, with explicit coverage/rules/owner validation. Pin **one** generation per package, not one snapshot load per input/transaction. Build immutable synthetic package outputs in request order. Unsupported/missing coverage takes fallback, never a false missing-input error.
3. Use a pure script verifier taking explicit immutable chain/profile context. Current resolved verifier fast path uses `GetActiveV2ChainId` (`:538`) and ordinary checks default to it (`:4593`); thread an explicit captured chain ID through **both** paths before claiming full binding. Do not set global chain selection on a worker. Worker effects and collectors are request-local; publish successful signature-cache entries only after primitive verification. Whole script-cache reads/writes stay authoritative/locked unless independently redesigned.
4. Add unlocked `ProcessRawTxBatchPrepared(chainman, expected_pool, package, options)` which prepares before acquiring locks and resolves current `ActiveChainstate` only under `cs_main`. Under lock order `cs_main`→`pool.cs`, rerun every current stateful precheck for **all** transactions in original order, reconstruct current workspaces/fees/parents and compare preparations. Exact matches skip script execution only. Mismatch means existing locked script path (or bounded retry outside locks), not stale success/error. Preserve all-prechecks-before-scripts-before-final-fees precedence. Finish every required script/deferred/consensus check and capacity check for the entire batch before insertion. Then reserve/submit once with publication defer; preserve notifications, unbroadcast bookkeeping, dry-run and uncache/flush behavior.
5. Item 11 adds an explicitly native `NativeScriptPreparation` field rather than redefining the public advisory warming object. Accept native reuse only for full matching, completed, record-free **success**; failures and incomplete/record-producing runs fall back to ordinary execution for exact error semantics. Keep independent standard and consensus outcomes for mixed/legacy bridge inputs; the pure V7 policy=consensus shortcut is already scoped at `:2581` and must not broaden. Existing `SpentOutputsMatch` and reuse deliberately reject V7 (`:673`, `:699`).
6. Preserve public `PrecomputeMempoolAdmission` advisory contract and its tests. Do not change old assertions `!standard.ran`, `!consensus.ran`, empty spent outputs or zero legacy `stats.precomputed`; add separate native preparation/reuse instrumentation if necessary. `lotus_v2_tests.cpp:751–758,795–800,819–859` already exercise invalid signatures, changed authoritative values, stale generations, missing coverage/rules/leaf and wrong ownership.

## Deadlock and lifetime rules

`AcceptToMemoryPoolStaged:3468–3471` documents an actual lock cycle: a locked batch caller can wait on script dispatcher while that dispatcher's worker waits for `cs_main`. Never invoke locked fallback inside executor tasks. Snapshot miss records unavailable and returns; caller decides fallback after all workers finish. Preserve nonblocking `TryRun`/inline fallback on a busy or nested executor, especially for locked callers, and avoid caller holding dispatcher ownership while trying to acquire global locks. Never acquire pool before `cs_main`. New preparation tasks must not read live pool beyond independently synchronized advisory APIs. Do not hold lazy snapshot-vector/template mutexes while entering live validation or dispatching work that can enter those locks. Snapshot `shared_ptr` pins snapshot memory, not chainman/pool lifetime: node shutdown must stop admission and join tasks before destroying them; raw owner pointers are identity comparisons only. Keep strict thread-safety annotations on locked helpers and explicit lock exclusions on pure workers/wrappers.

## Meaningful required adversarial gates

Use deterministic between-phase hooks and compare complete result type/reason/debug, result ordering, fees/vsize, pool membership/graph, notifications, unbroadcast set and snapshot publication with authoritative control. Test:

- Same TxId/different witness or signature, changed chain ID, flags, transaction/VM/cost/deferred version: no cross-reuse; changed input amount/token/state/branches/paths across any input changes signing/VM context.
- Metadata-only change (creation height, coinbase, fee-per-output, explicit expiration); cross maturity/expiry boundary with identical outputs/flags; equal-height reorg with changed sequence-lock ancestry; changed MTP/finality.
- Mempool parent removed, confirmed, removed/re-admitted with new entry ID; concurrent double spend, finalized conflicting tx; parent reappearance after old snapshot; wrong pool/chainman, null/missing SMT coverage/rules/entry tree. Valid missing-snapshot transaction still reaches authoritative success.
- Ordered parent-child-grandchild/diamond package, bad parent output index, duplicate IDs, mint inputs exempt from spent-outpoint tracking, conflict and non-topological order. Multi-fault precedence: later precheck failure versus earlier invalid script; script failure versus max-fee/capacity failure.
- Record-free OP_TRUE creating unauthorized state output; record-producing state/claim program falls back; individually successful claims jointly overclaim, claim-pair limit, mint positive-delta change, failed mint signature and mixed native/legacy bridge flags. Collected-but-unverified batch must not admit.
- Concurrent fee-delta, rolling fee, hysteresis (where used), max-fee and capacity changes; exact-size capacity with parent-child links; no partial insertion on final-tx failure or insufficient capacity; failed/test package publishes no admitted members.
- Two coordinated concurrent callers: locked authoritative batch using script pool, unlocked preparation with missing snapshot, nested/busy executor and shutdown. Assert bounded completion, no worker takes `cs_main`, and correct fallback. Do not merely rely on a timeout to prove lock ordering.

Run existing PLAN item 10/11 gates plus `rpc_batch_snapshot_tests`, `native_batch_admission_tests`, affected staged/advisory and deferred tests, and shared independent unit gates after implementation. Preserve assertions; new successful reusable path is tested through new API/instrumentation. Benchmarks later need three alternating pairs with independent processing/admission metrics; none were run in this review.

Native warming currently verifies BIP340 primitives individually through `WarmNativeAdmissionSignatures:3239`/signature verifier; batch collector and `VerifyAll` already exist in atomic batch path `:2517`. Their consolidation is a separate performance change, not part of this review's implementation scope.
