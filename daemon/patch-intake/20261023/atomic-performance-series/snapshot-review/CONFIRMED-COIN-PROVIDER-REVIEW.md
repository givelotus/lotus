# Generic immutable confirmed-coin provider prerequisite

Read-only review, 2026-10-23, fixed shared `cbc4e72925652e3c8676ed0b24fce22874be0dc1`. Existing checkout Git objects only; no source edits, new checkout, build/test/benchmark or remote operations. All code references below are at that shared commit. This is a prerequisite design, not implemented/validated functionality. Root owns staging.

## Minimum recommended design

Publish a complete immutable **composition**, not a full UTXO copy: `(fixed MDBX read epoch B, persistent override tree D, chain context C)`. D contains every confirmed coin change between B and C, including explicit spent tombstones. Lookups first consult D, then B. A hit returns an owned full `Coin`; absence of an override means consult B, while a tombstone means absent at C. Pin the composition once per package. All package coin resolution then runs outside `cs_main` and `mempool.cs`; a small provider-private mutex may serialize DB misses in the first implementation. Package/mempool overlay precedes this confirmed view. Final authoritative admission remains mandatory.

This meets Phase 10's immutable-view requirement without permanently copying requested coins under global locks. Per-batch work is O(requested outpoints × lookup depth), not O(UTXO set) or O(dirty cache). Initial bootstrap may scan **dirty cache entries once**, and mutation publication incrementally updates only changed outpoints. Full database iteration is unnecessary. Ordinary provider snapshot acquisition shares roots in O(1).

## Existing code and why simpler alternatives fail

- `src/coins.cpp:97–126,237`: const `GetCoin/AccessCoin` mutate `cacheCoins`, memory accounting and base fetch state. `PeekCoin:129` avoids insertion but reads an ordinary mutable unordered map. Neither is legal outside its existing chain lock. Seqlock retries cannot legalize these C++ data races.
- `AddCoin:135`, `SpendCoin:211`, `EmplaceCoinInternalDANGER:183` and parent `BatchWrite:266` alter live state. Fresh spent entries can disappear (`:225`, `:318`), while nonfresh spends remain cleared tombstones. A mirror derived only from currently unspent cache entries resurrects coins from DB. `Uncache:381` removes only clean entries: cache residency is not logical coin state.
- `Flush:351` clears the cache after base write; `Sync:363` clears dirty flags but retains entries; `Reset:374` changes cache semantics. Mirror state cannot be cleared independently from its backing DB epoch.
- `CCoinsViewDB::GetCoin`, `src/txdb.cpp:104`, uses `CDBWrapper::Read`. `ReadRaw`, `src/dbwrapper.cpp:572–585`, acquires/releases a separate renewed read transaction each call. These reads do not share a stable batch generation. Existing `CDBIterator:795` owns a transaction but borrows its parent and is not a concurrent random-read/lifetime API.
- Critically, `CCoinsViewDB::BatchWrite`, `txdb.cpp:203–275`, performs **several committed MDBX write transactions**: first clears `DB_BEST_BLOCK` and writes `DB_HEAD_BLOCKS` (`:230`), partial batches at `:251`, final marker commit at `:275`. A read transaction opened during the middle can see a mixed transition. Never pair a newly opened DB transaction with an arbitrary old overlay, never assume MDBX atomic transaction means an entire UTXO flush is atomic, and never infer completeness from height alone.
- `ResizeCache`, `txdb.cpp:91–101`, destroys/recreates `CDBWrapper`. Destructor `dbwrapper.cpp:456–489` drains background uses and closes the environment. Snapshot `shared_ptr` and raw owner pointer do not preserve this lifetime. `DBBackgroundHandle`, `dbwrapper.h:66–118`, explicitly does **not** keep DB alive; it fences short `Use` calls only. An idle long-lived transaction must be registered for invalidation/abort before close.
- DB value decoding includes XOR obfuscation (`dbwrapper.h:351–367`), and coins use `CoinEntry` key encoding (`txdb.cpp:72–84`). Provider must use the same serialization/deobfuscation helpers. I/O/corruption errors are not “coin absent”. Preserve ordinary fatal/catcher behavior or return distinct provider `Unavailable/Error` for authoritative fallback; never accept based on a fabricated absence.

## MDBX transaction and thread contract

The bundled primary API documentation is sufficient to settle thread use, without relying on version-mismatched web pages: `src/lotus_v2/vendor/libmdbx/mdbx.h:1151–1220` documents `MDBX_NOSTICKYTHREADS`. In particular `:1182–1202` explicitly forbids concurrent use of the same API transaction/cursor objects across threads and explains that cursor bind/unbind/close and transaction end also use the transaction. Translated meaning: removing thread association does not remove the requirement to serialize access. Environment is opened with this flag at `dbwrapper.cpp:388–390`.

Use one epoch transaction with a **private mutex covering every access, cursor operation and destruction**; it may move between OS threads sequentially. Copy returned bytes/deserialize into owned `Coin`s before releasing the guard. Do not let `MDBX_val` pointers or cursors escape. This mutex is not `cs_main` or `mempool.cs`, and readers must never call back into either while holding it. Start read txn at coherent boundary; never reset/renew it while serving the same published epoch. `mdbx_txn_id` docs at `mdbx.h:4065` identify its snapshot; `mdbx_txn_reset:4275–4293` releases it and warns that pinned readers prevent page reuse and can grow the DB.

Safe later concurrency alternative: capture a **bounded bank of independent read transactions at one stable boundary while coin DB writes are fenced**, verify each transaction ID matches, then exclusively lease one transaction per lookup batch. All bank transactions share B; separate cursors on the same transaction do **not** allow concurrent access. Do not open a “same snapshot” transaction lazily after writers resume: txn ID is an observation, not an API for reopening an old arbitrary ID. If equal generation cannot be obtained, decline that bank. The serialized single-transaction design is the minimum; a bank is a separately measurable optimization.

## Small API plan

1. Generic DB layer: `CDBReadEpoch` with `epoch_id/environment_incarnation`, fixed `txn_id`, private transaction mutex, immutable DB decoding context, bounded `ReadManyRaw(keys)` and `Close()`/cancellation. `CDBWrapper::CaptureReadEpoch()` registers it with a lifecycle registry. `Close` fences new reads, waits for active private read to finish, aborts txn while env still open, then marks unavailable. Wrapper destruction/cache resize invalidates **all** registered epochs before environment close. No borrowed wrapper reference is dereferenced after fencing. Do not merely extend background-use duration indefinitely, which would make resize wait for arbitrary clients.
2. Coins layer: `ConfirmedCoinOverride { exact OutPointKey key; optional<Coin> coin; }`, immutable leaf; `ConfirmedCoinSnapshot { environment/chainstate incarnation, epoch ref, immutable override root, tip hash, chain generation, complete; }`. `LookupMany` returns per-key `Present(Coin)/Absent` only for a complete live snapshot; overall `Unavailable/Error` on invalid epoch/coverage/decoding. No negative cache assumption or latest DB reads. Bind native full metadata naturally via the tier's `Coin` type without native SMT dependencies in shared.
3. Writer: `ConfirmedCoinSnapshotBuilder`, attached only to each authoritative chainstate `CoinsTip` and its persistent base epoch, `EXCLUSIVE_LOCKS_REQUIRED(cs_main)`. Feed successful logical mutations incrementally and publish a complete composition only after the matching chain transition succeeds. Add explicit `Publish/RotateBase/Invalidate` operations. Node snapshot gets `shared_ptr<const ConfirmedCoinSnapshot>` captured atomically with its chain/pool context; no mixing roots from independent publisher loads. Capture next-script flags with that same context as item 10 also needs them.
4. Reader API annotated `LOCKS_EXCLUDED(cs_main,pool.cs)`; acquire bounded request lease, resolve package→pinned mempool→confirmed composition, then release DB lease once owned coins are resolved. Scripts consume copied values only. A provider miss/unavailable on stale/closed view requests bounded retry or authoritative fallback, not RPC rejection. Phase 10 is complete only when the generic provider actually handles confirmed resolution outside locks; provider failure fallback does not substitute for implementation.

## Reusing existing CoW and allocation facilities

`src/radix.h:79–98` provides `ImmutableSnapshotTag` for root sharing only when source is immutable or held under exclusive writer protection. Later mutation takes CoW paths (`:186–211`). Use immutable leaves with RCU refcounts as demonstrated by `ImmutableMempoolEntry`, `src/node/snapshot.h:108–133`. Never mutate a shared leaf's Coin in place. Outpoint key must include full TxId **and** output index: a small exact 288-bit radix-key adapter, with static size/asserted shifting and equality, avoids hashed-key collision risks. Existing `Uint256RadixKey` alone cannot represent outpoints. Alternative txid-keyed immutable sparse output-index leaf works but copies a whole changed txid leaf; document that cost if selected.

Use `GlobalConcurrentSlabAllocator` (`src/support/allocators/chunked_slab.h:445–537`, existing SnapshotAllocator at `snapshot.h:106`) for nodes freed by reader/RCU threads. Plain `SlabArena/ChunkedSlabResource` (`chunked_slab.h:29,234`) mutate freelists without internal synchronization and are unsuitable as a shared reader/writer allocator. RCU reads must follow actual API: `radix.h:146–148` warns read sections are not nestable; use nonnested `get` or explicit `getWithinReadSection` when joining immutable structures. Do not hold an RCU section across slow DB I/O or invoke writer grace-period waits under locks required by a reader.

## Generation, flush, reorg and lifetime protocol

**Bootstrap:** under the writer boundary, capture a DB read epoch with consistent markers (`DB_HEAD_BLOCKS` empty and `DB_BEST_BLOCK` matching the chosen durable base; allow explicitly defined initial empty DB). Build D once from all current dirty authoritative cache mutations, including spent entries. If building after arbitrary cache state, prove every override relative to B is represented; merely scanning unspent or `HaveCoinInCache` entries is insufficient. Never expose an incomplete composition as `complete=true`.

**Normal connect/disconnect:** successful child cache merges into CoinsTip happen at `validation.cpp:4618` (disconnect) and `:4841` (connect). Incrementally replace override leaves during adopted parent-cache merges, including erased/fresh entries if logically needed; publish with final adopted tip/height/MTP only after success. Failed candidate child views contribute nothing. Hook direct authoritative Add/Spend/Emplace and import/snapshot/replay paths too; no publish between coin update and tip update. Confirmed view remains historical and immutable across later same-height reorgs; new generation/tip token invalidates prepared admission. Clean read-cache inserts/uncaches need no mirror update.

**Flush/Sync:** retain old B and old D across all partial write commits. They remain a coherent preflush view because B is an active fixed read txn. After **final successful** DB commit, capture B2 with markers/ID verified while DB coin writers remain fenced, and publish `(B2,empty D,new context)` when all previous dirty changes have reached B2. If writes after the selected flush boundary remain in memory, D2 must contain exactly those remaining changes; never clear them. `CoinsTip().Flush/Sync` is invoked at `validation.cpp:4427`. Sync leaves clean cache entries; those must not be mistaken for unflushed overrides. Failure or crash retains old published composition until shutdown; restart does not publish until existing DB replay/marker recovery completes. Publishing from `CCoinsViewDB::BatchWrite` alone is too early unless parent cache/tip context is also finalized.

**Reset/import/switch:** `Reset`, cache replacement, reindex, fast-sync install (`txdb.cpp:180–200`), active/background chainstate switch and resize invalidate or rebuild with a new incarnation. Old snapshots can never resolve against the replacement environment. A raw chainman/pool identity is insufficient if underlying chainstate/DB changed. Current incomplete recovery markers mean provider unavailable.

**Bounds:** do not keep one reader txn per RPC or generation forever. Reuse one base epoch across normal overlay publications, retire old epoch after flush, cap outstanding admitted request leases/generations, and bound lease age/retained override memory and reader lag. Cancel stale leases cooperatively; `Close` synchronizes with in-progress reads before abort/reset, unresolved lookups become unavailable, already copied coins remain advisory. Do not block chain progress waiting for a reader needing `cs_main`; epoch Close/read code never takes it. Bound registry and snapshot handles so callers cannot retain arbitrary roots forever. Expose pinned generations/txn age/reader lag/retained bytes; impose admission backpressure rather than unbounded disk growth. Safe reclamation is a correctness gate, not a benchmark-only concern.

## Independent commits and tests

A. DB fixed-read epoch/lifecycle API only, no validation lock changes. Prove repeated reads stable across writes, sequential cross-thread use, concurrent calls serialized, close/resize/destruction races, obfuscation and malformed value distinction. Verify no reset/renew while epoch pinned and bound reader slots.

B. Exact outpoint immutable override structure and Coin snapshot composition, no lock-scope changes. Property test key/index collisions, tombstone versus absent override, CoW stability/reclamation, allocator cross-thread free, cancellation and ownership. Include same TxId many outputs and all byte/index boundary keys.

C. Writer mirroring and atomic snapshot publication, old admission remains locked. Compare every published view with authoritative CoinsTip using randomized add/spend/re-add/overwrite/connect/disconnect/failed-child operations; compare sampled disk/cache combinations over flush/sync/uncache/reset. Inject observation after **each** partial DB batch: old pinned snapshots must still give old complete view; new capture must never expose partial state. Assert final base rotation + empty overlay equals current state. Include DB failure, recovered DB_HEAD_BLOCKS, active chain switch, fast-sync import and same-height reorg. Instrument updates to show O(changes), root-share capture O(1), no per-request full-cache/DB scan.

D. Phase 10 lock-scope commit consumes provider, performs preparation outside locks and authoritative atomic commit under them. Test confirmed disk-only input preparation while another thread owns cs_main; pool-only/package parents; stale generation and removed coin; expiry/maturity and MTP/flags change; full package exact errors/no partial mutation; no worker fallback taking global locks. Preserve earlier review gates. Add concurrent resolve+flush/reorg+resize/shutdown stress under TSAN and memory/DB-growth bounds. No tests or performance claims were made in this review.

This prerequisite is generic shared engine work. Native may adapt full Coin metadata and continue using its SMT provider, but must not replace the general provider with native consensus structures. Serialized DB misses may limit throughput; measure only after correctness gates, then consider a bounded same-generation reader bank as a distinct optimization.
