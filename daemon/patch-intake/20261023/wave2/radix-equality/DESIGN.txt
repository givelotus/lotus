Uint256RadixKey currently supplies implicit size_t conversion but no equality operator; radix leaf identity checks therefore truncate to low64. Add explicit key-key ==/!= delegating to arith_uint256 full-width comparison. Keep conversion, shifting, masking, memory layout and radix architecture unchanged.
Tests cover all bits64..255 with zero/nonzero shared low64, symmetric ==/!=, insertion of distinct high-word keys, duplicate-key insertion, absent keys sharing low64/path, exact element pointers, removal isolation, and retained immutable-snapshot contents while writer removes/reinserts. Both public equality operators are checked directly.
No locking/lifetime implementation changes or native consensus dependencies. No performance claim. No source commit before required gates.
Existing integer-oriented radix fixtures can mask this bug: inserting keys with different low values first constructs enough radix branches that later high-bit variants reach separate empty slots. The new fixture begins with a single leaf and introduces a high-only variant before any low-bit branch can hide the truncated equality. The standalone negative control checks that exact trigger and must return failure with the original header.
