    chain: give Lotus V2 its own data directory, ports and network identity
    
    Lotus V2 inherited Bitcoin ABC's network identity: the ~/.bitcoin data
    directory and bitcoin.conf, eCash's mainnet/testnet network and disk magic,
    default ports 8333/8332, eCash DNS seeders and fixed seeds, and eCash
    checkpoints, minimum chain work, assume-valid blocks and assumeutxo
    snapshots. Every network also hashed blocks under the all-zero V2 chain id,
    because nothing outside the tests set it. A V2 node on mainnet settings would
    look for eCash peers, and on a machine running Bitcoin ABC it would share
    ABC's data directory.
    
    - Data directory ~/.lotusd (Windows %APPDATA%\Lotusd, macOS
      ~/Library/Application Support/Lotusd), config lotusd.conf, pid lotusd.pid.
    - Lotus V1 default ports: P2P 10605/11605/12605, RPC 10604/11604/12604 for
      mainnet/testnet/regtest. Chronik ports are unchanged, as in V1.
    - New network and disk magic for all three networks.
    - Mainnet and testnet chain ids are SHA256("Lotus V2 mainnet") and
      SHA256("Lotus V2 testnet"); they are stored in CChainParams and selected
      with the chain. Regtest keeps the all-zero id its fixtures use. Genesis
      construction scopes the id so building another network's parameters does
      not change the selected one.
    - No DNS seeders, fixed seeds, checkpoints, assumeutxo snapshots, chain
      statistics, minimum chain work or assume-valid block for mainnet and
      testnet, through a new src/networks/lotus directory selected by
      NETWORK_DIR. The regtest checkpoint is the V2 regtest genesis hash.
    - Functional test framework and tests use the new magic, conf name and
      default data directory.
    
    Address encoding (still cashaddr "ecash:") and the mainnet/testnet genesis
    blocks are unchanged here.
