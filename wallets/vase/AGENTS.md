## Exact amount entry (2026-10-14)

- Financial amount conversion and formatting in `vase-client/lib/utils/currency.dart` must use decimal strings and `BigInt` base units, never `double`, `/`, or `BigInt.toInt()`. One XPI has six base-unit decimals. Do not parse localized presentation strings back into payments; `satsToLotus` is canonical ASCII editing/transport text.
- Preserve valid editing states (`0`, trailing decimal point, trailing fractional zeros). Numpad validation is centralized in `NumpadModel`; button handlers must use that result rather than independent length/decimal rules. All six decimals are enterable. The 19-integer-digit limit is an editing-length bound, not a consensus monetary maximum.
- Empty input clears to zero. Malformed, negative, exponent, grouped, and ambiguous decimal-comma input is rejected before mutating the model. Nonzero sub-unit fractions are rejected; excess zero precision may be normalized without changing the amount. Display rounding is nearest with ties away from zero, and must not mutate base units. Do not permit zero-amount Done/Send confirmation.
- Current code has a decimal amount keypad and no arithmetic-expression or fiat conversion engine. Preserve the restored scanner UI and current models rather than reviving historical calculator code as part of a numeric bug fix.
- Before correction, 10 of 11 initial regressions failed: base-unit loss (`1.000001` -> 1000000, `0.000249` -> 248), exact display/editing at large integers, empty/invalid states, locale state, precision limits, and decimal rounding. Corrected validation passes 59 Flutter tests (15 new amount/keypad regressions), plus 12 amount/model tests in headless Chrome. Full analyzer retains inherited notices; changed-source analysis and the web build are checked separately. No real wallet, storage, camera, transaction broadcast, or native platform operation is used for these regressions.

## Dependency upgrades and storage migration (2026-10-14)

- Resolve dependencies on the installed Flutter 3.47.4/Dart 3.13.3. The canonical SDK raises its minimum Dart to 3.11; the app requires 3.12 for current router/telemetry packages. Preserve the SDK path dependency. All runtime constraints were raised to current stable versions except the secure-storage migration bridge. `dependency-audit-20261014.json` records the complete before/after inventories, including transitive constraints.
- Pin `flutter_secure_storage` **10.3.4 exactly** until native upgrade tests prove existing v6 wallets have migrated. v11 removes legacy Android RSA-PKCS1/AES-CBC support; a direct upgrade can strand keys. All wallet storage must use `walletSecureStorage`: resetOnError=false, migrateOnAlgorithmChange=true, migrateWithBackup=true, original Apple service/accessibility/synchronization, Windows useBackwardCompatibility=true. Never change app identity, signing, key names, Android preferences namespace or Apple keychain groups as part of this upgrade.
- Failed secure-storage reads are not empty storage: initialization stops with an unavailable state without generating or persisting replacement keys. Successful reads with missing seed but other wallet markers also stop. Tests use in-memory storage; they do not prove native cipher/keychain/DPAPI migration. Migration changes stored formats; downgrading the dependency is not a storage rollback.
- Before distributing a native upgrade, test an upgrade without uninstalling a signed v6 fixture app containing a dummy known mnemonic/password, check identical derived addresses and password, restart/reboot, interrupted migration and locked/unavailable key stores. Exercise Android legacy cipher data, Apple original keychain service/accessibility, and Windows Credential Manager migration separately. Keep backups/recovery available; do not substitute fresh keys on failure.
