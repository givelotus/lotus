# Reconciliation core: normative specification

This section specifies a new reconciliation core. Historical miniblock designs and measurements elsewhere do not establish its implementation, performance or safety. This section controls the core where historical descriptions conflict.

## §1 ARCHITECTURE

The core is a sans-IO deterministic state machine. No sockets, threads, wall clock, globals, or hidden randomness. Time and an RNG seed are passed in; all output is returned as Actions. The host serializes all calls (single owner); the core never calls host services. RootFunction is the explicit exception: a pure deterministic calculation supplied by Configuration, with no IO, mutation, hidden randomness or access to peer ground truth.

```cpp
class SnowstormNode
{
public:
    explicit SnowstormNode(Configuration configuration); // maximumAdversaryFraction, epsilon, maximumSetSize, RootFunction, randomSeed
    Actions OnTransactionAdmitted(TransactionHandle, Time);
    Actions OnTransactionRemoved(ShortID, RemovalReason, Time);
    Actions OnTransactionBodyRemoved(ShortID, TransactionHash, RemovalReason, Time);
    Actions OnTransactionBodiesResult(PeerID, ShortID, BodyResult, Time);
    Actions OnMessage(PeerID, ByteSpan, Time);
    Actions OnTimer(Time);
    Actions OnPeerConnected(PeerID, PeerCapabilities, Time);
    Actions OnPeerDisconnected(PeerID, Time);
    Actions OnNewTip(TipParameters, Time);
    Actions OnBlockDisconnected(TipParameters, Time);
    NodeStatistics GetStatistics() const;
};
```

Action alternatives: Send{peer,bytes}, FetchBody{peer,shortID,fetchID}, Frozen{root,transactionIDs}, PeerMisbehaved{peer,reason}, ScheduleTimer{at}.


RemovalReason is expiry, trim, conflict, reorg, batchLoser, variant, replaced or other. TransactionHandle is an immutable opaque shared handle exposing 32-byte transactionID, 32-byte transactionHash and shortID. The core computes current shortID from transactionHash and TipParameters; a cached handle shortID is not authoritative after rekey. TipParameters contains a 32-byte tip context, SipHash k0/k1 and surviving handles. PeerID is a nonzero host-assigned connection identity never reused within a node lifetime; a reconnect has a fresh PeerID. PeerCapabilities contains protocolVersion and positive host-measured RTT. Only version 2 compatible peers enter D and protocol handling; incompatible peers generate no protocol traffic and are not penalized for incompatibility.

Time is signed int64 monotonic microseconds, with 0 <= Time <= INT64_MAX. Calls must be nondecreasing in Time. Backwards times and local arithmetic overflow return no Actions, set NodeStatistics.lastAPIError, and leave protocol state unchanged. Configuration requires finite 0<=maximumAdversaryFraction<1/3, finite 0<epsilon<1, 1<=maximumSetSize<=floor((2^21−256)/8) and a nonempty RootFunction. Invalid Configuration throws std::invalid_argument before allocating protocol state. Remote input never throws out of an API call or reaches an assertion. The host must keep admitted distinct-ID count and total admitted body count each <=maximumSetSize. An over-capacity admission is an explicit local API error, not a false successful admission. Other public operations return typed errors rather than wrapping integers or silently changing operands.

Host contract: every FetchBody token receives exactly one result, even after cancel/reset/disconnect (host owns timeouts). BodyResult contains fetchID, optional expectedTransactionHash, one of admitted, notFound, invalid or localRejected, and binding status matched or unbound. The host first parses body bytes and verifies their transactionHash maps to the requested short ID with the request's tip key. Unparseable/wrong-ID bytes are unbound peer-local failures; they cannot justify global invalid-ID rejection. Only a matching-ID body that fails actual transaction validation is invalid/matched. admitted requires matched binding, the exact32-byte expectedTransactionHash whose current short ID equals the requested ID, and successful actual admission. localRejected requires matched binding and expectedTransactionHash: a valid bound body was not admitted solely because of local policy/resource/temporary-context constraints, and no global invalidity is established. The host must not map policy refusal to admitted, notFound or invalid. On a live token, validate the status and binding enum domains before interpreting status-specific fields. notFound ignores binding/hash fields only after both enum values are valid. invalid/matched requires the matched32-byte hash; invalid/unbound ignores any supplied hash and is donor failure. admitted/unbound, localRejected/unbound, missing/wrong-binding required hashes or illegal enum values on a live token are local HostContractError with no state mutation or peer penalty. Stale/unknown/completed tokens are ignored before interpreting their payload. The host sends an admitted result before the matching OnTransactionAdmitted; that callback must eventually follow unless a tip transition cancels its generation. It never admits merely because an ID decoded. Tokens increase monotonically across tip/connection generations and never reuse; exhaustion is a nonfatal local error. Existing admitted matching IDs make late failures obsolete, not grounds for removing an admitted body. The core never inserts transactions into the host.

RootFunction receives all candidate bodies in canonical (transactionID bytes,transactionHash bytes) lexicographic order; the identity of the tip is an explicit additional RootFunction input. It returns 32 bytes and must be collision-resistant for honest equality inference. Frozen contains sorted unique transactionIDs represented by those candidate bodies. Root equality is a peer assertion, not authentication of a Byzantine peer's bodies. Out of scope: SnapBlock/Stage1.5, conflict resolution/BatchId, stake weighting and consensus changes.

## §2 FIELD GF(2^64)

P(x)=x^64+x^4+x^3+x+1 (reduction constant 0x1B). Multiply: hardware carry-less multiply (PMULL/PCLMULQDQ) selected by runtime CPU detection using function target attributes; portable fallback using 4-bit windowed tables. Squaring: byte tables. Inverse: Itoh–Tsujii. Batch inverse: Montgomery's trick. Invert(0) returns a typed ZeroInverse error. Batch inverse rejects a batch containing zero atomically with the same error; an empty batch succeeds with empty output. Solve(D) for u^2+u=D returns false iff Tr(D)=1; otherwise use the even-degree method with theta=x^61 (Tr(theta)=1), byte-wise tables, and verify y^2+y==D before returning. Solve(0) returns true,y=0. Half-trace is incorrect in even-degree fields and forbidden. Runtime backend selection and portable/hardware agreement are observable without exposing mutable dispatch state.

## §3 SHORT IDS AND BODIES

shortID is the 64-bit SipHash-2-4(k0,k1,transactionHash) result; zero maps to one. The transactionHash argument is exactly its canonical 32-byte sequence, not TransactionID||TransactionHash. Different witness transactionHash values generally have different IDs but can collide. R is keyed by distinct shortID; each ID owns its admitted body bucket. A second distinct body under an ID changes its body view and changes the root only if that ID is in W; it does not change the ID sketch or admission sequence. Duplicate admission of the same transactionHash is a no-op.

OnTransactionBodyRemoved(id,hash) removes precisely that body, updates the body view immediately, changes the root only for a candidate-body change, and removes the ID and its sketch contribution only when its last body leaves. Unknown body removal is a no-op. OnTransactionRemoved(id) is the explicit whole-bucket operation; every body under that ID leaves. Host normal removal callbacks use the body-specific method. Every RemovalReason has these same core set semantics.

Sketch reconciliation establishes distinct-ID equality in tested trials, not complete collision-body agreement. A colliding body can be hidden by the ID sketch, and globally rejecting an authenticated invalid matching-ID body can conservatively suppress a valid colliding body for the height. These are explicit limitations; ordinary host validation and block fallback remain mandatory. No claim of collision-complete transaction dissemination is made.

## §4 CODING

### §4.1 Cells and decode

Cell={int32 count;u64 s1,s3,s5}, serialized in 28 bytes little-endian. count never wraps and −2^31 is forbidden: exceeding ±(2^31−1) returns local Overflow or remote PeerMisbehaved(countOverflow). Adding nonzero x with sign sigma in {−1,+1}: count+=sigma;s1^=x;s3^=x^3;s5^=x^5. A residual is received cell minus requester reference encoding at the same index.

Decode(residual,idx,inReference) returns Zero, One{x,sigma}, Two{x1,sigma1,x2,sigma2}, or Undecodable:

- Zero iff count=0 and all syndromes zero.
- One requires |count|=1,s1!=0,s3=s1^3,s5=s1^5,ScheduleIncludes(s1,idx), and count=+1 iff s1 absent from reference (−1 iff present).
- Two requires count in {−2,0,+2},s1!=0. D=1 xor s3*s1^−3; Solve(D) succeeds; x1=s1*u;x2=x1 xor s1. Require distinct nonzero roots, s5=x1^5 xor x2^5 and schedule inclusion for both. Each sigma is −1 if root in reference, +1 otherwise; require sigma1+sigma2=count. Return roots in increasing unsigned order.
- Otherwise Undecodable. Checks do not authenticate a chosen malicious set; finite syndromes are not an injective commitment for arbitrary large sets.

### §4.2 Integer Rateless IBLT schedule

Credit: Yang et al., SIGCOMM2024. Item x has i0=0. SplitMix64 state starts x. Each step adds 0x9e3779b97f4a7c15 modulo2^64; z=(z xor(z>>30))*0xbf58476d1ce4e5b9; z=(z xor(z>>27))*0x94d049bb133111eb; output=z xor(z>>31), all operations u64 modulo arithmetic. Draw u as low32 bits of exactly one output; s=2^32−u.

Given included i, next j is the least integer j>i with `s*(j+1)*(j+2) >= 2^32*(i+1)*(i+2)`. Compute with u128 integer square root of the quadratic discriminant and exact integer adjustment. No floating point. Stop/exhaust if j>maximumSymbolIndex; never wrap. The corresponding continuous inverse-CDF has survival (i+1)(i+2)/((j+1)(j+2)), hence marginal inclusion2/(j+2). uint32 quantization is the exact implemented law. T3 retains target1/(1+i/2), million samples and4σ tolerance. This discrete law explicitly corrects the former inverse-square formula's .6400000001303852 index1 probability, which was inconsistent with2/3.

### §4.3 Sketch

Encode(set,[a,b)) returns cells. Incremental cache updates every advertised A membership gain/loss at every cached scheduled index. Use 64-byte-aligned SoA cell storage and precomputed (x,x^3,x^5) per ID. Body-only bucket changes do not modify sketches. Range bounds and overflow are checked before mutation.

### §4.4 Peeler

Use a worklist; each pass snapshots its dirty set; changes requeue cells; attempt singletons before pairs, batch-invert s1^3 for pair candidates and recheck staleness before solving. Run until empty, without an iteration cap. Each successful item removal changes reference membership and subtracts that item from every stored scheduled residual exactly once. A Two event is atomic and removes two distinct items. The node does not subtract them again.

Keep a per-pass claim ledger of item/sign. A repeated item claim in the same fixed reply/reference pass is inconsistentSymbols and terminates processing of that reply, not an endlessly toggling +x/−x cycle. At the node boundary this peel-derived failure is discarded without PeerMisbehaved (§6.6), since shared Pending may contain another peer's fabricated ID. The reference is fixed at reply-processing entry. Host changes cannot interleave the serialized call. Fetch/Pending effects are applied after peeling; they do not mutate the input reference or cause a second subtraction. Each attempt uses an immutable-input invariant residual and a private working copy; retained replies do not keep raw cells. The harness independently retains the received wire bytes. Claimed items beyond the validated maximum possible signed difference are a peel-derived inconsistency, discarded without a peer penalty; storage exhaustion is separately ResourceLimit, never an iteration cap. No hostile input triggers debug assertions. Recoverably validate hostile inconsistency and capacity before any internal debug invariant assertion. Each successful decode audit records its entire original source cell, index, both original membership bits and grouped One/Two outputs before any residual update. Independently rechecking a Two uses that original pair cell, not two fictitious singleton checks.

Peeler append validates the entire input batch before mutation. A prohibited INT32_MIN count or reconstruction overflow returns Error::overflow; an out-of-range index returns Error::invalidRange; conflicting duplicate indices, within the batch or against stored raw cells, return Error::inconsistentSymbols; insufficient capacity returns Error::capacity. Each such error leaves all peeler state unchanged. Identical duplicate raw cells are no-ops.

## §5 SET STORE

R continues to own all host-admitted body buckets and their bounded item lifetimes. Define advertised raw A={id in admittedIDs whose state is not FINAL-out}. Encode A in every own POLL/REPLY and setSize=|A|; exclusions are A minus candidate IDs. FINAL-out IDs occur in neither cells nor exclusions. The decode reference is Ref=(A union Pending) minus FINAL-out IDs. Inbound POLLs decode against A alone. A is a derived membership filter over existing state, with no second body store. A gain/loss, including a FINAL-out transition, updates caches and retained invariant residuals exactly once by net reference membership. Message formulas below use advertised A wherever they name sent/peer raw IDs; host admission/removal capacity still counts all R bodies/IDs, including terminal ones.

R is the host-admitted, not-removed body set of this height, keyed by distinct shortID, each with its admission sequence. Conflicts are not resolved here. Retain the conservative rejected-ID exception: a host admission under an ID rejected this height returns RejectedId without insertion, even for a valid colliding body. This is not an exact host-pool mirror and never bypasses normal validation. Body buckets, duplicate admission, body-specific removal and sequence behavior remain as specified in §3.

The sketch cache encodes current A at [0,cachedSymbolCount), extending on demand up to maximumSymbolsPerReply. Sparse probe indices use the same §4 schedule/encoding without allocating a dense array through the largest probe index. No snapshots, pins or change log are retained. OnNewTip/OnBlockDisconnected recompute IDs from surviving handles and the new key, clear Pending, confidence, W membership and per-height body-outcome marks, cancel old fetch generations and active rounds, preserve compatible connections and monotonic token generators. All surviving admitted IDs form W and start with preference in, both cumulative success counters zero, evidence S=0 and no FINAL status; no prior Pending or item state is inherited across tip reset. Sizing history follows the explicitly bounded rollover in §6.3. Old asynchronous results cannot mutate the new generation.

### §6.3 Adaptive sizing and frozen RequiredSymbols(d)

A timely REPLY_DIFF supplies uncensored start and now samples defined in §6.1. A fallback REPLY means either inbound decode did not succeed or a complete DIFF exceeded the message limit; apply the existing approximate estimator and growth rule to its cells. Every timely processed REPLY with cells records which residual cells are zero BEFORE peeling. Exclude index0 from the likelihood because p0=1; a zero symbol0 is used in the explicit zero-estimate branch below. For i>=1 use inclusionProbability=2/(i+2) and the model P(empty at i)=(1−inclusionProbability)^Delta. This is an independence approximation: schedule cells are correlated and mixed-sign cancellation is treated as negligible. Call the result the approximate maximum-likelihood estimate, not an exact MLE.

Let L=max(number of distinct items decoded from this reply,abs(raw symbol0 count minus reference symbol0 count)). Maximize over integer Delta>=L:

`emptyCellSum Delta*ln(1−inclusionProbability) + nonemptyCellSum ln(1−(1−inclusionProbability)^Delta)`.

The stated objective is unimodal; search integer Delta in[L,2*M+P] with smaller-Delta tie breaking and stable log evaluation. If the maximizer would lie above the domain, record a censored result at L; never perform unbounded search. If all received nonzero-index cells are pre-peel empty and symbol0 residual is zero, estimatedDifference=0. If no nonzero-index cell is pre-peel empty, record a censored estimate with lower bound L. ## §8 EVIDENCE-WEIGHTED ITEM ROUNDS AND ROOT SETTLEMENT

D is the compatible connected peer population captured at round start. At small D, sample all D peers. Votes express the responder's candidate preference. MATCH gives yes for captured W and no for other captured eligible IDs. At arrival, decoded-present and nonexcluded gives yes; decoded-absent or excluded gives no. An incomplete arrival gives no other sharing inference: remaining captured items abstain. A node never casts a yes for its own Pending item: Pending is absent from its W, root, proof, advertised cells, setSize and exclusions. Such received votes score the poller's captured Pending lifetime and permit the expressly required FINAL-in Pending state. MATCH votes remain as before.

For item x, voteCount=yesVoteCount+noVoteCount is the number of sampled peers casting valid votes on x. Set answerFloor=floor(K/2)+1. A round counts for x only if voteCount>=answerFloor; below this floor add0, count no success and change no item evidence/counters. The success denominator is voteCount, with the additional majority-of-K answer floor. This includes voteCount=0 as no success. For voteCount>0, at most one side can succeed. For a success, let m=ceil(D/2), let X have the hypergeometric law with population D, m peers on side s and voteCount draws without replacement, and H=P[X>=sideVoteCount]. ## §9 SIMULATOR AND EVALUATION

Rationale: Snowstorm is push-pull gossip. A random-subset POLL carries the poller's cells, letting the responder discover missing items immediately. If decoded, the responder returns the signed difference as plain IDs in REPLY_DIFF; otherwise it returns cells in fallback REPLY. In a successfully decoded nonmatching exchange, cells move into the POLL rather than being added to a cell-bearing reply; fallback exchanges can carry cells in both directions. One exchange therefore disseminates in both directions rather than requiring a later reverse poll. Under uniform regular connectivity each node sends K polls and receives about K polls per round in expectation, so polling itself is push-pull. The intended latency benefit is saving the wait for a reverse poll, described as half a round; actual timing and decode success are measured, not guaranteed. [Karp, Schindelhauer, Shenker and Vöcking, Randomized Rumor Spreading, FOCS2000](https://archive.cone.informatik.uni-freiburg.de/pubs/rumor.pdf) motivates combining directions, not a complete Snowstorm protocol proof.

Cost: POLL cells are sent before the poller knows whether roots match. When sets agree those cell bytes are wasted even though the response can be REPLY_MATCH. Its proof is16 bytes; with the unchanged proposed version/kind,tip context and pollID framing the full application payload is58 bytes, not16 under this grammar. Adaptive sizing shrinks requests as estimated differences shrink, subject to the request floor. Report poll-cell bytes on all exchanges and on matched exchanges separately in NodeStatistics and evaluation, plus REPLY_DIFF ID bytes  and fallback reply-cell bytes.


Body-latency rationale: a decoded ID is not a transaction. Body delivery and host validation precede admission into R; candidate entry is separately gated. Rounds continue during body transfers and collect eligible item observations. A late admission initializes a fresh state or preserves its complete live Pending state. Time to freeze depends on reconciliation/body latency and on the item round counts and gate, not on a separate stable-root likelihood barrier. A freeze can precede a delayed body admission only if no live FINAL-in Pending item blocks it. A later item that passes the gate changes the root and invalidates that freeze. Rounds do not wait for fetch completion; the explicit FINAL-in Pending freeze guard applies without an additional hidden timeout.

Per-node unique transactions are fetchable from their holding nodes. Host validation delay is1 ms and is printed in every run configuration. Evaluation body service completes after one donor-link round trip plus bodyBytes/linkBandwidth serialization plus a host validation delay recorded in the run configuration. Admit at completion time, including mid-round, never batch admissions at round end. Report time to last admission and time from last admission to freeze, alongside total freeze time; separate unsuccessful fetch outcomes and nonfreezing trials. Ground-truth classification of the last admission must state its horizon and does not leak into the core.

The operational role of K and host fanout f is to trade dissemination rounds against bytes. The author-selected confidence rule accumulates hypergeometric-tail evidence over successful rounds and requires at least three same-side successes before FINAL. Repetition alone does not prove that correlated neighbourhoods wash out: persistent partitions, response selection and adaptive equivocation remain evaluation/proof obligations, under the stated identity and sampling assumptions. No inherited Snowball security theorem or K-independent safety guarantee is claimed for this modified protocol.

Push is outside this specification. A separately tracked lotusd relay change announces each transaction to a uniformly random subset of f peers rather than all peers. This document adds no announcement message, relay algorithm or host-admission requirement to the core. In evaluation, model that existing host relay at fanout f (f=0 means no announcements); resulting validated transactions enter the unchanged core through ordinary OnTransactionAdmitted.

## §11 LIMITATIONS AND HOST REQUIREMENTS

Sybil resistance is not provided by this core. Stake-backed identity is required for a hard beta bound. Network-group diversity (/16,/32 or ASN as defined by the host) and outbound preference are host connection-management requirements; they raise Sybil cost but do not establish beta and do not alter uniform core sampling.

Silent/late/invalid/undecoded observations reduce voteCount under the new success rule, while D remains the full captured peer population in the hypergeometric tail. Answering and decoding may depend on adversarial identity and vote side; tail weights are not a proved sequential error bound under this selection. Report actual voteCount, side counts and adversarial response shares. Fixed-population response selection and measured-deadline starvation are concrete review obligations; zero false/split freezes remain hard test assertions, not results established here. A majority answer floor does not remove response selection: with D=K=16, eight YES and eight NO peers, timely eight YES plus one NO meet the floor and success threshold, yielding H=1/1430 and FINAL-in after three identical rounds before seven slow NO replies arrive. The mirrored timing yields FINAL-out. This concrete case remains unresolved against the hard safety assertions; no altered voting rule or weaker oracle is selected here.

Freezing under a continuous arrival stream is not established by this specification and is measured by R10. A freeze can be invalidated by a later root-changing admission; body-latency decomposition metrics do not assert that the first freeze follows the final admission of an unbounded stream.

Candidate-ID keyed XOR proofs do not prove body possession, complete collision-body agreement, identity independence or honest vote intent. A peer holding both candidate sets can supply different valid MATCH proofs to different pollers. Reversible exclusion, the mean-confidence entry gate, new arrivals, response conditioning and decode-conditioned item evidence require measured agreement/false-freeze evaluation. Freezing is the specified item-state condition under the stated identity, sampling and response assumptions, not proof of current body possession, agreement, or an unlimited-height error bound.
