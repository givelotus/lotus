# Reconciliation core: normative specification

This section specifies a new reconciliation core. Historical miniblock designs and measurements elsewhere do not establish its implementation, performance or safety. This section controls the core where historical descriptions conflict.

## §1 ARCHITECTURE

The core is a sans-IO deterministic state machine. No sockets, threads, wall clock, globals, or hidden randomness. Time and an RNG seed are passed in; all output is returned as Actions. The host serializes all calls (single owner); the core never calls host services. RootFn is the explicit exception: a pure deterministic calculation supplied by Config, with no IO, mutation, hidden randomness or access to peer ground truth.

```
class SnowstormNode {
  explicit SnowstormNode(Config cfg); // beta_max, epsilon, max_set_size, RootFn, rng_seed
  Actions on_tx_admitted(TxHandle, Time);
  Actions on_tx_removed(ShortId, RemovalReason, Time);
  Actions on_tx_body_removed(ShortId, TxHash, RemovalReason, Time);
  Actions on_tx_bodies_result(PeerId, ShortId, BodyResult, Time);
  Actions on_message(PeerId, ByteSpan, Time);
  Actions on_timer(Time);
  Actions on_peer_connected(PeerId, PeerCaps, Time);
  Actions on_peer_disconnected(PeerId, Time);
  Actions on_new_tip(TipParams, Time);
  Actions on_block_disconnected(TipParams, Time);
  Stats stats() const;
};
Action = Send{peer,bytes} | FetchBody{peer,short_id,fetch_id}
       | Frozen{root,txids} | PeerMisbehaved{peer,reason} | ScheduleTimer{at};
```

RemovalReason is expiry, trim, conflict, reorg, batch_loser, variant, replaced or other. TxHandle is an immutable opaque shared handle exposing 32-byte txid, 32-byte tx_hash and short_id. The core computes current short_id from tx_hash and TipParams; a cached handle short_id is not authoritative after rekey. TipParams contains a 32-byte tip context, SipHash k0/k1 and surviving handles. PeerId is a nonzero host-assigned connection identity never reused within a node lifetime; a reconnect has a fresh PeerId. PeerCaps contains protocol_version and positive host-measured RTT. Only version 2 compatible peers enter D and protocol handling; incompatible peers generate no protocol traffic and are not penalized for incompatibility.

Time is signed int64 monotonic microseconds, with 0 <= Time <= INT64_MAX. Calls must be nondecreasing in Time. Backwards times and local arithmetic overflow return no Actions, set Stats.last_api_error, and leave protocol state unchanged. Config requires finite 0<=beta_max<1/3, finite 0<epsilon<1, 1<=max_set_size<=floor((2^21−256)/8) and a nonempty RootFn. Invalid Config throws std::invalid_argument before allocating protocol state. Remote input never throws out of an API call or reaches an assertion. The host must keep admitted distinct-ID count and total admitted body count each <=max_set_size. An over-capacity admission is an explicit local API error, not a false successful admission. Other public operations return typed errors rather than wrapping integers or silently changing operands.

Host contract: every FetchBody token receives exactly one result, even after cancel/reset/disconnect (host owns timeouts). BodyResult contains fetch_id, optional expected_tx_hash, one of admitted, not_found, invalid or local_rejected, and binding status matched or unbound. The host first parses body bytes and verifies their tx_hash maps to the requested short ID with the request's tip key. Unparseable/wrong-ID bytes are unbound peer-local failures; they cannot justify global invalid-ID rejection. Only a matching-ID body that fails actual transaction validation is invalid/matched. admitted requires matched binding, the exact32-byte expected_tx_hash whose current short ID equals the requested ID, and successful actual admission. local_rejected requires matched binding and expected_tx_hash: a valid bound body was not admitted solely because of local policy/resource/temporary-context constraints, and no global invalidity is established. The host must not map policy refusal to admitted, not_found or invalid. On a live token, validate the status and binding enum domains before interpreting status-specific fields. not_found ignores binding/hash fields only after both enum values are valid. invalid/matched requires the matched32-byte hash; invalid/unbound ignores any supplied hash and is donor failure. admitted/unbound, local_rejected/unbound, missing/wrong-binding required hashes or illegal enum values on a live token are local HostContractError with no state mutation or peer penalty. Stale/unknown/completed tokens are ignored before interpreting their payload. The host sends an admitted result before the matching on_tx_admitted; that callback must eventually follow unless a tip transition cancels its generation. It never admits merely because an ID decoded. Tokens increase monotonically across tip/connection generations and never reuse; exhaustion is a nonfatal local error. Existing admitted matching IDs make late failures obsolete, not grounds for removing an admitted body. The core never inserts transactions into the host.

RootFn receives all candidate bodies in canonical (txid bytes,tx_hash bytes) lexicographic order; the identity of the tip is an explicit additional RootFn input. It returns 32 bytes and must be collision-resistant for honest equality inference. Frozen contains sorted unique txids represented by those candidate bodies. Root equality is a peer assertion, not authentication of a Byzantine peer's bodies. Out of scope: SnapBlock/Stage1.5, conflict resolution/BatchId, stake weighting and consensus changes.

## §2 FIELD GF(2^64)

P(x)=x^64+x^4+x^3+x+1 (reduction constant 0x1B). Multiply: hardware carry-less multiply (PMULL/PCLMULQDQ) selected by runtime CPU detection using function target attributes; portable fallback using 4-bit windowed tables. Squaring: byte tables. Inverse: Itoh–Tsujii. Batch inverse: Montgomery's trick. inv(0) returns a typed ZeroInverse error. Batch inverse rejects a batch containing zero atomically with the same error; an empty batch succeeds with empty output. solve(D) for u^2+u=D returns false iff Tr(D)=1; otherwise use the even-degree method with theta=x^61 (Tr(theta)=1), byte-wise tables, and verify y^2+y==D before returning. solve(0) returns true,y=0. Half-trace is incorrect in even-degree fields and forbidden. Runtime backend selection and portable/hardware agreement are observable without exposing mutable dispatch state.

## §3 SHORT IDS AND BODIES

short_id is the 64-bit SipHash-2-4(k0,k1,tx_hash) result; zero maps to one. The tx_hash argument is exactly its canonical 32-byte sequence, not TxId||TxHash. Different witness tx_hash values generally have different IDs but can collide. R is keyed by distinct short_id; each ID owns its admitted body bucket. A second distinct body under an ID changes its body view and changes the root only if that ID is in W; it does not change the ID sketch or admission sequence. Duplicate admission of the same tx_hash is a no-op.

on_tx_body_removed(id,hash) removes precisely that body, updates the body view immediately, changes the root only for a candidate-body change, and removes the ID and its sketch contribution only when its last body leaves. Unknown body removal is a no-op. on_tx_removed(id) is the explicit whole-bucket operation; every body under that ID leaves. Host normal removal callbacks use the body-specific method. Every RemovalReason has these same core set semantics.

Sketch reconciliation establishes distinct-ID equality in tested trials, not complete collision-body agreement. A colliding body can be hidden by the ID sketch, and globally rejecting an authenticated invalid matching-ID body can conservatively suppress a valid colliding body for the height. These are explicit limitations; ordinary host validation and block fallback remain mandatory. No claim of collision-complete transaction dissemination is made.

## §4 CODING

### §4.1 Cells and decode

Cell={int32 count;u64 s1,s3,s5}, serialized in 28 bytes little-endian. count never wraps and −2^31 is forbidden: exceeding ±(2^31−1) returns local Overflow or remote PeerMisbehaved(count_overflow). Adding nonzero x with sign sigma in {−1,+1}: count+=sigma;s1^=x;s3^=x^3;s5^=x^5. A residual is received cell minus requester reference encoding at the same index.

decode(residual,idx,in_reference) returns Zero, One{x,sigma}, Two{x1,sigma1,x2,sigma2}, or Undecodable:

- Zero iff count=0 and all syndromes zero.
- One requires |count|=1,s1!=0,s3=s1^3,s5=s1^5,schedule_includes(s1,idx), and count=+1 iff s1 absent from reference (−1 iff present).
- Two requires count in {−2,0,+2},s1!=0. D=1 xor s3*s1^−3; solve(D) succeeds; x1=s1*u;x2=x1 xor s1. Require distinct nonzero roots, s5=x1^5 xor x2^5 and schedule inclusion for both. Each sigma is −1 if root in reference, +1 otherwise; require sigma1+sigma2=count. Return roots in increasing unsigned order.
- Otherwise Undecodable. Checks do not authenticate a chosen malicious set; finite syndromes are not an injective commitment for arbitrary large sets.

### §4.2 Integer Rateless IBLT schedule

Credit: Yang et al., SIGCOMM2024. Item x has i0=0. SplitMix64 state starts x. Each step adds 0x9e3779b97f4a7c15 modulo2^64; z=(z xor(z>>30))*0xbf58476d1ce4e5b9; z=(z xor(z>>27))*0x94d049bb133111eb; output=z xor(z>>31), all operations u64 modulo arithmetic. Draw u as low32 bits of exactly one output; s=2^32−u.

Given included i, next j is the least integer j>i with `s*(j+1)*(j+2) >= 2^32*(i+1)*(i+2)`. Compute with u128 integer square root of the quadratic discriminant and exact integer adjustment. No floating point. Stop/exhaust if j>max_symbol_index; never wrap. The corresponding continuous inverse-CDF has survival (i+1)(i+2)/((j+1)(j+2)), hence marginal inclusion2/(j+2). uint32 quantization is the exact implemented law. T3 retains target1/(1+i/2), million samples and4σ tolerance. This discrete law explicitly corrects the former inverse-square formula's .6400000001303852 index1 probability, which was inconsistent with2/3.

### §4.3 Sketch

encode(set,[a,b)) returns cells. Incremental cache updates every admitted ID add/remove at every cached scheduled index. Use 64-byte-aligned SoA cell storage and precomputed (x,x^3,x^5) per ID. Body-only bucket changes do not modify sketches. Range bounds and overflow are checked before mutation.

### §4.4 Peeler

Use a worklist; each pass snapshots its dirty set; changes requeue cells; attempt singletons before pairs, batch-invert s1^3 for pair candidates and recheck staleness before solving. Run until empty, without an iteration cap. Each successful item removal changes reference membership and subtracts that item from every stored scheduled residual exactly once. A Two event is atomic and removes two distinct items. The node does not subtract them again.

Keep a per-pass claim ledger of item/sign. A repeated item claim in the same fixed reply/reference pass is inconsistent_symbols and terminates processing of that reply, not an endlessly toggling +x/−x cycle. At the node boundary this peel-derived failure is discarded without PeerMisbehaved (§6.6), since shared Pending may contain another peer's fabricated ID. The reference is fixed at reply-processing entry. Host changes cannot interleave the serialized call. Fetch/Pending effects are applied after peeling; they do not mutate the input reference or cause a second subtraction. Each attempt uses an immutable-input invariant residual and a private working copy; retained replies do not keep raw cells. The harness independently retains the received wire bytes. Claimed items beyond the validated maximum possible signed difference are a peel-derived inconsistency, discarded without a peer penalty; storage exhaustion is separately ResourceLimit, never an iteration cap. No hostile input triggers debug assertions. Recoverably validate hostile inconsistency and capacity before any internal debug invariant assertion. Each successful decode audit records its entire original source cell, index, both original membership bits and grouped One/Two outputs before any residual update. Independently rechecking a Two uses that original pair cell, not two fictitious singleton checks.

Peeler append validates the entire input batch before mutation. A prohibited INT32_MIN count or reconstruction overflow returns Error::overflow; an out-of-range index returns Error::invalid_range; conflicting duplicate indices, within the batch or against stored raw cells, return Error::inconsistent_symbols; insufficient capacity returns Error::capacity. Each such error leaves all peeler state unchanged. Identical duplicate raw cells are no-ops.

## §5 SET STORE

R is the host-admitted, not-removed body set of this height, keyed by distinct short_id, each with its admission sequence. Conflicts are not resolved here. Retain the conservative rejected-ID exception: a host admission under an ID rejected this height returns RejectedId without insertion, even for a valid colliding body. This is not an exact host-pool mirror and never bypasses normal validation. Body buckets, duplicate admission, body-specific removal and sequence behavior remain as specified in §3.

The sketch cache encodes current R at [0,cached_n), extending on demand up to max_symbols_per_reply. Sparse probe indices use the same §4 schedule/encoding without allocating a dense array through the largest probe index. No snapshots, pins or change log are retained. on_new_tip/on_block_disconnected recompute IDs from surviving handles and the new key, clear Pending, confidence, W membership and per-height body-outcome marks, cancel old fetch generations and active rounds, preserve compatible connections and monotonic token generators. All surviving admitted IDs form W and start with preference in, both cumulative side counters zero, consecutive count zero, and no previous vote or FINAL status; no prior Pending or item state is inherited across tip reset. Sizing history follows the explicitly bounded rollover in §6.3. Old asynchronous results cannot mutate the new generation.

## §6 POLLS (STATELESS)

### §6.1 Canonical messages and candidate proof

Concrete wire proposal for approval: u8 version=2, u8 kind (0=POLL,1=REPLY_MATCH,2=REPLY,3=REPLY_DIFF), then tip_context[32] on every message. This new version prevents confusing old session messages with polls. Integers are u64LE unless stated, lengths canonical CompactSize, no trailing bytes. poll_id is nonzero and strictly increases without reuse per node; exhaustion is a local error. Exclusions are strictly ascending nonzero IDs. Fully validate lengths, bounds, integer arithmetic and grammar before allocating message-owned collections. Incompatible versions do not enter protocol handling.

```
POLL: poll_id, nonce[16], root[32], set_size, mode:u8, n,
      m:CompactSize, cells[m]
REPLY_MATCH: poll_id, proof[16]
REPLY: poll_id, root_vote[32], set_size,
       exclusion_count:CompactSize, exclusions[exclusion_count],
       m:CompactSize, cells[m]
REPLY_DIFF: poll_id, root_vote[32], set_size,
            exclusion_count:CompactSize, exclusions[exclusion_count],
            missing_count:CompactSize, missing[missing_count],
            wanted_count:CompactSize, wanted[wanted_count]
```

POLL mode=0 requests prefix [0,n); mode=1 requests probe {0} union {2^k−1 <= set_size}, k>=1, sorted/deduplicated and clipped to the shared cell cap by retaining the lowest requested indices. POLL’s basis is its send-time set_size, not a separate wire field. Prefix n>=1; probe n=0. REPLY is always a dense prefix [0,m), including after a probe, and carries neither mode nor basis_size. There is no redundant REPLY correlation metadata; peer, poll_id and tip context correlate it with the current slot.

set_size is own distinct admitted |R| at send/reply time, not |R union Pending|. POLL carries the poller's own R encoding at exactly the requested indices: prefix[0,n) or the clipped probe set. Its cells,root and set_size are computed from the same state. For prefix POLL m=n; for probe m is exactly the prescribed clipped index count. The receiver validates those identities and cell structure before any Ref-dependent decode. For fallback prefix REPLY, m=min(max_symbols_per_reply,max(2*n,S(abs(set_size_r−set_size_q)))). No successful-decode S(Delta) reply-cell floor remains: success sends plain IDs instead. For a probe,let h be the largest probe index actually sent;fallback REPLY is prefix[0,m),m=min(max_symbols_per_reply,max(2*(h+1),S(abs(set_size_r−set_size_q)))). Use checked/saturating arithmetic before allocation. No partial ID lists,leftover residuals or bitmaps are sent in fallback replies. At the cap the prefix cannot grow further;no unconditional growth beyond the cap is claimed. Cells, root_vote, set_size and full exclusions=R_ID minus candidate IDs are all computed from one current responder state during the serialized call. The responder keeps no poll bookkeeping and answers every well-formed POLL; generic rate limiting belongs to the host.

If responder’s candidate root equals the POLL root, send REPLY_MATCH without decoding POLL cells; structural validation still applies. Otherwise peel the POLL once against responder raw R_ID, not Pending, captured at call entry. Do not retain or rescue inbound POLL cells. On success, if the complete DIFF fits the message limit, send missing=negative decoded IDs (responder-only) and wanted=positive decoded IDs (poller-only), each strictly ascending, nonzero and disjoint. The responder fetches its eligible positive items from the poller through ordinary FetchBody with the existing Pending reservation, binding and alternate-donor lifecycle. wanted describes absence for item votes; it is not a body request and triggers no body-send host action. Ordinary incomplete inbound positives use that same bounded fetch path. An explicit contradiction discards all effects of the inbound attempt before fallback. A decode never inserts R. Response cells, root_vote, set_size and exclusions refer to one coherent responder state.

On ordinary incomplete decode or explicit peel contradiction, fall back to REPLY with cells using the existing sizing rule; no REPLY_DIFF is emitted. Peel-derived faults are silent; structural cell faults remain reportable. Partial positives from an ordinary incomplete inbound attempt follow normal fetch rules. An explicit contradiction discards ALL effects of that attempt before building fallback REPLY. If successful decoding produces a complete REPLY_DIFF exceeding the message limit, send fallback REPLY cells instead; never truncate or fragment the ID lists. Inbound decoding uses raw R so normal Pending assumptions from other peers cannot be used as its reference. For candidate IDs x, proof is LE64(XOR SipHash-2-4(nonce,0x00||LE64(x))) followed by LE64(XOR SipHash-2-4(nonce,0x01||LE64(x))). Decode nonce's first/second eight bytes as little-endian k0/k1. Hash each distinct candidate ID once, regardless of body bucket size; empty XOR=0. Nonces come from the core's seeded RNG (proposed two consecutive u64 draws serialized LE). All polls of a round are sent at round start from one state. Keep ONE round capture: admitted raw IDs with admission incarnation and candidate bit, plus Pending IDs live at round start with their live item-lifetime identity, at most M+P records total. No body handles or per-slot copies are retained. Each slot stores its 16-byte expected proof over captured W and points at that capture. Only captured item lifetimes still live at scoring time receive this round’s observations; matching Pending admission preserves its lifetime and eligibility, while loss of support or removal/readmission does not. Items first appearing after capture get no votes this round. Release the capture at round end or tip reset. A delayed poll shares the capture only if the captured admitted/candidate/Pending state remains unchanged; otherwise defer it to the next round. Never create a second capture. Verify REPLY_MATCH against the stored proof even if current own root has changed. Mismatch still causes inconsistent_reply and abstention; do not discard a valid old-root MATCH merely because a body was admitted meanwhile. Candidate proof is algebraic set evidence, not authentication of bodies or identities.

The poller keeps fixed current-round slots (peer,poll_id,nonce,n,mode,send-time |R|,sent root,sent time,expected proof[16],shared round-capture reference,answer status). Correlated duplicates cannot contribute twice. Stale/unknown context or connection generations cannot mutate current evidence. Discard late replies entirely: no decoding, fetching, sizing, evidence or votes. No past-round slots are retained.


REPLY_DIFF is a complete reconstruction with no cell peeling or retention; its lists remain unauthenticated peer assertions. W_j=((round capture raw R minus wanted) union missing) minus peer exclusions. Start from captured raw R, including locally excluded IDs. For a captured Pending ID absent from captured raw R, the peer holds it exactly when it occurs in missing; use this reconstruction for all eligible captured lifetimes. Post-capture items receive no observation. Removal/readmission invalidates old-incarnation observations; matching live Pending admission preserves its state and eligibility. Fallback decoding causes no automatic back-propagation; a node discovers items through its own polls and existing fetch path.

An item preference or counter alone never cancels a fetch or creates an epoch rejection mark. Partial positives still use the normal fetch path. Core retains no second raw-cell array. Raw cells can be reconstructed as residual+encode(current Ref); the harness separately owns wire bytes. Nothing is retained across round end or tip cancellation. Explicit contradictions discard the reply under the existing nonpunitive policy.

Each peel attempt copies the invariant residual into ONE transient working buffer of at most max_symbols_per_reply cells, peels that copy, then discards it. Charge the buffer within decode workspace. Never retain private peel subtractions as invariant residuals. Capture Ref at attempt start for W_j and audit; after peel, apply eligible fetch/Pending effects. Partial positives follow the same live-fetch rules; they do not authenticate bodies.

Rescue contributes no new item observations that round: neither decoded later items nor newly inferred shared items replace arrival abstention. This includes dirty-set attempts caused within the same API call after the first arrival peel. Already eligible arrival observations remain governed by their captured lifetime and the existing validity/discard rules. Ordinary failure leaves the reply retained and clean; contradictions follow §6.6. Cascading Ref additions can dirty earlier replies; choose the smallest dirty poll order next.

Arrival observations use the existing bounded round-evidence records keyed to captured item lifetimes and selected peers. Record at most one outcome per selected peer/item; later rescue does not update it. Ordinary lifetime/validity filters still apply at scoring. No per-reply cell-index evidence buffer or extra evidence-only peel is retained or run. Capture/evidence storage is released at round end or tip reset and actual capacities remain charged under §6.5.

No work cap and no proportionality claim. A retained reply is re-peeled only after a Ref change touches its indices. Within the cascade of one call, Ref gains at most P new Pending entries and an ID cannot re-enter Pending in that call. Assert attempts per call<=retained-reply bound*(1+Ref changes in the call), conservatively using K as the reply bound, without terminating at a runtime cap. Keep eligible item evidence and update retained residuals for net Ref changes, including admission/removal. There is no separate root-confidence state or root-change scoring veto. Tip/generation reset still cancels the round. Rescues use current Ref for dissemination; item observation eligibility and values come from the arrival outcome and the corresponding captured lifetime.

Sizing Delta_hat_now and Delta_hat_start are captured only at first processing, using its pre-peel bitmap and original attempt's lower bound; later attempts create no new samples and never rewrite earlier ones. Full-observation tests record the complete cascade in observation-owned growable storage (§10); audit allocation failure is a test failure, not a protocol ResourceLimit or an atomic-reservation requirement. ### §6.3 Adaptive sizing and frozen S(d)

A timely REPLY_DIFF supplies uncensored start and now samples defined in §6.1. A fallback REPLY means either inbound decode did not succeed or a complete DIFF exceeded the message limit; apply the existing approximate estimator and growth rule to its cells. Every timely processed REPLY with cells records which residual cells are zero BEFORE peeling. Exclude index0 from the likelihood because p0=1; a zero symbol0 is used in the explicit zero-estimate branch below. For i>=1 use p_i=2/(i+2) and the model P(empty at i)=(1−p_i)^Delta. This is an independence approximation: schedule cells are correlated and mixed-sign cancellation is treated as negligible. Call the result the approximate maximum-likelihood estimate, not an exact MLE.

Let L=max(number of distinct items decoded from this reply,abs(raw symbol0 count minus reference symbol0 count)). Maximize over integer Delta>=L:

`sum_empty Delta*ln(1−p_i) + sum_nonempty ln(1−(1−p_i)^Delta)`.

The stated objective is unimodal; search integer Delta in[L,2*M+P] with smaller-Delta tie breaking and stable log evaluation. If the maximizer would lie above the domain, record a censored result at L; never perform unbounded search. If all received nonzero-index cells are pre-peel empty and symbol0 residual is zero, Delta_hat=0. If no nonzero-index cell is pre-peel empty, record a censored estimate with lower bound L. For probe{0} with no nonzero-index cells, zero symbol0 residual gives Delta_hat=0; otherwise censor at L. The estimate is an approximation even on hostile input and never authenticates a set. Censored samples enter request selection at L; no floating-point estimates are rounded into different counts silently.

Compute two estimates per reply. Delta_hat_now uses the Ref captured at reply entry and sizes the next round. Delta_hat_start applies the same estimator after adding back the effect of items that entered Pending/Ref since round start, bounded by P, solely for estimation; it determines the next-height ratio. ## §9 SIMULATOR AND EVALUATION

Rationale: Snowstorm is push-pull gossip. A random-subset POLL carries the poller's cells, letting the responder discover missing items immediately. If decoded, the responder returns the signed difference as plain IDs in REPLY_DIFF; otherwise it returns cells in fallback REPLY. In a successfully decoded nonmatching exchange, cells move into the POLL rather than being added to a cell-bearing reply; fallback exchanges can carry cells in both directions. One exchange therefore disseminates in both directions rather than requiring a later reverse poll. Under uniform regular connectivity each node sends K polls and receives about K polls per round in expectation, so polling itself is push-pull. The intended latency benefit is saving the wait for a reverse poll, described as half a round; actual timing and decode success are measured, not guaranteed. [Karp, Schindelhauer, Shenker and Vöcking, Randomized Rumor Spreading, FOCS2000](https://archive.cone.informatik.uni-freiburg.de/pubs/rumor.pdf) motivates combining directions, not a complete Snowstorm protocol proof.

Cost: POLL cells are sent before the poller knows whether roots match. When sets agree those cell bytes are wasted even though the response can be REPLY_MATCH. Its proof is16 bytes; with the unchanged proposed version/kind,tip context and poll_id framing the full application payload is58 bytes, not16 under this grammar. Adaptive sizing shrinks requests as estimated differences shrink, subject to the request floor. Report poll-cell bytes on all exchanges and on matched exchanges separately in Stats and evaluation, plus REPLY_DIFF ID bytes  and fallback reply-cell bytes.


Body-latency rationale: a decoded ID is not a transaction. Body delivery and host validation precede admission into R; candidate entry is separately gated. Rounds continue during body transfers and collect eligible item observations. A late admission initializes a fresh state or preserves its complete live Pending state. Time to freeze depends on reconciliation/body latency and on the item round counts and gate, not on a separate stable-root likelihood barrier. A freeze can precede a delayed body admission. A later item that passes the gate changes the root and invalidates that freeze. Rounds do not wait for fetch completion; no fetch gate or hidden timeout constant is added.

Per-node unique transactions are fetchable from their holding nodes. Host validation delay is1 ms and is printed in every run configuration. Evaluation body service completes after one donor-link round trip plus body_bytes/link_bandwidth serialization plus a host validation delay recorded in the run configuration. Admit at completion time, including mid-round, never batch admissions at round end. Report time to last admission and time from last admission to freeze, alongside total freeze time; separate unsuccessful fetch outcomes and nonfreezing trials. Ground-truth classification of the last admission must state its horizon and does not leak into the core.

The operational role of K and host fanout f is to trade dissemination rounds against bytes. The replacement confidence rationale is that one round is one projection of a correlated peer neighbourhood; likelihood magnitude from one projection is not accumulated as sequential confidence. Repeated round votes are required by the fixed consecutive-success threshold. Repetition alone does not prove that correlated neighbourhoods wash out: persistent partitions, response selection and adaptive equivocation remain evaluation/proof obligations, under the stated identity and sampling assumptions. No inherited Snowball security theorem or K-independent safety guarantee is claimed for this modified protocol.

Push is outside this specification. A separately tracked lotusd relay change announces each transaction to a uniformly random subset of f peers rather than all peers. This document adds no announcement message, relay algorithm or host-admission requirement to the core. In evaluation, model that existing host relay at fanout f (f=0 means no announcements); resulting validated transactions enter the unchanged core through ordinary on_tx_admitted.

## §11 LIMITATIONS AND HOST REQUIREMENTS

Sybil resistance is not provided by this core. Stake-backed identity is required for a hard beta bound. Network-group diversity (/16,/32 or ASN as defined by the host) and outbound preference are host connection-management requirements; they raise Sybil cost but do not establish beta and do not alter uniform core sampling.

Silent peers abstain, but the sampled population for quorum remains the captured K and alpha is never recomputed from answerers. Response dependence can affect liveness and the adversarial composition of usable observations; these remain evaluation and proof obligations. No independent-answering or answerer-fraction safety guarantee is established here. Neither silence nor selective response reduces alpha. The simulator must report the actual adversarial share of answerers each round from ground truth. The core cannot enforce response independence.

Freezing under a continuous arrival stream is not established by this specification and is measured by R10. A freeze can be invalidated by a later root-changing admission; body-latency decomposition metrics do not assert that the first freeze follows the final admission of an unbounded stream.

Candidate-ID keyed XOR proofs do not prove body possession, complete collision-body agreement, identity independence or honest vote intent. A peer holding both candidate sets can supply different valid MATCH proofs to different pollers. Reversible exclusion, the mean-confidence entry gate, new arrivals, response conditioning and decode-conditioned item evidence require measured agreement/false-freeze evaluation. Freezing is the specified item-state condition under the stated identity, sampling and response assumptions, not proof of current body possession, agreement, or an unlimited-height error bound.
