# Reconciliation core: normative specification

This section specifies a new reconciliation core. Historical miniblock designs and measurements elsewhere do not establish its implementation, performance or safety. This section controls the core where historical descriptions conflict.

## §1 ARCHITECTURE

The core is a sans-IO deterministic state machine. No sockets, threads, wall clock, globals, or hidden randomness. Time and an RNG seed are passed in; all output is returned as Actions. The host serializes all calls (single owner); the core never calls host services. RootFunction is the explicit exception: a pure deterministic calculation supplied by Configuration, with no IO, mutation, hidden randomness or access to peer ground truth.

```cpp
class SnowstormNode
{
public:
    explicit SnowstormNode(Configuration configuration); // maximumAdversaryFraction, epsilon, maximumSetSize, RootFunction, randomSeed
    Actions OnTransactionAdmitted(TransactionHandle, Time);
    Actions OnTransactionRemoved(ShortID, RemovalReason, Time);
    Actions OnTransactionBodyRemoved(ShortID, TransactionHash, RemovalReason, Time);
    Actions OnTransactionBodiesResult(PeerID, ShortID, BodyResult, Time);
    Actions OnMessage(PeerID, ByteSpan, Time);
    Actions OnTimer(Time);
    Actions OnPeerConnected(PeerID, PeerCapabilities, Time);
    Actions OnPeerDisconnected(PeerID, Time);
    Actions OnNewTip(TipParameters, Time);
    Actions OnBlockDisconnected(TipParameters, Time);
    AdmissionAuthorization GetAdmissionAuthorization(FetchID, TransactionHash) const;
    NodeStatistics GetStatistics() const;
};
```

Action alternatives: Send{peer,bytes}, FetchBody{peer,shortID,fetchID,admissionMode}, Frozen{tipContext,epochNumber,root,transactionIDs}, PeerMisbehaved{peer,reason}, ProtocolAnomaly{shortID,reason}, ScheduleTimer{at}.


RemovalReason is expiry, trim, conflict, reorg, batchLoser, variant, replaced or other. TransactionHandle is an immutable opaque shared handle exposing 32-byte transactionID, 32-byte transactionHash, shortID and an immutable spentInputKeys view supplied by the validating host. The view contains sorted unique canonical outpoint identities from that exact body’s inputs, using the chain adapter’s existing outpoint identity; it is local metadata, not a new network encoding. Equal keys mean the same spent input. The host validates body-to-descriptor identity and actual transaction validity before supplying it. Core conflict checks use only these supplied immutable inputs, with no IO, body parsing, remote conflict assertion or hidden host query. The core computes current shortID from transactionHash and TipParameters; a cached handle shortID is not authoritative after rekey. TipParameters contains a 32-byte tip context, SipHash k0/k1 and surviving handles. PeerID is a nonzero host-assigned connection identity never reused within a node lifetime; a reconnect has a fresh PeerID. PeerCapabilities contains protocolVersion and positive host-measured RTT. Only version 3 compatible peers enter D and protocol handling; incompatible peers generate no protocol traffic and are not penalized for incompatibility.

Time is signed int64 monotonic microseconds, with 0 <= Time <= INT64_MAX. Calls must be nondecreasing in Time. Backwards times and local arithmetic overflow return no Actions, set NodeStatistics.lastAPIError, and leave protocol state unchanged. Configuration requires finite 0<=maximumAdversaryFraction<1/3, finite 0<epsilon<1, 1<=maximumSetSize<=floor((2^21−256)/8) and a nonempty RootFunction. Invalid Configuration throws std::invalid_argument before allocating protocol state. Remote input never throws out of an API call or reaches an assertion. The host must keep admitted distinct-ID count and total admitted body count each <=maximumSetSize. An over-capacity admission is an explicit local API error, not a false successful admission. Other public operations return typed errors rather than wrapping integers or silently changing operands.

Host contract: every FetchBody token receives exactly one result, even after cancel/reset/disconnect (host owns timeouts). BodyResult contains fetchID, optional expectedTransactionHash, one of admitted, notFound, invalid or localRejected, and binding status matched or unbound. The host first parses body bytes and verifies their transactionHash maps to the requested short ID with the request's tip key. Unparseable/wrong-ID bytes are unbound peer-local failures; they cannot justify global invalid-ID rejection. Only a matching-ID body that fails actual transaction validation is invalid/matched. admitted requires matched binding, the exact32-byte expectedTransactionHash whose current short ID equals the requested ID, and successful actual admission. localRejected requires matched binding and expectedTransactionHash: a valid bound body was not admitted solely because of local policy/resource/temporary-context constraints, and no global invalidity is established. The host must not map policy refusal to admitted, notFound or invalid. On a live token, validate the status and binding enum domains before interpreting status-specific fields. notFound ignores binding/hash fields only after both enum values are valid. invalid/matched requires the matched32-byte hash; invalid/unbound ignores any supplied hash and is donor failure. admitted/unbound, localRejected/unbound, missing/wrong-binding required hashes or illegal enum values on a live token are local HostContractError with no state mutation or peer penalty. Stale/unknown/completed tokens are ignored before interpreting their payload. The host sends an admitted result before the matching OnTransactionAdmitted; that callback must eventually follow unless a tip transition cancels its generation. It never admits merely because an ID decoded. Tokens increase monotonically across tip/connection generations and never reuse; exhaustion is a nonfatal local error. Existing admitted matching IDs make late failures obsolete, not grounds for removing an admitted body. The core never inserts transactions into the host. Until tip reset, the host must make retained frozen-archive body handles available to the existing ordinary body-serving lookup, including bodies removed from live R. Serving an archived body does not readmit it locally or mutate its archive; request-arrival inventory includes the retained archive for the live tip context, and the requesting host still performs ordinary binding and validation. No new body request or core body-send Action is introduced.

AdmissionMode is STANDARD_POLICY or CONSENSUS_ONLY; ordinary FetchBody uses STANDARD_POLICY. CONSENSUS_ONLY is an explicit host request to fetch/revalidate and admit a FINAL-in body, or a majority-preferred validated conflict alternative under §8.1, using consensus validity rather than host policy. This is a local action attribute, not a new network field or body-send protocol. ProtocolAnomaly reports a FINAL-in item subsequently proven consensus-invalid or contradictory conflict FINAL-in decisions; it never authorizes admission or reversal of an immutable terminal decision. BodyResult.localRejectionReason distinguishes POLICY from RESOURCE or CONTEXT, validated with the existing live-token enum/hash/binding checks. Only POLICY authorizes the new override. The host must keep configured admission/body bounds before reporting admitted; no core eviction rule is selected. A verified first-seen conflict may also authorize the same path on an IN majority-preference transition before FINAL, as §8.1 specifies; conflict handling is no longer deferred.

RootFunction is the host's existing non-coinbase merklix transaction subtree function (Subtree A), the same TransactionSubtreeARoot/BuildTxSubtreeA used inside the block transaction commitment. The overlay contains ordinary non-coinbase transactions only; it cannot commit to a miner's not-yet-created coinbase. For a complete reconstructed block, compare RootFunction(block non-coinbase bodies) with stored frozen overlay roots. For a header-plus-coinbase snap candidate, combine the received coinbase leaf with each stored overlay subtree root using the existing TransactionRootFromSubtreeA function and compare with the header transaction root before constructing/validating the candidate. GBT uses the latest frozen non-coinbase overlay and ordinary coinbase/header construction. These are two views of the same existing block commitment, not a new commitment algorithm. It receives the canonical transaction body set in (transactionID bytes,transactionHash bytes) lexicographic order and returns32 bytes. Do not add the tip, epoch number, a separate prefix hash construction or an ordered epoch manifest to this transaction commitment; tip/epoch correlation is separate protocol context. The frozen overlay O_k is the union of this tip's frozen epoch batches1..k; O_0 is empty. Frozen.root=RootFunction(O_k), and Frozen.transactionIDs is the sorted unique transactionID set of that cumulative overlay, not just the newly frozen batch. Root equality remains a peer assertion, not authentication of a Byzantine peer's bodies. GBT returns the latest frozen overlay, never the active unfrozen candidate set. Before this tip's first nonempty freeze, the Snowstorm-backed GBT path reports no frozen overlay available; it neither exposes active W nor fabricates an empty frozen epoch. Ordinary host behavior outside that path is unchanged. Before clearing old-tip state on block receipt, the host computes the block's reconstructed non-coinbase merklix subtree root with that same function and looks it up among all overlay roots frozen since the preceding block. A match selects the corresponding retained overlay as a snap-block reconstruction; no match uses ordinary block relay. Ordinary consensus/body validation remains mandatory in both paths. No new block/header consensus field or destination rule is introduced. Conflict policy handling is §8.1; BatchId, stake weighting and consensus changes remain out of scope; the overlay lookup and GBT integration are now in scope.

## §2 FIELD GF(2^64)

P(x)=x^64+x^4+x^3+x+1 (reduction constant 0x1B). Multiply: hardware carry-less multiply (PMULL/PCLMULQDQ) selected by runtime CPU detection using function target attributes; portable fallback using 4-bit windowed tables. Squaring: byte tables. Inverse: Itoh–Tsujii. Batch inverse: Montgomery's trick. Invert(0) returns a typed ZeroInverse error. Batch inverse rejects a batch containing zero atomically with the same error; an empty batch succeeds with empty output. Solve(D) for u^2+u=D returns false iff Tr(D)=1; otherwise use the even-degree method with theta=x^61 (Tr(theta)=1), byte-wise tables, and verify y^2+y==D before returning. Solve(0) returns true,y=0. Half-trace is incorrect in even-degree fields and forbidden. Runtime backend selection and portable/hardware agreement are observable without exposing mutable dispatch state.

## §3 SHORT IDS AND BODIES

shortID is the 64-bit SipHash-2-4(k0,k1,transactionHash) result; zero maps to one. The transactionHash argument is exactly its canonical 32-byte sequence, not TransactionID||TransactionHash. Different witness transactionHash values generally have different IDs but can collide. R is keyed by distinct shortID; each ID owns its admitted body bucket. A second distinct body under an ID changes its body view and changes the root only if that ID is in W; it does not change the ID sketch or admission sequence. Duplicate admission of the same transactionHash is a no-op.

OnTransactionBodyRemoved(id,hash) removes precisely that body, updates the body view immediately, changes the root only for a candidate-body change, and removes the ID and its sketch contribution only when its last body leaves. Unknown body removal is a no-op. OnTransactionRemoved(id) is the explicit whole-bucket operation; every body under that ID leaves. Host normal removal callbacks use the body-specific method. Every RemovalReason has these same live-R semantics. Removing a frozen body from live R does not mutate its retained archive handle, batch membership or overlay root; archive retention is charged under §6.5 until tip reset.

Sketch reconciliation establishes distinct-ID equality in tested trials, not complete collision-body agreement. A colliding body can be hidden by the ID sketch, and globally rejecting an authenticated invalid matching-ID body can conservatively suppress a valid colliding body for the height. These are explicit limitations; ordinary host validation and block fallback remain mandatory. No claim of collision-complete transaction dissemination is made.

## §4 CODING

### §4.1 Cells and decode

Cell={int32 count;u64 s1,s3,s5}, serialized in 28 bytes little-endian. count never wraps and −2^31 is forbidden: exceeding ±(2^31−1) returns local Overflow or remote PeerMisbehaved(countOverflow). Adding nonzero x with sign sigma in {−1,+1}: count+=sigma;s1^=x;s3^=x^3;s5^=x^5. A residual is received cell minus requester reference encoding at the same index.

Decode(residual,idx,inReference) returns Zero, One{x,sigma}, Two{x1,sigma1,x2,sigma2}, or Undecodable:

- Zero iff count=0 and all syndromes zero.
- One requires |count|=1,s1!=0,s3=s1^3,s5=s1^5,ScheduleIncludes(s1,idx), and count=+1 iff s1 absent from reference (−1 iff present).
- Two requires count in {−2,0,+2},s1!=0. D=1 xor s3*s1^−3; Solve(D) succeeds; x1=s1*u;x2=x1 xor s1. Require distinct nonzero roots, s5=x1^5 xor x2^5 and schedule inclusion for both. Each sigma is −1 if root in reference, +1 otherwise; require sigma1+sigma2=count. Return roots in increasing unsigned order.
- Otherwise Undecodable. Checks do not authenticate a chosen malicious set; finite syndromes are not an injective commitment for arbitrary large sets.

### §4.2 Integer Rateless IBLT schedule

Credit: Yang et al., SIGCOMM2024. Item x has i0=0. SplitMix64 state starts x. Each step adds 0x9e3779b97f4a7c15 modulo2^64; z=(z xor(z>>30))*0xbf58476d1ce4e5b9; z=(z xor(z>>27))*0x94d049bb133111eb; output=z xor(z>>31), all operations u64 modulo arithmetic. Draw u as low32 bits of exactly one output; s=2^32−u.

Given included i, next j is the least integer j>i with `s*(j+1)*(j+2) >= 2^32*(i+1)*(i+2)`. Compute with u128 integer square root of the quadratic discriminant and exact integer adjustment. No floating point. Stop/exhaust if j>maximumSymbolIndex; never wrap. The corresponding continuous inverse-CDF has survival (i+1)(i+2)/((j+1)(j+2)), hence marginal inclusion2/(j+2). uint32 quantization is the exact implemented law. T3 retains target1/(1+i/2), million samples and4σ tolerance. This discrete law explicitly corrects the former inverse-square formula's .6400000001303852 index1 probability, which was inconsistent with2/3.

### §4.3 Sketch

Encode(set,[a,b)) returns cells. Incremental cache updates every advertised A membership gain/loss at every cached scheduled index. Use 64-byte-aligned SoA cell storage and precomputed (x,x^3,x^5) per ID. Body-only bucket changes do not modify sketches. Range bounds and overflow are checked before mutation.

### §4.4 Peeler

Use a worklist; each pass snapshots its dirty set; changes requeue cells; attempt singletons before pairs, batch-invert s1^3 for pair candidates and recheck staleness before solving. Run until empty, without an iteration cap. Each successful item removal changes reference membership and subtracts that item from every stored scheduled residual exactly once. A Two event is atomic and removes two distinct items. The node does not subtract them again.

Keep a per-pass claim ledger of item/sign. A repeated item claim in the same fixed reply/reference pass is inconsistentSymbols and terminates processing of that reply, not an endlessly toggling +x/−x cycle. At the node boundary this peel-derived failure is discarded without PeerMisbehaved (§6.6), since shared Pending may contain another peer's fabricated ID. The reference is fixed at reply-processing entry. Host changes cannot interleave the serialized call. Fetch/Pending effects are applied after peeling; they do not mutate the input reference or cause a second subtraction. Each attempt uses an immutable-input invariant residual and a private working copy; retained replies do not keep raw cells. The harness independently retains the received wire bytes. Claimed items beyond the validated maximum possible signed difference are a peel-derived inconsistency, discarded without a peer penalty; storage exhaustion is separately ResourceLimit, never an iteration cap. No hostile input triggers debug assertions. Recoverably validate hostile inconsistency and capacity before any internal debug invariant assertion. Each successful decode audit records its entire original source cell, index, both original membership bits and grouped One/Two outputs before any residual update. Independently rechecking a Two uses that original pair cell, not two fictitious singleton checks.

Peeler append validates the entire input batch before mutation. A prohibited INT32_MIN count or reconstruction overflow returns Error::overflow; an out-of-range index returns Error::invalidRange; conflicting duplicate indices, within the batch or against stored raw cells, return Error::inconsistentSymbols; insufficient capacity returns Error::capacity. Each such error leaves all peeler state unchanged. Identical duplicate raw cells are no-ops.

## §5 SET STORE

R owns currently host-admitted body buckets. In addition, retain immutable body handles/membership for frozen batches until the next tip; a held frozen body occurs once in the union of R and that archive, not once per cumulative overlay. Only held bodies outside the archive participate in the active epoch. Let activeAdmittedIDs denote the distinct IDs of those active bodies, and A={id in activeAdmittedIDs whose active-epoch state is not FINAL-out}. Encode A in active POLL/REPLY cells and setSize=|A|; exclusions are A minus active candidate IDs. Frozen prefix bodies are not encoded again in the active sketch. The active decode reference is Ref=(A union Pending) minus active FINAL-out IDs; inbound polls decode against the selected active or historical raw set alone. A is derived without a second live body store. A gain/loss updates caches/retained invariant residuals exactly once. Body membership is tracked by immutable body identity, so an archived body does not reactivate on duplicate admission; a later distinct colliding body retains §3's collision limitations. The union of active/held and archived distinct bodies and IDs counts against M.

R is the host-admitted, not-removed body set of this height, keyed by distinct shortID, each with its admission sequence. The host keeps at most one held spend of each common input using first-seen policy initially; §8.1 permits majority-selected replacement and protects frozen winners. Conflict detection uses direct input intersection, never a transitive conflict equivalence class. Retain the conservative rejected-ID exception: a host admission under an ID rejected this height returns RejectedId without insertion, even for a valid colliding body. This is not an exact host-pool mirror and never bypasses normal validation. Body buckets, duplicate admission, body-specific removal and sequence behavior remain as specified in §3.

The sketch cache encodes active A at [0,cachedSymbolCount), extending on demand within the cell cap; sparse probes never allocate a dense array through the largest index. EpochNumber starts at1 for each tip. At a nonempty freeze, retain the newly frozen batch once, its cumulative overlay root and its epoch number, then atomically advance to the next epoch. Archive membership/root/body views are immutable until tip reset; host removal of a frozen body from R does not erase its retained archive handle or change a frozen root. A new distinct body sharing an archived ID remains an active collision-bucket body and cannot mutate the archived view. Active W is the held, nonarchived body set selected by active item preferences. All held nonarchived items start the next epoch IN with zero preference counters, absent confidence/zero evidence/count and no FINAL status, including items previously FINAL-out. Unadmitted Pending starts OUT with zero epoch-local counters/confidence/FINAL; preserve its reservation, live fetch/awaiting/policy phase, donor retries and token/hash bindings. End the completed round; release its capture, observations, retained replies and sizing work, reset active sizing banks/prefix and root confidence, then permit the next epoch's first poll only from a fresh capture. No old-epoch reply supplies effects to the new epoch. Immutable archived batch handles are the sole approved historical membership retention; no historical cell array or poll model is retained.

OnNewTip/OnBlockDisconnected discard old-tip overlay records after the host's snap lookup, cancel old fetch generations/rounds, rekey surviving host handles and start epoch1 with all surviving held items IN and fresh item/root state. The host supplies survivors after removing block-included transactions; omitted frozen transactions that remain held are included in the new remainder. A reorg uses the same surviving-handle rule. Preserve compatible connections and monotonic poll/fetch token generators; prior Pending state is not inherited across a tip reset. Height sizing history follows §6.3; epoch rollover within a tip clears active sizing but does not reset the deadline floor. Old asynchronous results cannot mutate a new tip generation.

## §6 POLLS (STATELESS)

### §6.1 Canonical messages and candidate proof

Concrete wire proposal for approval: u8 version=3, u8 kind (0=POLL,1=REPLY_MATCH,2=REPLY,3=REPLY_DIFF), then tipContext[32], epochNumber:u64LE and frozenPrefixRoot[32] on every message. frozenPrefixRoot is the already existing merklix overlay root for epochNumber−1, with RootFunction(empty) for epoch1; it is not a separate prefix commitment function. epochNumber>=1. All four messages carry this context; POLL additionally carries its current overlay root in the existing root field. This distinguishes same-prefix/different-active-set replies from genuine prefix splits. This new version prevents confusing old session messages with polls. Integers are u64LE unless stated, lengths canonical CompactSize, no trailing bytes. pollID is nonzero and strictly increases without reuse per node; exhaustion is a local error. Exclusions are strictly ascending nonzero IDs. Fully validate lengths, bounds, integer arithmetic and grammar before allocating message-owned collections. Incompatible versions do not enter protocol handling.

```
POLL: pollID, nonce[16], root[32], setSize, mode:u8, n,
      m:CompactSize, cells[m]
REPLY_MATCH: pollID, proof[16]
REPLY: pollID, rootVote[32], setSize,
       exclusionCount:CompactSize, exclusions[exclusionCount],
       m:CompactSize, cells[m]
REPLY_DIFF: pollID, rootVote[32], setSize,
            exclusionCount:CompactSize, exclusions[exclusionCount],
            missingCount:CompactSize, missing[missingCount],
            wantedCount:CompactSize, wanted[wantedCount]
```

POLL mode=0 requests prefix [0,n); mode=1 requests probe {0} union {2^k−1 <= setSize}, k>=1, sorted/deduplicated and clipped to the shared cell cap by retaining the lowest requested indices. POLL’s basis is its send-time setSize, not a separate wire field. Prefix n>=1; probe n=0. REPLY is always a dense prefix [0,m), including after a probe, and carries neither mode nor basisSize. There is no redundant REPLY correlation metadata; peer, pollID, tip context and epochNumber correlate it with the current slot; the slot also captures frozenPrefixRoot. A different frozen-prefix root at the same epoch is an incomparable-prefix reply: it counts as a correlated complete timing answer after structural validation but supplies no per-item observations, root confidence, sizing sample, fetch or peel effects. Never report that mere mismatch as peer misbehavior. Duplicate/stale/late filtering precedes effects.

setSize is own distinct advertised |A| at send/reply time, not |R union Pending|. POLL carries the poller's own A encoding at exactly the requested indices: prefix[0,n) or the clipped probe set. Its cells and setSize describe the active advertised A; its root is RootFunction(frozen prefix union active W), computed from the same serialized state. Frozen prefix bodies contribute to that root, not to active cells or setSize. For prefix POLL m=n; for probe m is exactly the prescribed clipped index count. The receiver validates those identities and cell structure before any Ref-dependent decode. For fallback prefix REPLY, m=min(maximumSymbolsPerReply,max(2*n,RequiredSymbols(abs(setSizeR−setSizeQ)))). No successful-decode RequiredSymbols(Delta) reply-cell floor remains: success sends plain IDs instead. For a probe, inspect the residual against responder A BEFORE peeling. Let bracketUpper be the smallest actually sent probe index whose residual cell is Zero; if no probe cell is Zero, use the largest actually sent probe index. Fallback REPLY is a dense prefix with m=min(maximumSymbolsPerReply,RequiredSymbols(bracketUpper)). Use the index itself, not index+1, a point estimate, or twice the probe span. RequiredSymbols(0)=1 remains valid. Capture only these transient scalar bracket operands; no retained inbound poll, per-index observation mask or sizing-bank sample is introduced. Use checked/saturating arithmetic before allocation. No partial ID lists,leftover residuals or bitmaps are sent in fallback replies. At the cap the prefix cannot grow further;no unconditional growth beyond the cap is claimed. Cells, rootVote, setSize and full exclusions=A minus candidate IDs are all computed from one current responder state during the serialized call. The responder keeps no poll bookkeeping. For the requested tip/epoch, select current active state if epochNumber equals the local active epoch, or the retained frozen batch and its cumulative overlay root if the responder is ahead. A behind responder abstains without a reply or penalty. The selected historical raw/candidate set is exactly that epoch batch, with no exclusions; its prefix is the preceding frozen overlay root, not the responder's latest prefix. Historical serving is read-only: it may perform the one transient inbound peel against the selected frozen batch to construct DIFF/fallback, but creates no fetch/Pending or local tally mutation and retains no inbound decode state. Release historical workspace before return. If the POLL's frozenPrefixRoot differs from the selected state's prefix, abstain without decoding or fetching. Otherwise answer every well-formed POLL; generic rate limiting belongs to the host.

If the selected responder overlay root equals the POLL root and their frozenPrefixRoot values agree, send REPLY_MATCH without decoding POLL cells; structural validation still applies. Otherwise peel the POLL once against the selected responder raw set (active A or historical frozen batch), not Pending, captured at call entry. Do not retain or rescue inbound POLL cells. On success, if the complete DIFF fits the message limit, send missing=negative decoded IDs (responder-only) and wanted=positive decoded IDs (poller-only), each strictly ascending, nonzero and disjoint. An active-state responder fetches its eligible positive items from the poller through ordinary FetchBody with the existing Pending reservation, binding and alternate-donor lifecycle. wanted describes absence for item votes; it is not a body request and triggers no body-send host action. Ordinary incomplete inbound positives use that same bounded fetch path only for an active-state responder; historical service never initiates a fetch. An explicit contradiction discards all effects of the inbound attempt before fallback. A decode never inserts R. Response cells, rootVote, setSize and exclusions refer to one coherent responder state.

On ordinary incomplete decode or explicit peel contradiction, fall back to REPLY with cells using the existing sizing rule; no REPLY_DIFF is emitted. Peel-derived faults are silent; structural cell faults remain reportable. Partial positives from an ordinary incomplete inbound attempt follow normal fetch rules. An explicit contradiction discards ALL effects of that attempt before building fallback REPLY. If successful decoding produces a complete REPLY_DIFF exceeding the message limit, send fallback REPLY cells instead; never truncate or fragment the ID lists. Inbound decoding uses raw A so normal Pending assumptions from other peers cannot be used as its reference. For selected active or historical batch candidate IDs x (excluding the frozen prefix), proof is LE64(XOR SipHash-2-4(nonce,0x00||LE64(x))) followed by LE64(XOR SipHash-2-4(nonce,0x01||LE64(x))). Decode nonce's first/second eight bytes as little-endian k0/k1. Hash each distinct candidate ID once, regardless of body bucket size; empty XOR=0. Nonces come from the core's seeded RNG (proposed two consecutive u64 draws serialized LE). All polls of a round are sent at round start from one state and capture the same tip, epoch number and frozenPrefixRoot. Keep ONE round capture: advertised admitted IDs with admission incarnation and candidate bit, plus Pending IDs live at round start with their live item-lifetime identity, at most M+P records total. No body handles or per-slot copies are retained. Each slot stores its 16-byte expected proof over captured W and points at that capture. Only captured item lifetimes still live at scoring time receive this round’s observations; matching Pending admission preserves its lifetime and eligibility, while loss of support or removal/readmission does not. Items first appearing after capture get no votes this round. Release the capture at round end, epoch rollover or tip reset. A delayed poll shares the capture only if the captured admitted/candidate/Pending state remains unchanged; otherwise defer it to the next round. Never create a second capture. Verify REPLY_MATCH against the stored proof even if current own root has changed. Mismatch still causes inconsistentReply and abstention; do not discard a valid old-root MATCH merely because a body was admitted meanwhile. Candidate proof is algebraic set evidence, not authentication of bodies or identities.

The poller keeps fixed current-round slots (peer,pollID,nonce,n,mode,send-time |A|,sent root,sent time,expected proof[16],shared round-capture reference,answer status). Correlated duplicates cannot contribute twice. Stale/unknown context or connection generations cannot mutate current evidence. Discard late replies entirely: no decoding, fetching, sizing, evidence or votes. No past-round slots are retained.


REPLY_DIFF is a complete reconstruction with no cell peeling or retention; its lists remain unauthenticated peer assertions. peerCandidates=((round capture raw A minus wanted) union missing) minus peer exclusions. Start from captured raw A, including locally excluded IDs. For a captured Pending ID absent from captured raw A, the peer holds it exactly when it occurs in missing; use this reconstruction for all eligible captured lifetimes. Post-capture items receive no observation. Removal/readmission invalidates old-incarnation observations; matching live Pending admission preserves its state and eligibility. The poller starts ordinary FetchBody for eligible missing items, deduplicating concurrent in-flight/awaiting operations and preserving alternate-donor retry. wanted triggers no fetch or body-send action at the poller. Admission remains host-authoritative. Record estimatedRoundStartDifference=|missing|+|wanted| and estimatedCurrentDifference=|missing minus current Ref|+|wanted intersect current A| at reply-processing entry, before Pending effects. These are exact counts of the specified lists, not authenticated holdings. DIFF supplies the normal exact sizing sample and complete per-item observations.

Validate list lengths, strictly ascending nonzero IDs, disjoint missing/wanted, wanted membership in captured raw A and missing absence from captured raw A, and setSize=sentSetSize+missingCount−wantedCount with checked arithmetic. The asserted peer raw set is (captured raw A minus wanted) union missing; its cardinality must equal setSize and its exclusions must be a subset. Exclusion and complete-message bounds apply. Reject an internally inconsistent DIFF before any fetch or observation effect, using captured raw A rather than current R or Pending. wanted only describes peer absence for voting. ### §6.3 Adaptive sizing and frozen RequiredSymbols(d)

For i>=1 use inclusionProbability=2/(i+2) and the model P(empty at i)=(1−inclusionProbability)^Delta. This is an independence approximation: schedule cells are correlated and mixed-sign cancellation is treated as negligible. Call the result the approximate maximum-likelihood estimate, not an exact MLE.

Let L=max(number of distinct items decoded from this reply,abs(raw symbol0 count minus reference symbol0 count)). Maximize over integer Delta>=L:

`emptyCellSum Delta*ln(1−inclusionProbability) + nonemptyCellSum ln(1−(1−inclusionProbability)^Delta)`.

The stated objective is unimodal; search integer Delta in[L,2*M+P] with smaller-Delta tie breaking and stable log evaluation. If all received nonzero-index cells are pre-peel empty and symbol0 residual is zero, estimatedDifference=0. For probe{0}, zero residual gives estimatedDifference=0; otherwise the censored floor is max(L,InverseHalfCDF(1)). The estimate is an approximation even on hostile input and never authenticates a set. Censored samples enter request selection at their lowerSizingBound; no floating-point estimates are rounded into different counts silently.

InverseHalfCDF uses the frozen conservative step CDF and its specified extrapolation, not inverse linear median interpolation. A table-derived censor floor can exceed2*M+P on hostile input; record that censored floor without running an empty-domain MLE search or attributing a peer fault. ### Rationale

Each round samples K of the node's D fixed peers afresh, so rounds are independent conditional on the neighbourhood, and epsilon bounds the probability of FINAL or freeze when at most p0 of the node's D peers prefer that side. Binomial(K,p0) is a conservative bound for sampling K of D. The step from neighbourhood to network is not bounded by epsilon: it rests on the stated random-peer-selection assumption and Snowball metastability (votes are preferences, so information spreads beyond D).

FINAL and freeze use exact run-length null thresholds. Each item side spends (epsilon/2)*2^(-(r-2)); the root spends epsilon*2^(-(r-2)). Summing over run lengths and both item sides yields epsilon per prospective item-start round; the root is one-sided and has the same epsilon bound. The unconditional decision-error bound applies per potential start round under the neighbourhood null. Per item (and for the root), the probability of a false FINAL or freeze in an epoch is at most epsilon times the number of rounds polled in that epoch. Every round is counted, including failed first rounds; the success-run lifecycle is unchanged and no conditional calibration is used. This is not merely a description of the observed score and does not bound the neighbourhood-to-network step.

Every counted round must exceed the exact upper median of its Binomial(K,p0) null; the threshold is derived from that null,not a fixed agreement percentage. p0 is the neighbourhood null bound; this does not supply an epsilon-bound on the network fraction.

Votes are preferences shaped by each node's own tallies, so information spreads beyond a node's D peers (Snowball metastability). The step from neighbourhood to network rests on the stated random-peer-selection assumption and Snowball metastability, not an epsilon network-level bound.

Consecutive runs, not cumulative totals: only the recent run reflects the network's current state, and one round is one projection of a correlated neighbourhood. Hence the reset and the 3-round floor.

Preference uses strict sample majority; confidence uses the null upper-median gate followed by exact run-length calibration. These thresholds may coincide for some parameters,but their roles remain separate.

Per-item agreement does not imply set agreement (100 items each missing at a different 10% of peers each show 90% yes, yet few peers hold identical sets). The freeze therefore uses a vote on the cumulative overlay root; REPLY_MATCH carries it implicitly under the captured epoch/prefix context.

non-answers count for neither side, so silence alone cannot produce a success or move a preference; it can delay decisions.

Unanimous rounds carry more evidence than marginal ones. Print the exact threshold representation and rounds-to-FINAL at70%,80% and100% for each declared K; the exact null thresholds, rather than a fixed-score formula, determine the rounds.

## §9 SIMULATOR AND EVALUATION

Rationale: Snowstorm is push-pull gossip. A random-subset POLL carries the poller's cells, letting the responder discover missing items immediately. If decoded, the responder returns the signed difference as plain IDs in REPLY_DIFF; otherwise it returns cells in fallback REPLY. In a successfully decoded nonmatching exchange, cells move into the POLL rather than being added to a cell-bearing reply; fallback exchanges can carry cells in both directions. One exchange therefore disseminates in both directions rather than requiring a later reverse poll. Under uniform regular connectivity each node sends K polls and receives about K polls per round in expectation, so polling itself is push-pull. The intended latency benefit is saving the wait for a reverse poll, described as half a round; actual timing and decode success are measured, not guaranteed. [Karp, Schindelhauer, Shenker and Vöcking, Randomized Rumor Spreading, FOCS2000](https://archive.cone.informatik.uni-freiburg.de/pubs/rumor.pdf) motivates combining directions, not a complete Snowstorm protocol proof.

Cost: POLL cells are sent before the poller knows whether roots match. When sets agree those cell bytes are wasted even though the response can be REPLY_MATCH. Its proof is16 bytes; with version/kind,tip context,epoch number,frozen-prefix root and pollID framing the full application payload is98 bytes, not16 under this grammar. Adaptive sizing shrinks requests as estimated differences shrink, subject to the request floor. Report poll-cell bytes on all exchanges and on matched exchanges separately in NodeStatistics and evaluation, plus REPLY_DIFF ID bytes  and fallback reply-cell bytes.


Body-latency rationale: a decoded ID is not a transaction. Body delivery and host validation precede admission into R; W contains only held nonarchived bodies whose active item preference is IN. Rounds do not wait for fetch completion; the explicit FINAL-in Pending freeze guard applies without an additional hidden timeout.

## §11 LIMITATIONS AND HOST REQUIREMENTS

Snowstorm requires 3<=K<=D. A node that cannot sample at least3 peers does not run Snowstorm and uses ordinary block relay. No calibration or tests below K3 are specified.

Each round samples K of the node's D fixed peers afresh, so rounds are independent conditional on the neighbourhood, and epsilon bounds the probability of FINAL or freeze when at most p0 of the node's D peers prefer that side. Binomial(K,p0) is a conservative bound for sampling K of D. The step from neighbourhood to network is not bounded by epsilon: it rests on the stated random-peer-selection assumption and Snowball metastability (votes are preferences, so information spreads beyond D). The per-potential-start and per-epoch bounds stated in §8 apply only within this neighbourhood scope; per item and for the root, epoch error is at most epsilon times rounds polled, counting every round.

Each node's peers are chosen at random across the network (as outbound peer selection is intended to do), so samples are representative of the network. The sampling assumption excludes partitioned and clique-bridged topologies. Such topologies may freeze different roots; Snowstorm is pseudo-consensus, so this delays block reception and never affects consensus validity. Zero-split acceptance is scoped to topologies meeting this assumption, using random graphs in tests. The clique-bridge limitation fixture reports split outcomes without failing that assertion.

Sybil resistance is not provided by this core. Stake-backed identity is required for a hard beta bound. Network-group diversity (/16,/32 or ASN as defined by the host) and outbound preference are host connection-management requirements; they raise Sybil cost but do not establish beta and do not alter uniform core sampling.

Silent/late/invalid/undecoded observations count for neither side and never reduce the fixed K thresholds. Binomial weights and exact null thresholds use p0=(1+maximumAdversaryFraction)/2 with the neighbourhood scope stated above; they do not supply an epsilon network-level bound. Root-MATCH and item preferences must be evaluated under actual topology, response timing and policy. Report false/split freezes and nonfinishing cases; zero-split is required on assumption-conforming random graphs, while clique-bridge outcomes are reported as a limitation.

Successive epochs allow multiple frozen overlays between blocks; no throughput or liveness guarantee under an unbounded arrival stream is established. Measure this under R10, including per-epoch freeze times, laggard catch-up and the latest frozen overlay exposed to GBT. New active admissions do not invalidate sealed overlays. A genuine frozen-prefix split at the same epoch supplies no item/root evidence across those prefixes and is the existing pseudo-consensus limitation; it is resolved by the next accepted block's ordinary reset, not a new Snowstorm fork-repair rule. Historical replies let a laggard with the matching prefix catch up one frozen epoch at a time. Snap lookup must be performed against old-tip frozen overlays before the host clears them, and a miss falls back to ordinary relay. Root lookup never bypasses consensus validation or creates a new consensus commitment rule.

Candidate-ID keyed XOR proofs do not prove body possession, complete collision-body agreement, identity independence or honest vote intent. A peer holding both candidate sets can supply different valid MATCH proofs to different pollers. Reversible exclusion, new arrivals, response conditioning and decode-conditioned item evidence require measured agreement/false-freeze evaluation. Freezing is the specified root-evidence/run and FINAL-in-Pending condition, with no emitted empty epoch, under the stated identity, sampling and response assumptions; it is not proof of current body possession, agreement, or an unlimited-height error bound.
