Private V2 operator workflow acceptance — 2026-10-15

The reviewed controller at f5a72c4cef12f0f1ec599e40b683f656c2b644d8 passed the native operator gate in 9.512 seconds. It launched two independent foreground controller sessions with separate node/wallet homes, explicit nonzero loopback P2P endpoints and separate Chronik listeners. All functional operations used the unchanged public Controller.execute commands; the gate also recorded bounded, read-only native transaction-status observations to fence asynchronous P2P relay. It used no controller adapters or mocked native behavior.

This is a same-host private acceptance result with Avalanche off. It does not establish separate-machine operation, quorum/finality, production synchronization, release readiness or publication. Avalanche configuration validation is covered by controller tests; this native gate does not demonstrate credential provisioning.

Observed workflow

  • Receiver created and registered bob, exported its public recipient descriptor, and shared that file. Sender imported it as bob-remote; matching descriptor SHA256 was c718a9f914d63ae39e5c8482bbc027b31ffa177453d04a613c9c5262eb29c77e. Import and export recompiled the public key using the pinned Payment compiler.
  • wallet pay alice --to-recipient bob-remote --amount 10000 --fee 1000 submitted the payment without changing the sender tip or creating a sender-side recipient wallet. Receiver independently mined the relayed transaction and discovered a present receipt with value 10000 through its explicit Chronik binding.
  • Both sessions stopped cleanly and resumed their original homes/configuration at generation 2. Sender mined a longer branch while receiver was offline. On reconnection, receiver discovery cleared the detached receipt and sender wallet history reported pending on the competing branch. Sender was offline during the original confirmation, so this trace does not claim an observed sender confirmed → pending transition.
  • Sender explicitly rebroadcast the original persisted transaction; native submission returned duplicate acceptance. Receiver independently mined it again and rediscovered the receipt. No second signing operation occurred.
