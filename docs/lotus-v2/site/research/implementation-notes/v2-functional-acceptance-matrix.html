Exact-source V2 functional acceptance matrix

Prepared 2026-10-15 from native commit 09e36f683003db0cc487fd59ed54622bb1f02195, tree 7006c765d8000c37da5b3bfcdf0811fd672b512a, and monorepo base 6fc3862d. This is a read-only scheduling and coverage audit. It launches no test or node and establishes no new passing result. Production workspaces, chain data, release assets, source and tests are untouched.

The complete machine-readable inventory classifies every registered path and preserves each registered parameter variant, source SHA256, purpose, literal options, skip guards and concrete source lines supporting its fixture/dependency assessment. The registration authority is the pinned test/functional/test_runner.py, whose SHA256 is also recorded.

These 25 paths are included in the JSON, outside the 292-script totals.

What the classifications mean

The 158 inherited regression scripts exercise retained configuration, startup, RPC, network, mempool, wallet and storage behavior. Their use of inherited regtest blocks or transactions does not make them worthless: they are useful regression coverage for the code that still handles those objects. It also does not make their results native V2 chain evidence. Wallet creation/encryption, mempool persistence/reorg, pruning, reindex and block transport remain required regression work even when they are expensive or exercise legacy objects.

The 125 fixture-sensitive scripts check concrete chain rules, activation times, script rules, monetary/address expectations, inherited proof/quorum behavior, or legacy Chronik contracts. This category is a review and attribution gate, not an exclusion list. Run them unchanged against the intended retained legacy regtest mode first. For a failure, retain the precise rejection/expectation and compare the same test with the exact upstream base in a separate controlled build where necessary. A source-justified Lotus fixture correction requires its own review and preserves the original failure evidence. Do not rewrite an assertion just to make a batch green or silently call it unsupported.

Examples of concrete source assumptions retained in the JSON:

  • abc-minimaldata.py tests pre/post-activation MINIMALDATA acceptance; feature_dersig.py expects regtest BIP66 activation at height 1251; feature_tx_version.py distinguishes Wellington rules.
  • chronik_block.py asserts an inherited genesis size of 285 bytes, a 5,000,000,000-satoshi coinbase, reversed protobuf hash bytes and legacy /block behavior. These are unrelated to the native 134-byte header, merkleized identities and /v2/explorer/v1 contract.
  • Inherited abc_*avalanche*, proof, contender, parking and finalization tests use eCash proof/quorum and staking fixtures. Passing them does not establish the native V2 observer's funded quorum, parking or finality semantics.
  • p2p_addrv2_relay.py tests BIP155 address messages; its name does not mean Lotus V2. chronik_token_slp_mint_vault.py tests SLP V2 mint vaults, not native V2 mint selectors. ALP/SLP tests cannot replace native asset event/burn tests.

Every registered source was parsed and inspected for its docstrings, calls, imports, skip guards and literal options. The inventory is not an independent proof of every assertion's semantic suitability. Each result still needs its actual executed chain mode, fixture scope and feature configuration recorded.
