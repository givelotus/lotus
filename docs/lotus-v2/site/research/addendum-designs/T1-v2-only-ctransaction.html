T1 — Transaction versions in Lotus V2: the legacy bridge (primary) and v7-only (alternative)

This is a design only. Nothing here was built, run or committed. Section 0 separates what was read in the source from what is assumed.

The user's final decision is the legacy bridge (Design A):

  • v1/v2 transactions stay valid. They use the legacy format, txid, interpreter and sighash, and they spend and create only legacy coins.
  • A v7 transaction can spend legacy P2PKH and P2SH coins through narrow, native template rules.
  • v7 transactions create only V2 coins.

The earlier direction, v7-only + leaf versions (Design B), is kept as the written alternative. The file name dates from the original brief ("V2-only CTransaction").

Verified in source

Transaction shapes and identities

  • Three shapes decode and get a TxId today (transaction.h:450-463, 466-610):
  • (1) pure v7 wire;
  • (2) "wrapped v7": raw version 0x80000007/0xC0000007, legacy CTxIn/CTxOut bytes, nVersion=7;
  • (3) legacy nVersion 1/2.
  • Shapes 2 and 3 get V2-style identities through implicit mappings, and the version is XORed into byte 0 of the id (transaction.cpp:384-396). The flat fallback digest (400-446) is used when the mapping fails.
  • The eCash tier's TxId equals TxHash, which equals the SHA256d of the legacy serialization (fe649023c3:src/primitives/transaction.cpp:172-178). So a "legacy txid" is well defined and needs no V2 machinery.

Where shapes 2 and 3 are refused or accepted

  • Only RPC refuses shapes 2 and 3: rpc/mempool.cpp:49-59 (bad-txns-non-v7-format, -allowlegacytx, LOTUS_ALLOW_LEGACY_TX).
  • -allowlegacytx is not registered in init.cpp, and no test passes it.
  • P2P, blocks (tx_verify.cpp:58-63 allows 1/2/7) and the in-process CWallet (wallet.cpp:2086-2126, legacy ::SignTransaction) all accept or produce these shapes.

Implicit output and input mappings

  • CTxOut::ToV2Output (transaction.cpp:140-198) maps any legacy scriptPubKey to a V2 output. It tries V2 decode, then OP_RETURN + V2 decode, then falls back to branches={BranchLeaf(script)} (an unversioned V0 leaf, so legacy bytes would run on the renumbered V2 VM).
  • CTxIn::ToV2Input (28-83) turns scriptSig into witness[0].script.

Coins and the V2 state

  • Coin (coins.h:33-55) stores uint32_t nHeightAndIsCoinBase = (height << 1) | coinbase, plus C17a nFeePerOutput/nExpirationHeight. It is serialized as VARINT(nHeightAndIsCoinBase) + TxOutCompression(out) (coins.h:95-104).
  • TxOutCompression (compressor.h:96-121) already has two encodings: a V2 tag and legacy ScriptCompression.
  • The V2 state (sparse Merkle UTXO set, MDBX disk_state, fast sync) already has a legacy coin representation:
  • lotus::v2::Output::legacy_script (lotus_v2/output.h:37);
  • EncodeCoin writes 0x80 || value u64 || CompactSize(len) || script for it (lotus_v2/sparse_state.cpp:107-131);
  • DecodeCoinBytes reads it back (163-173);
  • UtxoLeaf commits it (214-...);
  • lotus_v2/legacy_coin.h converts between it and CTxOut. All of this came from eCash tier f839f1a3b8 and is used by ecash_state_sync_tests/native_state_sync_tests.
  • EncodeOutput refuses legacy outputs: "legacy state output is not a V2 transaction output" (lotus_v2/output.cpp:77).

V2 signing

  • V2 signatures are BIP340 over a 32-byte x-only key. 64 bytes means mode 0; 65 bytes ending in 0x01/0x02 means mode 1/2 (signing.cpp:560-579).
  • SigningMessage(prepared, input, witness, mode) (signing.cpp:459-529):
  • mode 0 = chain_id, txid (witness-free) and coins_root;
  • mode 1 = own-input hash and all outputs;
  • mode 2 = own-input hash and the same-index output.
  • Every message contains the invocation selector (1, input, branch_index, leaf_hash) (384-390).
  • Coins enter coins_root as CoinEntryLeaf(OutputBytes(coin)) (354-358).

1. The two designs side by side

1.1 Design A — legacy bridge (primary, user-decided)

Transaction formats

  • Three formats, each with its own identity. Versions 1 and 2 use the legacy format: legacy TxId = TxHash = SHA256d(serialization), the legacy interpreter and the legacy FORKID sighash. Version 7 uses the V2 format with structural V2 identities.
  • Any other raw version is a decode failure, bad-txns-version.
  • The wrapped form (0x80000007) and the flat fallback ID are deleted.

Coins

  • Every coin carries a legacy-created bit.
  • A v1/v2 transaction may spend only legacy coins and creates only legacy coins.
  • A v7 transaction creates only V2 coins.

v7 spends of legacy coins

  • A v7 transaction may spend a legacy coin only if its scriptPubKey is exactly P2PKH or P2SH:
  • P2PKH: the node checks HASH160(pubkey) natively, then a V2 CHECKSIG (BIP340, V2 message, V2 modes).
  • P2SH: the node checks HASH160(redeem script) natively, then runs the redeem script on the legacy interpreter byte-for-byte. A checker verifies legacy CHECKSIG-family signatures against the V2 message.
  • Every other legacy script is unspendable by v7.

Coinbase

  • A v1/v2 coinbase is allowed only where the per-network consensus parameter allowLegacyCoinbase is true. It is true on regtest and false on mainnet and testnet.
  • The coinbase's version sets its coins' legacy bit, as for any transaction.
  • Mainnet and testnet therefore have no legacy coins. v1/v2 transactions are valid there but can never find a coin to spend, so the bridge is inert outside regtest.
  • See §2.0 for the reasons and for how a coinbase version is selected.

1.2 Design B — v7-only + leaf versions (alternative)

  • Only v7 is valid anywhere.
  • Legacy scripts survive as branch leaves that commit to a leaf version: 0 = V2 VM, 1 = the legacy interpreter with V2-message signatures, 2–255 = unconditional success.
  • There are no legacy coins.
  • Tests build v7 natively. A test-only CTransactionLegacy exists only for upstream interpreter vectors.
  • Section 9 gives its full specification.

The wallet impact is the same in kind for both: any v7 spend signs the V2 message. Only the signature encoding differs. The rule is therefore standardized per template:

  • P2PKH always uses the V2 encoding.
  • P2SH always uses the legacy encoding plus a fixed hashtype→mode map.

2. Design A specification

2.0 Source of legacy coins

The problem. Design A has three rules:

  • legacy transactions spend only legacy coins;
  • v7 creates only V2 coins;
  • nothing migrates backward.

Under those rules a chain whose coinbases are all v7 never contains a legacy coin, so no v1/v2 transaction can ever be valid. The inherited test suite mines a coinbase and spends it with v1/v2 transactions:

  • functional tests use create_coinbase, generatetoaddress, MiniWallet and chained legacy transactions;
  • C++ tests use TestChain100Setup, m_coinbase_txns and CreateValidMempoolTransaction.

That suite is the reason legacy support is kept at all. It must therefore run unchanged, which means it needs legacy coinbases.

2.2 The legacy-created coin bit

In-memory layout and serialization. The field is Coin::nHeightAndIsCoinBase = (height << 2) | (legacy << 1) | coinbase:

  • New accessors: IsLegacy(), plus GetHeight() = >> 2. The constructor gains bool fLegacy.
  • Heights must be < 2^30, which is asserted. That is about 2,000 years at 1-minute blocks.
  • The struct size is unchanged, and spend-time checks read the bit with no extra lookup.

VARINT size cost. VARINT stores 7 bits per byte, so shifting by one more bit adds one byte only where the value crosses a 7-bit group boundary:

  • That happens for heights in roughly [2^5,2^6), [2^12,2^13), [2^19,2^20) and [2^26,2^27).
  • For about 524k–1.05M blocks (roughly 1–2 years) every coin is one byte larger in the LevelDB chainstate and undo files. Outside those bands the size is unchanged.
  • So "zero extra bytes" holds for most heights, not all.

Where the bit is checked:

  • Consistency: the bit must agree with the stored output representation. A legacy coin holds a legacy CTxOut (§2.8) and compresses through ScriptCompression; a V2 coin compresses through the V2 tag. Coin decode fails if they disagree.
  • Undo data: CTxUndo stores Coin, so it carries the bit automatically. Disconnect restores it.

V2 state commitment. No new field is needed:

  • A legacy coin is recorded with lotus::v2::Output::legacy_script and encoded by the existing EncodeCoin 0x80 discriminator (sparse_state.cpp:111-118).
  • So UtxoLeaf, the state root, disk_state (MDBX), fast-sync shards and snapshot transfer already distinguish legacy coins.
  • ConnectBlock/DisconnectBlock must build state coins with LegacyStateOutput(out) for legacy coins (legacy_coin.h:8-14) and with ToV2Output() only for V2 coins.

Expiry and fees. C17a expiry applies identically:

  • fee_per_output for a legacy transaction comes from its fee and its spendable (non-OP_RETURN) outputs.
  • The cleaning crew may sweep expired legacy coins.

Formats and migration. The coin DB format changes, as does the state content of legacy-tx outputs. The placeholder chain resets, -reindex is required, and there is no migration.

2.3 P2PKH bridge (v7 input spending a legacy P2PKH coin)

Witness (the v7 wire is unchanged):

  • nFlags=1, nPathIndex=0, vWitnesses.size()==1.
  • w.script is empty, w.siblings is empty.
  • w.arguments == [sig, pubkey], in exactly this order (the scriptSig push order), as follows:
Argument Contents
sig V2 encoding: 64 bytes (mode 0), or 65 bytes whose last byte is 0x01 or 0x02 (modes 1, 2)
pubkey 33-byte compressed SEC: 0x02/0x03 ‖ x
  • Uncompressed 65-byte keys are not accepted (Q3). Such coins remain spendable by v1/v2.

Check, natively in CScriptCheck with no VM program:

  1. RIPEMD160(SHA256(pubkey)) == scriptPubKey[3..23], else bad-txns-v2-legacy-p2pkh.
  2. msg = SigningMessage(prepared, nIn, 0, mode), with the legacy-coin preparation rules of §2.5.
  3. VerifyBip340Signature(xonly = pubkey[1..33], sig, msg) must be Valid. This goes through BatchSigCollector::Add like any V2 BIP340 signature.
  4. BIP340 x-only keys mean the signer uses d or -d according to the parity of P. This is the standard behaviour of secp256k1_keypair, so wallets sign exactly as for a native V2 key.

Cost: the cost of one V2 CHECKSIG, plus the V2 structural byte cost of the witness, plus a fixed HASH160 charge. The charge is a new VmCostProfile constant, equal to the cost of SHA256 over 33 bytes plus a RIPEMD160 block.

2.4 P2SH bridge (v7 input spending a legacy P2SH coin)

Witness:

  • nFlags=1, nPathIndex=0, vWitnesses.size()==1, no siblings.
  • w.script = the redeem script.
  • w.arguments = the pushes that would precede the redeem script in a legacy scriptSig, bottom of the stack first.

Size limits:

  • Redeem script ≤ MAX_SCRIPT_ELEMENT_SIZE (520), the limit a legacy push would have.
  • Each argument ≤ 520.
  • Argument count ≤ the V2 profile max_arguments.

Check:

  1. RIPEMD160(SHA256(w.script)) == scriptPubKey[2..22], else bad-txns-v2-legacy-p2sh-hash.
  2. Synthesize scriptSig' = MinimalPush(arguments[0]) ‖ … ‖ MinimalPush(arguments[n-1]) ‖ MinimalPush(w.script). Then call the unchanged VerifyScript(scriptSig', coin.scriptPubKey, LEGACY_FLAGS, LegacyBridgeSignatureChecker(...), metrics, &err).
  3. LEGACY_FLAGS is exactly the flag set the V2 node applies to v1/v2 inputs at the same height (GetBlockScriptFlags; Q4 if it changes over time).
  4. This runs the full legacy P2SH evaluation byte-for-byte: hash160 again, redeem-script evaluation, CLEANSTACK, SIGPUSHONLY, and the INPUT_SIGCHECKS density rule against |scriptSig'|.
  5. The only difference from a v1/v2 spend of the same coin is the signature checker.
  6. LegacyBridgeSignatureChecker : BaseSignatureChecker behaves as follows:
Method Behaviour
CheckSig(sig‖t, pubkey, scriptCode, flags) Signature encodings are the legacy ones: ECDSA DER or 64-byte eCash Schnorr, plus the trailing hashtype byte t, with 33/65-byte keys. t must have FORKID and maps to a V2 mode (table below). The message is SigningMessage(prepared, nIn, 0, mode). scriptCode and OP_CODESEPARATOR do not change the message, because the selector commits to the redeem script (§2.5). 0x41 ALL|FORKID 0

Cost:

  • SigChecks from metrics.nSigChecks are charged as V2 CHECKSIG costs and added to the block resource cost. Legacy v1/v2 inputs are charged the same way (§2.6).

Same-result property. For any redeem script, args and flags, the result is identical on both paths whenever no signature opcode reaches a signature check. With signatures, each path's result is the same function of "signature valid for this path's message". The tests in §6 rely on this property.

2.5 V2 signing message for legacy coins

PreparedSigningContext::PrepareChecked (signing.cpp:~250-457) accepts ResolvedCoins whose entries may be legacy (Output::legacy_script). Three things are defined for them.

1. Coin wire.

LegacyCoinWire = 0x80 || value:u64le || CompactSize(|script|) || script
  • This is the same byte string as EncodeCoin's output segment (sparse_state.cpp:111-118).
  • CoinEntryLeaf(LegacyCoinWire) goes into coins_root (mode 0), and OwnInputHashFromCoinWire uses it for modes 1 and 2.
  • OutputBytes keeps refusing legacy outputs for transaction outputs (output.cpp:77). Only the coin-wire path gains the legacy case.

2. Selector leaf. invocation.selector is (1, input_index, branch_index=0, legacy_leaf), where:

legacy_leaf = TaggedHash("Lotus/v2/branch",
                         0x03 || CompactSize(|coin_script|) || coin_script
                              || CompactSize(|w.script|) || w.script)
  • Prefix 0x03 is distinct from leaf 0x00, node 0x01 and Design B's 0x02, so no V2 branch leaf can collide with it.
  • legacy_leaf commits to both the template (P2PKH vs P2SH, and the hash) and the redeem script.
  • A signature for a bridge spend can therefore never verify as a native V2 spend, or as a different redeem script.

3. Membership check. For legacy coins, the V2 branch-membership check (372-382) is replaced by rule A5 and the hash160 check of §2.3/§2.4.

The fast paths are disabled for any transaction that has a legacy-coin input: TxIsAllAutomaticSuccess, InputIsPureMode0Checksig, and the 45-byte batch path at validation.cpp:371.

5. Risks (Design A)

  • R1 Consensus surface. Two grammars, two id schemes and two signature regimes stay forever. Legacy SignatureHash and the interpreter remain consensus-critical for v1/v2 and for P2SH bridge inputs. Mitigation: no new legacy features, and the same-result tests in T1-07.
  • R2 Representation churn and performance. Variant CTxIn/CTxOut change sizeof and the slab slot fit (transaction.cpp:676-... STORAGE_SLOT_SIZES). Benchmark chained_tx, mempool stress and lotus_v2_loopback_tps_stress before and after T1-02. Keep the InitHashes v7 fast path.
  • R3 Regtest-only legacy coins. With allowLegacyCoinbase false on mainnet and testnet, the legacy paths and the bridge are consensus code that production networks never exercise. Their only coverage is the regtest suite, so keep T1-06, T1-07 and T1-13 in the default test run.
  • R4 P2SH bridge = legacy interpreter on v7 inputs. Its DoS profile is the legacy one (sigchecks, opcount), charged to the V2 block cost through sigchecks only. That is acceptable because v1/v2 inputs have the same profile. Re-check if V2 block cost weights are tuned later.
  • R5 Pre-existing BIP68 shortcut (found while reading, not caused by T1).
  • validation.cpp:195-201 and 569-573 return empty lock points for v7 spends, assuming FINAL sequences.
  • The decoder accepts relative-lock sequences, and ConnectBlock's SequenceLocks (3214, 4612) enforces BIP68 for version ≥ 2.
  • The mempool may therefore accept transactions that blocks reject. Report this as a separate fix. Bridge inputs must not widen it: T1-07 tests a CSV redeem script through the bridge in both mempool and block.
  • R6 Pre-existing lock semantics.
  • nLockTime = uint32_t(lock >> 8) truncates the 56-bit V2 lock value.
  • IsFinalTx uses the 500M threshold rather than the V2 lock type.
  • The bridge CheckLockTime (§2.4) uses the type byte. V2-level finality is otherwise unchanged by T1 (Q8).
  • R7 Chronik and wallet ownership overlap with C1 (Chronik) and P1/W1 (wallet). Agree on ownership of chronik_bridge.cpp:447-466 and CWallet before T1-10/T1-11.
  • R8 VARINT size bands. One extra byte per coin at certain heights (§2.2). Negligible, but not zero as first stated.
  • R9 Pre-existing: testnet accepts a null hashStateRoot. validation.cpp:4850-4857 skips the state-root check when the root is null and fPowAllowMinDifficultyBlocks is set. That is regtest and, presumably, testnet. This is not caused by T1; report it separately.

9. Design B — v7-only + leaf versions (alternative, full specification)

Kept so the comparison in §1.3 can be checked.

B1 Rule.

  • Only raw version 7 decodes, so v1/v2 and wrapped forms do not. bad-txns-version is the decode reason.
  • -allowlegacytx, bad-txns-non-v7-format, bad-txns-v2-identity and bad-txns-legacy-state-output are deleted.
  • The legacy VerifyScript path, BIP34 coinbase and BIP30 loop are deleted.
  • CTransaction construction throws on a non-encodable transaction. There is no fallback id.

B2 Leaf hashing.

  • LeafHash(0, s) = TaggedHash(branch, 0x00 || CompactSize || s): today's bytes.
  • LeafHash(v≥1, s) = TaggedHash(branch, 0x02 || v || CompactSize || s).
  • Node prefix 0x01 is unchanged.
  • LEAFHASH opcode 0xbe stays V0.

B3 Reveal.

  • BranchWitness.leaf_version is a byte before script in every spend witness. Mints are V0 and not encoded.
  • TxIds are unchanged, TxHashes change.
  • The alternative is input flags=4 "versioned spend".

B4 Dispatch:

Version Behaviour
V0 V2 VM
V1 EvalLegacyLeaf
V2–255 Success after membership; policy-nonstandard

Fast paths require V0. Effects only from V0.

B5 V1 execution:

  • Initial stack: the arguments; no P2SH layer.
  • Limits:
  • script ≤ min(10,000, max_script_bytes);
  • each argument ≤ 520.
  • Flags: STRICTENC|DERSIG|LOW_S|NULLFAIL|MINIMALDATA|MINIMALIF|CLTV|CSV|FORKID|SCHNORR_MULTISIG|ENFORCE_SIGCHECKS.
  • Clean stack: checked by the caller.
  • OP_CODESEPARATOR: fails.
  • Checker: the legacy sig encoding plus a hashtype map (0x41/0xC1/0xC3 → modes 0/1/2) over SigningMessage. The selector leaf commits to the version.
  • Cost:
  • script bytes × structural cost;
  • a per-opcode base cost;
  • sigchecks × CHECKSIG cost;
  • per-byte hash costs.

B6 Implicit mapping. ToV2Output inference is deleted. Explicit constructors replace it:

  • LegacyLeafOutput (V1), OpTrueOutput, V0LeafOutput, DataOutput, OutputForDestination (→ V1 leaf).
  • The miner fund compares against OutputForDestination.

B7 Types.

  • V2-only CTxIn/CTxOut/CTransaction (static nVersion = 7, single nLock, no scriptSig/scriptPubKey, OutputScript() derived).
  • A test-only CTransactionLegacy in src/test/util, used only for upstream interpreter vectors and never converted.

B8 Wallet.

  • LegacyLeafSignatureCreator; IsMine by branch root (LeafHash(1, script)).
  • PSBT, lotus-tx and BIP37 are removed or ported.

B9 Genesis.

  • Mainnet/testnet: the coinbase output and tx2 become V1-leaf P2PK. Tx2's witness reveals the P2PK script with the message as its argument.
  • Re-mine.
  • Regtest stays byte-identical via an explicit V0 leaf.
