Private V2 explorer coverage, 2026-10-15

This measures existing tests against frontend source from monorepo 39ac976c and native/Chronik source 86201398e3df61605c2eb2d09c201ce774013e7f. Collection uses a fresh monorepo worktree at a6a0f471; its explorer/v2 tree is byte-identical to 39ac976c. A separate native worktree and new build/target directories preserve existing builds, nodes, and data. No application source or test was changed. This baseline predates authority repair cfdc16f435 and the subsequent node C++ changes; their new counter/authority branches are not covered by this collection. Passing tests for those newer changes must be recorded separately, and an updated coverage run needs their final exact source pin.

Evidence and collection helpers retain source/binary hashes, logs, compressed exports, mapped denominators, and uncovered ranges. summary.json is generated by summarize.py. This is execution coverage of selected tests, not path coverage, MC/DC, whole-program coverage, protocol acceptance, or a performance measurement. The native-to-Rust CXX boundary is explicitly unmeasured below.

Frontend

Node 26.10.0, TypeScript 7.0.2, and c8 10.1.3 ran the existing four test files: 18 passed, 0 failed. V8 profiles include the DOM test's app.js?dom-test import and server subprocesses. The first Node coverage display omitted the query-suffixed app URL and lost server profiles when tests killed children. The final c8 report normalizes script URLs, includes every compiled production file, and uses a coverage-only preload to flush V8 before server SIGTERM exit. The preload changes instrumentation teardown, not requests or assertions. Both original and instrumented test logs are retained.

These are generated JavaScript line denominators, without TypeScript source maps. c8 reports no function entries for server.mjs; 0/0 supplies no function-coverage evidence. The server's compressed source puts several conditions on one line, so 100% line coverage does not establish all validation outcomes. V8 branch ranges are not a census of language conditions or independent decision outcomes.

Uncovered frontend behavior includes connect/search form handlers and their errors; branch form invalid-position/root handling and the unspent choice; unknown-route and bad initial configuration rendering; wire continuation validation; and several malformed status/error outcomes. Proxy uncovered ranges include unsupported methods, oversized request bodies/URLs, upstream response overflow, already-aborted/completed requests, and parts of failure cleanup. Exact generated ranges are in frontend/gaps.json; generated JS is retained alongside the exports. The existing DOM test exercises screens with synthetic HTTP fixtures; it does not establish browser compatibility or native chain acceptance.

Native producer

A fresh standalone CMake/Ninja build ran 2/2 tests successfully: chronik_sync_test and chronik_explorer_test. LLVM 23.1.2 compiled at -O0 -g -fprofile-instr-generate -fcoverage-mapping, with build concurrency -j2. The initial build encountered Boost/libc++ pragma-clang-attribute diagnostics promoted by the suite's -Werror; the successful build adds only -Wno-error=pragma-clang-attribute. Both build logs are retained. There were no coverage-export warnings.

Only chronik_explorer.cpp/.h and chronik_sync.cpp/.h enter this producer denominator. Runtime, codec, database, test, and vendor sources linked into these test binaries are excluded from the reported scope.

Mapped functions are 10/10; mapped regions are 196/232 (84.48%). MC/DC was not instrumented. These suites use the actual native runtime/storage/codec and a recording Chronik sink. They do not compile LOTUS_V2_CHRONIK_CXX, so bridge conversion, Rust sink calls and node publication wiring have no measured coverage, and are absent from this mapped denominator.

The synchronization suite does not execute unavailable-state guard outcomes for zero limits, missing runtime authority, reopen, paused execution or pending recovery journal/receipt/propagation (chronik_sync.cpp:90–95). Other gaps include corrupt checkpoint/genesis/active-child/header lookups and connected-body conversion failures. Many frame-size, output-encoding and cursor-advance checks in the producer remain unexecuted on their error sides. Some are defensive checks after authenticated native decoding/encoding; the report does not infer that each is independently reachable. summary.json lists each uncovered native branch outcome with source position and counts.

Rust explorer API and storage

Rust 1.93.0 already had LLVM tools installed, so direct -C instrument-coverage collection was available without installing cargo-llvm-cov. A new Cargo target directory ran cargo +1.93.0 test --locked -j2 -p chronik-db -p chronik-http -p chronik-indexer -p chronik_lib v2 -- --nocapture, with Python 3.13.16 selected for PyO3. 61 tests passed: DB 23, HTTP 18, query/indexer 14, service 6. These are the existing filtered V2 suites, not every crate test.

The explicit source inventory contains eight production files. Seven have coverage mappings; chronik-lib/src/v2_ffi.rs is unmapped and unmeasured, not counted as covered or silently represented as zero lines. The HTTP file's inline test module at lines 1199–1314 is excluded from the production summary; production request validators after that module remain included. Other selected files put tests in separate modules. Raw exports retain the original mappings and inline tests; summarize.py applies the documented production exclusion to LCOV line/function entries.

Stable Rust coverage provides no branch records in this run, so Rust branch coverage and MC/DC are unmeasured. This does not prove the error side of a conditional ran just because its line ran.

LLVM reports four mismatched mappings in nom::traits::Compare::compare, outside the selected source inventory. The retained dump identifies all four; no selected explorer function is identified by that warning. The export completed successfully. Profiles from the fresh run include instrumented Cargo build processes; reports select only the four test executables and the explicit production files.

Uncovered Rust lines include DB record bounds, invalid input flags/coinbase ranges, frozen spend/witness-table checks, parent/location/empty-frame/duplicate-identity checks and corruption handling. Query gaps include the concrete ReadSnapshot explorer/asset adapter methods, several missing-record and continuation cases, and branch posting-order/record corruption. HTTP gaps include cursor errors, record/request/response limits, unavailable/continuation handling and route-specific results. Service gaps include input/transaction/full-fact/block/response capacity guards; server gaps include poisoned authority lock, numeric-bind bounds and shutdown timeout. These are line observations; Rust decision coverage was not measured. Exact uncovered lines are retained in summary.json.

Reproduction and remaining evidence

commands.json records actual commands, environment selections, source pins and artifact paths. export.py re-exports the four Rust test binaries from the isolated instrumented build; summarize.py regenerates the scoped summary from retained exports. frontend/coverage-summary.json, frontend/coverage-final.json.gz, frontend/lcov.info, native/coverage.json, and rust/coverage.lcov supply the denominators. Native and Rust raw profiles/builds remain in the recorded temporary directories; compressed merged profiles and exports are retained for audit.

Actual daemon/Chronik/browser funding, transaction, token, reorg and restart acceptance must be evaluated from its own live evidence. This collection launches no native node and establishes no CXX boundary coverage, browser-engine matrix, adversarial path completeness, race completeness, fuzzing coverage, performance result or release readiness.
