Implementation Plan: Unified Boost.Beast HTTP/WebSocket Server, /chronik/* Single-Port Delegation, and /p2p/ws Encrypted/Compressed P2P Transport

Target Baseline: Existing eCash bitcoind (daemon/patches/ecash/, layered right after ecash/054 before the v2/ patch stack, so both eCash bitcoind and Lotus V2 inherit it cleanly).

Architectural Overview

  1. Replace libevent (evhttp) in src/httpserver.cpp with Boost.Beast (<boost/beast/http.hpp>, <boost/beast/websocket.hpp>, <boost/beast/ssl.hpp>) running on the existing Boost.Asio C++20 co_await coroutine pool (HTTPCoroutinePool), while keeping the public HTTPRequest, RegisterHTTPHandler, RegisterHTTPAsyncHandler, and HTTPEvent signatures in src/httpserver.h 100% source-compatible so zero existing RPC/REST handlers (src/httprpc.cpp, src/rest.cpp) break.
  2. Auto-Detect TLS vs. Plain HTTP/WS on the Same Port (boost::beast::async_detect_ssl):
  3. Each bound RPC/HTTP port (-rpcport, default 8332 in eCash / 10604 in Lotus V2) peeks at the first bytes of each incoming TCP connection via boost::beast::async_detect_ssl.
  4. If the client sends a TLS ClientHello (https:// or wss://), the connection is wrapped in boost::beast::ssl_stream using either -tlscert / -tlskey or an auto-generated in-memory ECDSA P-256 self-signed certificate (-tlsephemeral=1, default enabled).
  5. If the client sends plain ASCII (http:// or ws://, e.g., localhost or behind a TLS-terminating Kubernetes Ingress / Cloudflare / Alchemy Load Balancer), it runs directly over boost::beast::tcp_stream.
  6. Optional permissive mTLS (-tlsmutual=1): sets boost::asio::ssl::verify_peer (without verify_fail_if_no_peer_cert on the port, enforcing peer cert presence or v2hello signature specifically on /p2p/ws).
  7. Delegate /chronik/* (HTTP + /chronik/ws WebSocket) on the Main RPC Port to Chronik (hyper/axum):
  8. Chronik keeps its existing secondary port (-chronikbind, default 127.0.0.1:8321), AND src/httpserver.cpp registers a built-in prefix route /chronik (exempt from -rpcuser/-rpcpassword basic auth, configurable via -chronikpubliconrpcport=1, default 1 when -chronik=1).
  9. Regular HTTP requests to /chronik/<subpath> strip the /chronik prefix and asynchronously proxy over a pooled loopback boost::asio::ip::tcp::socket to Chronik's bound SocketAddr (127.0.0.1:8321).
  10. WebSocket upgrade requests to /chronik/ws upgrade the client via boost::beast::websocket::stream (or raw TCP splice after 101 Switching Protocols) and bidirectionally pump frames between the client socket and 127.0.0.1:8321/ws.
  11. When built with -DBUILD_CHRONIK=OFF or run with -chronik=0, /chronik/* simply returns 404 Not Found with zero compile-time dependency on Rust/Chronik.
  12. Additive P2P over WebSockets on /p2p/ws with Streaming zstd + Prebaked Dictionary (p2p-zstd-v1) Alongside Existing Raw TCP P2P:
  13. Normal TCP P2P (-port=8333, CConnman::ListenSocket, CConnman::AcceptConnection, CConnman::ConnectNode("ip:port")) remains 100% intact, unmodified, and enabled by default. A single node simultaneously accepts legacy raw TCP peers on port 8333 and WebSocket peers on /p2p/ws, relaying blocks and transactions seamlessly across both transports.
  14. Inbound requests to GET /p2p/ws with Upgrade: websocket on the HTTP port negotiate streaming libzstd compression with a prebaked P2P/Script dictionary (Sec-WebSocket-Protocol: p2p-zstd-v1) (with automatic fallback to raw streaming p2p-zstd or RFC 7692 permessage-deflate for generic WebSocket clients) and hand the upgraded connection to CConnman via a local socketpair(AF_UNIX, SOCK_STREAM, 0) bridge.
  15. Using ZSTD_CCtx_refCDict + ZSTD_compressStream2(..., ZSTD_e_flush) on a persistent per-peer ZSTD_CCtx gives immediate high compression on the very first small packet (via the prebaked dictionary of P2P headers, inv/ava prefixes, P2PKH/P2SH/CashToken/Lotus V2 TMPL_SCRIPT templates, and sequence/version boilerplate) and maintains a live 128 KB sliding window across consecutive P2P messages at 500+ MB/s (< 3 us latency per message).
  16. Every Bitcoin/Lotus P2P message flows through the existing 24-byte CMessageHeader || payload wire format inside binary WebSocket frames (ws.binary(true)), so V1TransportDeserializer, V1TransportSerializer, CNode, and src/net_processing.cpp require zero modifications.
  17. Outbound peers use normal raw TCP when given "ip:port" or "host:port", and use the WebSocket dialer when prefixed with ws:// or wss:// (-addnode=wss://node.example.com:443/p2p/ws or -connect=ws://...), setting TLS SNI (SSL_set_tlsext_host_name) and the HTTP Host: header so standard Kubernetes Ingresses, Cloudflare tunnels, and L7 load balancers route P2P traffic identically to normal web traffic.

5-Commit Atomic Implementation Sequence

Implement this as 4 sequential, self-contained commits on top of the eCash bitcoind tree (daemon/patches/ecash/), plus a 5th commit in daemon/patches/v2/ for Lotus V2. Every commit must compile cleanly (ninja bitcoind test_bitcoin) and pass test_bitcoin and httpserver_tests.
