Snowstorm: Multi-Peer Rateless $\text{GF}(2^{64})$ BCH Fountain Pseudo-Consensus

Status: implemented & verified in lotusd (src/net/v2_protocol_handler.*, src/lotus_v2/mempool_overlay.*, src/avalanche/processor.*, src/txmempool.*).

1. Executive Summary & Pseudo-Consensus Philosophy

Core Insight — The Union Needs No Agreement; Only the Cut Does: Set union is commutative, associative, and idempotent (a grow-only CRDT), so reconciling the interior of an epoch requires no symmetry breaking or voting—every node agrees that learning missing valid transactions is progress, and Snowstorm's symmetric transitive conflict quarantine $F(A \cup B) = F(B \cup A)$ makes even double-spend removal a commutative join-homomorphism. Where consensus (and FLP) enters is closing the finite epoch cut so every node derives the exact same 256-bit SubtreeARoot and UtxoRoot for 0-RTT SnapBlock assembly. Snowstorm uses repeated sampling of 913-byte rateless $\text{GF}(2^{64})$ BCH miniblocks to shrink the agreement problem from all $N$ transactions in the epoch down to the thin boundary of late arrivals near the cut—resolving the interior by algebraic union while using cohort support from the decoded sketches and a unified Hypergeometric SPRT to snap all nodes onto the same boundary cut.

In Practice

  • Zero-Wait Block Propagation: Instead of waiting until a block is mined to discover which transactions are inside it, Snowstorm lets nodes continuously stream lightweight mathematical "fountain" sketches to each other beforehand so everyone's mempool crystallizes into the exact same set of transactions before the block is found.
  • Header + Coinbase Instant Blocks (SnapBlock): When a miner finds a block, they don't need to broadcast megabytes of transactions—just a compact SealedHeader (SnapBlock) frame (134-byte native V2 block header + serialized coinbase_tx, or 240 bytes on legacy 84B-header + 156B-coinbase benchmark frames; 238 bytes for a 134B V2 header + 103B 1-output coinbase). Nodes snap the block into place in 0.089 milliseconds (88.6 µs) with 0 post-block RTTs—14× faster in post-block CPU than Merklix-Snowball (1.25 ms) and 2,905× faster in total WAN propagation than post-block recovery (257.39 ms).
  • Pseudo-Consensus (Optional, Never Splits the Chain): No node or miner is forced to use Snowstorm. Block validity is still 100% decided by Proof-of-Work and Lotus V2's deterministic consensus rules (C01–C28). If a miner mines a custom block without Snowstorm, or a node turns Snowstorm off, the network never forks—nodes simply fall back to standard compact/full block download (and any local PreConsensusPolicy parking of blocks that conflict with finalized batches is a temporary tip-selection policy, never a permanent validity rule). Yet participating is overwhelmingly beneficial because Snowstorm blocks propagate in 0 RTTs with near-zero orphan risk.

Under the Hood

  • Multi-Peer Rateless $\text{GF}(2^{64})$ BCH Fountain Codes: Interactive prefix-tree reconciliation (Merklix-Snowball, our earlier prototype combining Merklix prefix trees [2] with Snowball peer sampling [14]) requires interactive top-down traversal (5 RTTs, 118.5 B / missing tx), fixed-capacity algebraic sketches (PinSketch [5, 6], IBLT [9], Graphene [11], Erlay/Minisketch [12]) suffer a catastrophic "decoding cliff" when symmetric difference $|\Delta|$ exceeds table capacity, pairwise Rateless IBLTs [16] map coded symbols with decreasing density but peel singletons only (count == 1, strictly pairwise) without multi-peer coupling or algebraic cell fraud proofs, and block-byte fountain codes (LT [7], Raptor [8], Velocity [13]) only work on a single static byte array from one miner. Snowstorm combines rateless multi-peer fountain streaming with $\text{GF}(2^{64})$ degree-3 BCH algebraic power sums $(S_1, S_3, S_5)$ over $\mathbb{F}_2[x]/(x^{64}+x^4+x^3+x+1)$.
  • ~30% Overhead & Cross-Peer Coupled Peeling ($d \le 2$ Solver + 64-Bit $S_5$ Integrity Tag): Every RatelessMiniblock carries a 32 × 28 = 896 B BCH cell array (913 B in compact stream mode with a 17 B per-miniblock header, or 1,018 B standalone with the full 122 B self-describing scope/root header) that partitions a peer's epoch into 32 cells using SplitMix64(short_id ^ seed) with geometric decimation $1/2^L$. Because each cell resolves up to $d = 2$ items algebraically with an independent 64-bit $S_5$ integrity check (and $d = 3$ strictly for raw wire cell validation), a receiver collects miniblocks concurrently from $K_t$ sampled peers, subtracts its local mempool, and runs coupled degree-2 BCH root solving plus donor-isolated cross-peer projection across all divergent peers simultaneously—achieving 2 RTTs (2.5× fewer RTTs) and 34.97 B / missing tx (20,980 B total reconciliation wire payload = 18 × 896 B cells + 4,852 B GETSHORTTX, 3.39× lower bandwidth, 0.92 cells / item, which is below 1 cell/item and represents ~30% cell overhead above the $0.71\text{ cell/item}$ multi-root BCH peeling threshold) with zero interactive tree descent.
  • $O(1)$ Algebraic Fraud Proofs Keyed on (peer_id, candidate_root): Four mathematical invariants—Type 1 single-cell degree-3 BCH self-consistency (count in {0..3}), Type 2 $L=0$ 32-cell partition conservation, Type 3 generalized cell capacity conservation ($\text{peeled\_missing}_c \le \text{raw\_count}_c$), and exhausted-cell local-extra elimination (scoped per (peer_id, candidate_root) with bounded root rotations)—allow any node to prove in $O(1)$ that a Byzantine peer sent a poisoned miniblock, shun the peer, and purge its state without falsely penalizing honest mid-stream epoch updates.

2. Why Snowstorm is Pseudo-Consensus

A foundational architectural principle of Lotus V2 is the strict boundary between Hard Consensus Validity and Snowstorm Pseudo-Consensus Coordination.

2.1 Hard Consensus Invariance (consensus.md C01–C28)

Hard consensus validity is a pure, deterministic state-transition function of a block's bytes and its parent state commitment:

  1. Valid Proof-of-Work (BlockID <= Target) under P04's two-stage BLAKE3 header specification (134-byte native V2 header with 18-byte nonce field nonce1:u64 || nonce2:u64 || extra_work:u16).
  2. Valid transaction encodings, two-phase outputs-then-inputs CTOR UTXO resolution (C12), multi-branch MAST scripts, deferred ENFORCEOUTPUT / HAS_STATE checks (C12a), BIP340 Schnorr signatures, bounded VM cost (cu), and token conservation (C01–C24).
  3. Exact match of Header.tx_root (H_txroot(0x03 || CoinbaseLeaf || SubtreeA)) and Header.state_root (H_state(0x00 || ChainID || u64(height) || UtxoRoot || Bytes(MonetaryState)), where Bytes(MonetaryState) is 56 bytes at genesis $h=0$ and 88 bytes including the 32-byte history_root at $h \ge 1$ per C03 and P02).

[!IMPORTANT] Consensus Non-Interference Guarantee:

  • A block that satisfies C01–C28 is consensus-valid whether or not its transactions passed through Snowstorm.
  • A block that violates any rule in C01–C28 is consensus-invalid even if 100% of Snowstorm peers voted for its epoch batch.
  • Every transaction recovered via Snowstorm undergoes full MemPoolAccept (ProcessTransaction) signature, UTXO, and VM validation before it can enter a node's working epoch layer (W_e), and every epoch root must pass the Strict 256-Bit Root-Verification Gate (recomputed_root_32B == peer_root_32B).

2.4 System, Network, and Adversary Model

  • Network Model: Nodes communicate over a P2P overlay subject to partial synchrony; during synchronous intervals, messages between honest peers arrive within bounded delay $\Delta_{\text{net}}$.
  • Cryptographic & Field Assumptions: 256-bit BLAKE3 (TaggedHash) is modeled as a collision-resistant / random-oracle hash function, and per-epoch SipHash-2-4(k0, k1, TxId || TxHash) is modeled as a pseudorandom function whose key $(k_0, k_1) = H(\texttt{"SNOWSTORM\_EPOCH\_ID"},\, P.\text{block\_hash} \parallel P.\text{batch\_id})$ is unpredictable prior to Proof-of-Work discovery of parent block $P$ [17].
  • Adversary Budget: We separate the two protocol layers explicitly:
  • Assumption A1 (Bonded Stake-Weighted Finality, $f_{\text{stake}} < 1/3$): At most $f_{\text{stake}} < 1/3$ of bonded PoW-UTXO stake weight (consensus.md, enforced cryptographically via ProofId UTXO ownership proofs) in the Avalanche MSG_AVA_MEMPOOL_BATCH quorum is Byzantine.
  • Assumption A2 (Unweighted P2P Sample Bound, $f_{\text{peer}} < 1/4$): At most $f_{\text{peer}} < 1/4$ of entries in an honest node's AS/subnet-diversified P2P peer table (peering.md) are Byzantine. Crucially, consensus safety never depends on A2: if a node is eclipsed on P2P ($f_{\text{peer}} \ge 1/4$), it at worst experiences a SnapBlock cache miss and falls back to Stage 2 (cmpctblock) or adopts the stake-certified batch under Assumption A1.

4. Mathematical & Wire Specification of RatelessMiniblock

4.1 Finite Field $\text{GF}(2^{64})$ and Odd Power-Sum Syndromes

All syndrome arithmetic operates in the characteristic-2 extension field: $$\text{GF}(2^{64}) = \mathbb{F}_2[x] \big/ (x^{64} + x^4 + x^3 + x + 1)$$ with primitive irreducible pentanomial modulus 0x1B ($x^4 + x^3 + x + 1$). Multiplication in $\text{GF}(2^{64})$ is accelerated via hardware carry-less multiplication (_mm_clmulepi64_si128 on x86_64 and vmull_p64 on ARM64 NEON), achieving 745.6M tx/sec syndrome accumulation and 41.34M roots/sec BCH decoding.

For any non-zero 64-bit transaction short identifier $x \in \text{GF}(2^{64})^\times$ (computed via per-epoch keyed SipHash-2-4(k0, k1, TxId || TxHash) and deduplicated per set), its contribution to a cell is: $$\text{count} \mathrel{+}= 1, \qquad S_1 \mathrel{\oplus}= x, \qquad S_3 \mathrel{\oplus}= x^3, \qquad S_5 \mathrel{\oplus}= x^5$$

[!NOTE] Why Key $x$ Over (TxId, TxHash) + Same-TxId Witness Conflict Quarantine? Under C07, SubtreeA is keyed by TxId, and each leaf TxLeaf(tx) = H_txroot(0x01 || TxId || TxHash) commits to both TxId and TxHash. If $x$ were derived from TxId alone, an attacker could sign the same transaction twice with fresh BIP340 randomness ($w_1 \neq w_2$, yielding $\text{TxId}_1 = \text{TxId}_2$ and $\text{TxHash}_1 \neq \text{TxHash}_2$) and send one variant to each half of the network: the two variants would map to the same $x$ and cancel in the sketch while producing different SubtreeA roots! Keying $x = \text{SipHash-2-4}(k_0, k_1, \text{TxId} \parallel \text{TxHash})$ ensures both variants appear in the decoded symmetric difference. Because two witness variants of the same TxId spend the exact same inputs, receiving a second valid witness variant for an unsealed TxId already in active_epoch treats the pair as a same-input conflict class and routes both into the order-independent conflict quarantine (quarantined_txs_, retaining the variant with $\min_j \text{TxHash}_j$ with no replacement cap) for promotion into Epoch $E+1$. If two peers still exhibit $R_A \neq R_B$ with an all-zero $L=0$ sketch residual (e.g., due to a $2^{32}$ birthday collision in $\text{GF}(2^{64})^\times$), reconciliation falls back to a 1-RTT depth-2 Merklix bucket digest comparison (getmerklixbuck, $256 \times 32\text{ B} = 8\text{ KiB}$) or an interactive $O(\log_{16} N)$ branch walk ($2\text{--}4\text{ RTTs}$).

Why Only Odd Power Sums $(S_1, S_3, S_5)$? In characteristic 2 ($\mathbb{F}_2$), Freshman's Dream $(a \oplus b)^2 = a^2 \oplus b^2$ implies that all even power sums are redundant squares of earlier power sums: $$S_2 = \bigoplus_i x_i^2 = \left(\bigoplus_i x_i\right)^2 = S_1^2, \qquad S_4 = S_1^4, \qquad S_6 = S_3^2$$ Thus the three 64-bit odd power sums $(S_1, S_3, S_5)$ provide all 6 consecutive BCH syndromes $(S_1, S_2, S_3, S_4, S_5, S_6)$ required to solve up to $t = 3$ unknown errors over $\text{GF}(2^{64})$ in just $24\text{ bytes}$.

4.2 Wire Format (RatelessMiniblock & Size Accounting)

Each RatelessMiniblock contains NUM_CELLS = 32 algebraic BCH cells (28 bytes per cell = 896 bytes cell array). Depending on whether the 112-byte epoch/root context (context_id[32] + parent_base_root[32] + candidate_root[32] + salt_k0[8] + salt_k1[8] = 112 B, or 96 B excluding the two 8-byte session salts) is carried per frame or amortized across an epoch session stream, the wire sizes are:

  • Cell Payload (32 × 28 B): 896 bytes (cells[0..31]).
  • Compact Session-Stream Miniblock (17 B stream header + 896 B cells): 913 bytes (scope[1] + context_short_id[8] + total_tx_count[4] + miniblock_id[3] + decimation_level[1] + cells[896], where context_short_id binds (context_id, candidate_root) for the active session stream).
  • Standalone Self-Describing RatelessMiniblock (122 B full header + 896 B cells): 1,018 bytes (src/net/v2_protocol_handler.h:337-360).
  • Canonical Scope Salt Verification (salt_k0, salt_k1): In PRECONSENSUS_EPOCH scope (0x01), (salt_k0, salt_k1) is deterministically derived from context_id = H("SNOWSTORM_EPOCH_ID", P.block_hash || P.batch_id) (salt_k0 = LE64(context_id[0..7]), salt_k1 = LE64(context_id[8..15])). RatelessMiniblockDecoder::AddPeerMiniblock strictly rejects any incoming miniblock whose wire (salt_k0, salt_k1) does not equal the scope's derived (m_salt_k0, m_salt_k1) (src/net/v2_protocol_handler.cpp:2109), preventing any sender from choosing or grinding the SipHash salt.
  • Why 0.92 cells / item Is Below 1 Cell/Item (~30% Overhead Above the $0.71\text{ cell/item}$ Threshold): Because each 28-byte degree-2 BCH cell resolves up to $d = 2$ items simultaneously while retaining a 64-bit $S_5$ integrity check, the algebraic capacity ceiling is $0.50\text{ cells/item}$ (14 B/item). Under random Poisson cell occupancy across geometric decimation levels $2^{-L}$, the empirical $d \le 2$ peeling threshold is $\approx 0.71\text{ cells/item}$ ($443$ cells for $625$ items, compared to $> 1.35\text{ cells/item}$ for degree-1 IBLT/RIBLT), so $18 \times 32 = 576\text{ cells}$ for $625$ difference items equals 0.92 cells / item ($\approx 30\%$ cell overhead above $0.71\text{ cells/item}$).
MerklixSubBucketEntry / RatelessSketchCell (28 bytes):
  count : i32_le        # Signed 32-bit element count (non-negative in raw wire cells; signed delta_count after subtraction)
  s1    : u64_le        # XOR sum of x        in GF(2^64)
  s3    : u64_le        # XOR sum of x^3      in GF(2^64)
  s5    : u64_le        # XOR sum of x^5      in GF(2^64)

  context_id       : h256                      # 32 B: Epoch / context identifier

  candidate_root   : h256                      # 32 B: Sender's active epoch SubtreeA root

  salt_k1          : u64_le                    # 8 B:  SipHash key k1
  total_tx_count   : u32_le                    # 4 B:  Sender's total distinct short_id count in this scope
  miniblock_id     : u32_le                    # 4 B:  Monotonic fountain stream index (0, 1, 2, ...)
  decimation_level : u8                        # 1 B:  Multi-scale sampling exponent L in [0..12] (rate = 1 / 2^L)
  cells            : RatelessSketchCell[32]    # 896 B: 32 algebraic BCH cells (32 * 28 bytes)

4.3 Deterministic SplitMix64 Cell Mapping & Multi-Scale Geometric Decimation

Given (short_id, miniblock_id, decimation_level L) with $L \in [0, 12]$:

  1. Compute the per-miniblock 64-bit mix input: $$z = \text{short\_id} \oplus (\text{miniblock\_id} \times \texttt{0x9E3779B97F4A7C15}_{64}) \oplus (\text{decimation\_level} \times \texttt{0xBF58476D1CE4E5B9}_{64})$$
  2. Apply the bijective SplitMix64 finalizer: $$h = \text{SplitMix64}(z)$$
  3. Decimation Gate ($L > 0$): If $L > 0$: let $\text{mask} = (1 \ll L) - 1$. If $\big((h \gg 8) \ \& \ \text{mask}\big) \neq 0$, the element is not sampled in this miniblock (returns std::nullopt).
  4. Cell Assignment ($0..31$): Otherwise, the element maps to cell: $$c = h \ \& \ \texttt{0x1F} \quad \in \{0, 1, \dots, 31\}$$

Because step 3 inspects bits 8 .. 8+L-1 and step 4 inspects bits 0 .. 4, the decimation filter and the 32-way cell partition are orthogonal. At $L = 0$, every element in the set maps to exactly one of the 32 cells.

Multi-Scale Geometric Schedule (SelectRatelessDecimationLevel): When an estimated difference $|\hat{\Delta}| > 64$, the sender interleaves higher decimation levels $L_{\max} \to \dots \to 1 \to 0$ so that early miniblocks isolate sparse singletons/pairs even when $|\Delta|$ is thousands of transactions, while $L = 0$ miniblocks guarantee 100% coverage of the tail without coupon-collector gaps.

5. Multi-Peer Coupled BCH Peeling & The Six Formal Theorems

When a node holds local transaction set $M_{\text{local}}$ and receives RatelessMiniblock frames from $K$ peers (where Peer $p$ holds transaction set $M_p$), the decoder subtracts $M_{\text{local}}$ and runs an iterative coupled peeling solver across all stored miniblocks.

Theorem 1 (Degree-3 BCH Elementary Symmetric Polynomial Reduction in $\text{GF}(2^{64})$)

Let $X = \{x_1, \dots, x_d\} \subset \text{GF}(2^{64})^\times$ ($1 \le d \le 3$) be a set of distinct non-zero elements with odd power sums $S_k = \bigoplus_{i=1}^d x_i^k$, and let $\sigma_1, \sigma_2, \sigma_3$ be the elementary symmetric polynomials of $X$ such that $\Lambda(z) = z^d \oplus \sigma_1 z^{d-1} \oplus \dots \oplus \sigma_d = \prod_{i=1}^d (z \oplus x_i) = 0$. Using Newton's identities in characteristic 2 ($S_2 = S_1^2,\ S_4 = S_1^4$): $$\begin{aligned} S_1 &= \sigma_1 \\ S_3 &= \sigma_1 S_2 \oplus \sigma_2 S_1 \oplus \sigma_3 = S_1^3 \oplus S_1 \sigma_2 \oplus \sigma_3 \\ S_5 &= \sigma_1 S_4 \oplus \sigma_2 S_3 \oplus \sigma_3 S_2 = S_1^5 \oplus \sigma_2 S_3 \oplus S_1^2 \sigma_3 \end{aligned}$$ Define $d_1 := S_3 \oplus S_1^3 = S_1 \sigma_2 \oplus \sigma_3$. Then:

  1. Single Root ($d = 1$): $\sigma_2 = \sigma_3 = 0 \iff d_1 = 0 \land S_5 = S_1^5$, with unique root $x_1 = S_1$.
  2. Two Distinct Roots ($d = 2$): $\sigma_3 = 0 \iff d_1 = S_1 \sigma_2 \neq 0$, giving: $$\sigma_1 = S_1, \qquad \sigma_2 = \frac{d_1}{S_1}, \qquad \text{subject to the 64-bit BCH check } S_5 = S_1^5 \oplus \sigma_2 S_3 = S_1^5 \oplus S_1^3 \sigma_2 \oplus S_1 \sigma_2^2 = x_1^5 \oplus x_2^5$$
  3. Three Distinct Roots ($d = 3$): Substituting $\sigma_3 = d_1 \oplus S_1 \sigma_2$ into $S_5 = S_1^5 \oplus \sigma_2 S_3 \oplus S_1^2 \sigma_3$ gives $S_5 \oplus S_1^5 \oplus S_1^2 d_1 = S_5 \oplus S_1^2 S_3 = d_1 \sigma_2$, yielding (RecoverGF64SyndromesUpTo3): $$\sigma_1 = S_1, \qquad \sigma_2 = \frac{S_5 \oplus S_1^2 S_3}{d_1} = \frac{S_5 \oplus S_1^5 \oplus S_1^2 d_1}{d_1}, \qquad \sigma_3 = d_1 \oplus S_1 \sigma_2$$

Theorem 2 ($2^{-64}$ Cross-Peer Projection & Signed-Difference Classification Soundness)

Suppose a residual cell $(m, c)$ of Peer $p$ has signed count $\Delta c = |U^+| - |U^-|$, where $U^+ \subset M_p \setminus M_{\text{local}}$ are unpeeled peer-missing items and $U^- \subset M_{\text{local}} \setminus M_p$ are unpeeled local-extra items. In characteristic 2, XOR syndromes do not carry sign bits, so TryResolveCell and TryCrossPeerProjectCell enforce two strict gates before classifying any recovered roots $\{r_1, \dots, r_d\}$ ($d = |\Delta c| \in \{1, 2\}$):

  1. Sign-Membership Partition Gate:
  2. When $\Delta c > 0$ ($\Delta c \in \{1, 2\}$): every root $r_i$ must satisfy $r_i \notin M_{\text{local}}$ (!m_local_short_ids.contains(r_i)) and pass HasZeroCellVetoForPeer(peer_id, r_i) == false.
  3. When $\Delta c < 0$ ($\Delta c \in \{-1, -2\}$): every root $r_i$ must satisfy $r_i \in M_{\text{local}}$ (m_local_short_ids.contains(r_i)).
  4. If any root violates the sign-membership partition or cell assignment MapShortIdToMiniblockCell(r_i, m, L) == c, the entire candidate resolution is rejected (all_valid = false).
  5. $\ge 64$-Bit Algebraic Redundancy Gate ($d \le 2$) & Adversarial Chosen-Syndrome Containment:
  6. Random Mixed-Sign Residual Collisions ($< 2^{-74}$): Over uniform SipHash-2-4(k0, k1, TxId) short IDs and independent SplitMix64 cell/decimation bit slices:
  7. For $d = 0$ (proj.IsZero()), all three 64-bit syndromes $(S_1, S_3, S_5)$ and delta_count must vanish simultaneously ($2^{-192}$ false-positive probability).
  8. For $d = 1$, $S_3 = S_1^3$ and $S_5 = S_1^5$ provide 128 bits of algebraic redundancy plus $5 + L$ bits of cell-mapping verification ($< 2^{-133}$ false-positive probability, preventing a mixed $2\text{-positive}, 1\text{-negative}$ residual $x_1 \oplus x_2 \oplus y_1$ with $\Delta c = +1$ from masquerading as a single root).
  9. For $d = 2$, $\sigma_2 = d_1 / S_1$ uses only $(S_1, S_3)$, leaving $S_5 = S_1^5 \oplus \sigma_2 S_3 = x_1^5 \oplus x_2^5$ as a completely independent 64-bit algebraic check. Specifically, for any non-solvable residual cell with $k = |U^+| + |U^-| \ge 3$ unpeeled items in the cell pre-image $\mathcal{C}_{m,L,c}$ ($|\mathcal{C}_{m,L,c}| = 2^{59-L}$):
  10. Zero False Positives at $k = 3$: False acceptance has probability zero when $k = 3$, because the degree-$2$ check polynomial factors identically as $z_1 z_2(z_1 \oplus z_2) X(X \oplus z_1)(X \oplus z_2) = 0$, whose only roots are $z_1, z_2$ (duplicates) and $0 \notin \mathbb{F}^\times$.
  11. Degree-$3$ Cancellation for $k \ge 4$: Conditioning on fixed $z_1, \dots, z_{k-1} \in \mathcal{C}_{m,L,c}$ with $(A, B, C) = \bigoplus_{i=1}^{k-1} (z_i, z_i^3, z_i^5)$, expanding $S_1 S_5 \oplus S_3^2 \oplus S_1^3 S_3 \oplus S_1^6 = 0$ over $\mathbb{F}_2$ cancels $X^6, X^5, X^4$ identically in $X = z_k$, leaving the degree-$3$ polynomial: $$P_{A,B,C}(X) = (B \oplus A^3) X^3 \oplus A(B \oplus A^3) X^2 \oplus (C \oplus A^2 B) X \oplus (A C \oplus B^2 \oplus A^3 B \oplus A^6) = 0$$
  12. Root Classification of $P_{A,B,C}(X)$:
  13. Generic prefix ($B \neq A^3$): $P_{A,B,C}(X)$ has exact degree $3$ and therefore at most $3$ roots in $\mathbb{F}$.
  14. Degenerate cubic prefix ($B = A^3,\ C \neq A^5$): $P_{A,B,C}(X)$ collapses to the degree-$1$ equation $(C \oplus A^5)(X \oplus A) = 0$, whose unique root $X = A$ yields $S_1 = A \oplus X = 0$ and is immediately rejected by the $S_1 \neq 0$ guard (0 valid roots).
  15. Syndrome-equivalent prefix ($B = A^3,\ C = A^5$): The $k-1$ prefix is already syndrome-equivalent to the single element $A$; here $B = A^3$ is itself a quadratic equation $A'(z_{k-1}^2 \oplus A' z_{k-1}) \oplus (B' \oplus A'^3) = 0$ in $z_{k-1}$ with $\le 2$ roots whenever $A' \neq 0$.
  16. Resulting Non-Heuristic Bound: Conditioned on $(B, C) \neq (A^3, A^5)$, false acceptance has probability at most $3 / (2^{59-L} - k + 1)$ over $z_k \in \mathcal{C}_{m,L,c}$ (and $\le 3/(2^{64}-1) < 2^{-62.4}$ over $\mathbb{F}^\times$). For $k = 4$ (where $A' = z_1 \oplus z_2 \neq 0$ holds deterministically for distinct $z_1, z_2$), a union bound over $(z_3, z_4)$ gives an unconditional false-positive bound of $\le 5 / (2^{59-L} - 3)$ without any heuristic independence assumption.
  17. By contrast, allowing $d = 3$ during residual peeling or cross-peer projection would consume $(S_1, S_3, S_5)$ to solve for $(\sigma_1, \sigma_2, \sigma_3)$, leaving only $3 \times 5 = 15$ bits of cell-mapping verification at $L=0$ ($2^{-15}$ birthday grinding surface). Therefore, Snowstorm strictly restricts residual peeling and cross-peer projection to $d \le 2$, using $d = 3$ only for Type 1 raw wire cell validation (raw_count == 3).
  18. Adversarial Chosen-Syndrome Containment: A Byzantine peer that intentionally computes valid $(S_1, S_3, S_5)$ for chosen roots $\{r_1, r_2\}$ mapping to cell $c$ does not face a $2^{-64}$ algebraic barrier on its own chosen cell; instead, per-donor candidate isolation (donor_cand_missing) prevents those candidates from contaminating honest peers' projections, and any forged or fabricated set $M'_p$ is caught deterministically either by cross-miniblock conservation (Theorems 3 & 4) or by the mandatory 256-bit TxId (GETSHORTTX / ProcessTransaction) and 256-bit SubtreeARoot commitment gate (§5.4).

5.3 Short-ID Collision Resilience, Re-Signed Variant Tiebreaking, & Zero-Residual Merklix Prefix-Walk Fallback

While accidental 64-bit SipHash-2-4(k0, k1, TxId || TxHash) collisions occur with negligible probability ($\approx 2.7 \times 10^{-10}$ at $N = 100,000$), an adversary who knows the parent block $P$ could attempt a $2^{32}$ birthday search to find two of their own transactions $x_a \neq x_b$ that collide under SipHash-2-4(k0, k1, ...) (or broadcast two re-signed BIP340 witness variants of the same TxId to disjoint halves of the network). Snowstorm eliminates both vectors completely:

  1. Keying Over (TxId, TxHash) + Canonical min(TxHash) Variant Tiebreak: Because short_id hashes TxId || TxHash rather than TxId alone, two re-signed witness variants with $\text{TxId}_1 = \text{TxId}_2$ and $\text{TxHash}_1 \neq \text{TxHash}_2$ map to distinct 64-bit short IDs and never cancel in the rateless sketch. When the competing variant is fetched via GETSHORTTX, the node deterministically retains the variant with the lexicographically smaller TxHash ($\min(\text{TxHash}_1, \text{TxHash}_2)$) (capped at 1 replacement per TxId per epoch), ensuring all honest peers converge to the identical (TxId, TxHash) leaf in SubtreeA regardless of arrival order.
  2. Miniblock Deduplication: BuildRatelessMiniblockFromShortIds sorts and deduplicates short_ids before encoding so an accidental 64-bit collision within $M_p$ never creates a self-canceling $x \oplus x = 0$ syndrome with $\text{count} = 2$.
  3. Mandatory 256-Bit TxId & SubtreeARoot Verification Gate + Zero-Residual Merklix Prefix-Walk Fallback (mempool-reconciliation.md): Recovered short IDs are used solely to request full serialized transactions via GETSHORTTX. Admitted transactions are indexed in the epoch overlay by their full 256-bit TxId, and an epoch candidate is only accepted as matching a peer's epoch if the local 256-bit Merklix root SubtreeARoot matches the peer's 256-bit active_sketch_root byte-for-byte (recomputed_root_32B == peer_root_32B). If a peer's SubtreeARoot still differs from the local SubtreeARoot ($R_A \neq R_B$) after full $L = 0$ cell coverage while the subtracted sketch residual is all-zero ($\Delta_{\text{decoded}} = \emptyset$, e.g., due to an adversarial $2^{32}$ birthday collision $s_1(x_a) = s_1(x_b)$), the reconciler immediately invokes the $O(\log N)$ Merklix Radix-Tree Branch-Count / Prefix Walk specified in mempool-reconciliation.md to isolate the colliding 256-bit TxIds in 1–2 RTTs.

Theorem 3 (Generalized Cell Capacity Conservation & Exhausted-Cell Local-Extra Elimination)

For any miniblock $m$ and cell $c \in [0..31]$ received from Peer $p$ with raw wire count $\text{raw\_count}_{m,c} = |M_p(m, c)|$, partition $M_p(m, c)$ and $M_{\text{local}}(m, c)$ into:

  • $A_{\text{peeled}}(m, c) = (M_p \setminus M_{\text{local}})(m, c) \cap \text{confirmed\_has}_p$ (missing items already peeled from Peer $p$),
  • $U^+(m, c) = (M_p \setminus M_{\text{local}})(m, c) \setminus \text{confirmed\_has}_p$ (unpeeled missing items in cell $c$),
  • $B(m, c) = (M_p \cap M_{\text{local}})(m, c)$ (shared items in cell $c$), and
  • $L_{\text{unpeeled}}(m, c) = |B(m, c)| + |U^-(m, c)|$ (local items in $M_{\text{local}}(m, c)$ not yet marked missing from Peer $p$).

Then at every step of decoding, the residual cell's delta_count satisfies the exact identity: $$\boxed{\text{cell.delta\_count} + L_{\text{unpeeled}}(m, c) = \text{raw\_count}_{m,c} - |A_{\text{peeled}}(m, c)| = |U^+(m, c)| + |B(m, c)| \ge 0}$$

From this identity, three powerful operational rules follow immediately:

  1. Capacity Overflow Fraud Proof (|A_peeled| > raw_count): If peeled_missing_count[c] > raw_count[c] at any point, Peer $p$ has claimed more missing items in $(m, c)$ across its miniblocks than raw_count[c] permits $\implies$ Type 3 Fraud Proof (MarkPeerFraudulent(peer_id)).
  2. Exhausted-Cell Veto (peeled_missing_count[c] >= raw_count[c]): As soon as peeled_missing_count[c] == raw_count[c], $|U^+(m, c)| = 0$, so cell $(m, c)$ immediately vetoes any further missing-item candidate for Peer $p$ in HasZeroCellVetoForPeer—even before local-extra items in $(m, c)$ are peeled!
  3. Exhausted-Cell Local-Extra Elimination & Syndrome Zero Check: When peeled_missing_count[c] == raw_count[c], $|B(m, c)| = 0$, which proves $M_p(m, c) \cap M_{\text{local}} = \emptyset$. Therefore, every unpeeled local item $l \in M_{\text{local}}(m, c)$ is provably absent from Peer $p$ ($l \in M_{\text{local}} \setminus M_p$) regardless of how many local items map to $(m, c)$! The decoder immediately peels all such $l$ via PeelLocalExtraFromPeer(peer_id, l), after which mb.cells[c] must equal (0, 0, 0, 0) (IsZero()). If !mb.cells[c].IsZero(), Peer $p$'s syndromes in $(m, c)$ are inconsistent with its claimed items $\implies$ Type 3 Fraud Proof (MarkPeerFraudulent(peer_id)).

Theorem 4 (32-Cell $L = 0$ Partition Conservation Law Keyed on (peer_id, candidate_root))

At decimation level $L = 0$, MapShortIdToMiniblockCell is a total function $M_p \to \{0, \dots, 31\}$ for every miniblock_id. Therefore, across all $L = 0$ miniblocks $m$ generated from a peer's epoch set $M_p$ for a given candidate_root, the global 4-tuple: $$\mathcal{I}(M_p, \text{candidate\_root}) = \left(\sum_{c=0}^{31} \text{count}_{m,c},\ \bigoplus_{c=0}^{31} s_{1,m,c},\ \bigoplus_{c=0}^{31} s_{3,m,c},\ \bigoplus_{c=0}^{31} s_{5,m,c}\right) = \big(|M_p|,\ S_1(M_p),\ S_3(M_p),\ S_5(M_p)\big)$$ is strictly invariant.

  • Per-(peer_id, candidate_root) Scoping (Pass 15A): Both the Type 2 $L=0$ invariant table (m_peer_l0_invariants) and Type 3 cell-capacity/zero-cell state are keyed on (peer_id, candidate_root) (MAX_ROOT_ROTATIONS_PER_PEER = 4). Consequently, an honest peer whose working epoch $M_p$ legitimately evolves to a new candidate_root mid-stream never triggers a false-positive fraud proof, whereas any peer transmitting two $L = 0$ miniblocks under the same candidate_root with differing $\mathcal{I}$ (or an $L > 0$ miniblock for that candidate_root whose cell count sum exceeds $|M_p|$, or exceeding MAX_ROOT_ROTATIONS_PER_PEER) is caught in $O(1)$ by a Type 2 Fraud Proof.

5.4 Scope of Algebraic Sketch-Inconsistency Proofs vs. Cryptographic Set Commitments

It is important to state the exact security boundary of Types 1, 2, and 3:

  • What Types 1, 2, and 3 Prove (Algebraic Sketch Consistency): They prove in $O(1)$ whether a peer's RatelessMiniblock stream is algebraically self-consistent and conservation-preserving (preventing corrupted-syndrome sketch poisoning that silently stalls IBLT, Graphene, or Minisketch decoders).
  • What Binds the Sketch to Actual Valid Transactions (256-Bit SubtreeARoot + MemPoolAccept): A Byzantine peer could construct a mathematically self-consistent sketch of a synthetic set $M'_p$ of nonexistent short IDs. That attack is defeated not by the sketch syndromes alone, but by the two-layer cryptographic binding: (1) every decoded short ID must resolve via GETSHORTTX / SHORTTX to a full consensus-valid transaction passing ProcessTransaction, and (2) the resulting Merklix overlay must match the peer's advertised 256-bit SubtreeARoot (recomputed_root_32B == peer_root_32B).

Snowstorm further distinguishes between immediate on-link peer shunning (which requires no public-key signatures) and network-wide relayable inconsistency proofs:

  1. Immediate On-Link Peer Shunning (MarkPeerFraudulent + RemovePeer):
  2. Every node independently verifies Type 1, Type 2, and Type 3 invariants on all incoming RATELESSMB frames over its direct P2P links.
  3. When any invariant fails for peer_id, V2PeerProtocolHandler immediately records peer_id in m_fraudulent_peers, executes RemovePeer(peer_id) to purge all miniblocks and uncorroborated candidate short IDs from peer_id, and signals Misbehaving to disconnect the offending peer so honest peers' miniblocks finish decoding cleanly without contamination.
  4. Third-Party Relayable Compact Fraud Proofs (Signed Validator / Node Identity Extension):
  5. Because raw RATELESSMB frames over P2P transport are not signed by a long-term key by default, an unsigned miniblock cannot be forwarded to a third party without allowing an attacker to fabricate a corrupted frame and blame an innocent peer.
  6. However, notice a remarkable algebraic property of Theorem 1 (Type 1) and Theorem 4 (Type 2): both invariants are 100% intrinsic to the sender's own miniblocks and do not depend on the receiver's local mempool $M_{\text{local}}$!
  7. Therefore, when a staking Avalanche peer (identified by its authenticated ProofId / staking public key) or signed-session peer attaches a 64-byte Schnorr signature (BIP340) over H("SNOWSTORM_MINIBLOCK_SIG", ChainID || epoch_id || scope || candidate_root || miniblock_id || level || MerkleRoot32(cells[0..31])) (explicitly committing to the 32-byte candidate_root), any node can construct a self-contained, publicly relayable compact fraud proof:
  8. Relayable Type 1 Proof ($\le 270\text{ bytes}$): Signed commitment header (32 B candidate_root + 17 B stream metadata + 64 B Schnorr signature) + cell_index (1 B) + offending 28-byte cell (count, S1, S3, S5) + 5-step Merkle inclusion branch (5 * 25.6 B or 160 B uncompressed; 270 B total with compact cell-commitment framing). Any node on the network verifies the signature and confirms !ValidateSingleCell(cell) in $< 5\ \mu\text{s}$.
  9. Relayable Type 2 Proof (2,018 bytes): Two signed $L = 0$ RatelessMiniblock frames (2 * (913 + 32 + 64) B) from the same ProofId for the same (epoch_id, scope, candidate_root) (commit_A.candidate_root == commit_B.candidate_root) whose 32-cell XOR sums $\mathcal{I}(m_1) \neq \mathcal{I}(m_2)$ disagree. Binding candidate_root inside the signed preimage ensures an honest peer that legitimately transitions to a new candidate_root between two $L=0$ frames can never have its two frames combined into a false Type 2 proof.

6.2 Hypergeometric Peer Sampling via Rateless BCH Fountain Codes, Sequential Confidence Accumulation, and Phase 2 Majority Boundary Filtering

Snowstorm unifies within-round finite-population sampling of peers' mempools via rateless BCH fountain codes, across-round confidence accumulation, the 1-RTT fast path, and Phase 2 boundary filtering under hypergeometric sampling without replacement:

  1. Within-Round Hypergeometric Concentration (Serfling's Inequality) & Monotone Likelihood Ratio (MLR): Under Assumption A2 ($f_{\text{peer}} \le \beta < 1/4$), if honest nodes are split so at most half of honest peers plus all $\beta N_{\text{peers}}$ Byzantine peers support a minority root $R$ (composite null hypothesis $H_0 : M \le M_0$), at most $M_0 = \lfloor \frac{1+\beta}{2} N_{\text{peers}} \rfloor$ peers in the population of $N_{\text{peers}}$ can vote for $R$ ($p_0 = M_0 / N_{\text{peers}} \le 0.625$ at $\beta = 0.25$), whereas under converged honest agreement ($H_1$) at least $M_1 = \lceil (1-\beta) p_{\text{honest}} N_{\text{peers}} \rceil$ peers hold $R$. Because the $\text{Hypergeometric}(N_{\text{peers}}, M, K_t)$ family has a monotone likelihood ratio (MLR) in $Y_t$ with respect to population support $M$, testing against the boundary $M_0$ dominates all $M \le M_0$: $$\Pr_{M \le M_0}[Y_t \ge \alpha K_t] \le \sum_{j=\lceil \alpha K_t \rceil}^{\min(K_t, M_0)} \frac{\binom{M_0}{j}\binom{N_{\text{peers}}-M_0}{K_t-j}}{\binom{N_{\text{peers}}}{K_t}} \;\le\; \exp\!\left(-\frac{K_t \, D_{\text{KL}}(\alpha \,\|\, p_0)}{1 - \frac{K_t-1}{N_{\text{peers}}}}\right)$$
  2. Across-Round Sequential Log-Likelihood Accumulation ($S_t(R)$ vs. Finite-Horizon CUSUM $\mathcal{C}_t$) & Adaptive $K_{t+1}$: Each polling round $t$ contributes hypergeometric log-likelihood bits: $$B_t(Y_t, K_t, N_{\text{peers}}) = \log_2 \frac{P_{\text{Hyp}}(Y_t \mid N_{\text{peers}}, M_1, K_t)}{P_{\text{Hyp}}(Y_t \mid N_{\text{peers}}, M_0, K_t)}$$
  3. Per-Root Unreflected LLR ($S_t(R)$): Keyed to a specific candidate root $R$, the unreflected log-likelihood sum $S_t(R) = \sum_{i=1}^t B_i(R)$ (resetting to $0$ only when the local candidate root $R$ itself changes) makes $2^{S_t(R)}$ a non-negative supermartingale under $H_0$, so Ville's inequality bounds the infinite-horizon false-lock probability for root $R$ by $\Pr_{H_0}[\exists t \ge 1 : S_t(R) \ge B_{\text{target}}] \le 2^{-B_{\text{target}}}$.
  4. Finite-Horizon Reflected CUSUM ($\mathcal{C}_t = \max(0, \mathcal{C}_{t-1} + B_t)$): When using the reflected CUSUM accumulator $\mathcal{C}_t = \max(0, \mathcal{C}_{t-1} + B_t)$ over an epoch horizon of at most $T$ rounds, a union bound over the at most $T$ excursions from zero gives: $$\Pr_{H_0}\!\left[\max_{1 \le t \le T} \mathcal{C}_t \ge B_{\text{target}}\right] \;\le\; T \cdot 2^{-B_{\text{target}}} \;\le\; \varepsilon \qquad \big(\text{for } B_{\text{target}} = \log_2(T/\varepsilon)\big)$$ Between rounds, the next sample size $K_{t+1}$ is chosen adaptively from the remaining confidence gap $\Delta B = B_{\text{target}} - \mathcal{C}_t$: $$K_{t+1} = \text{clamp}\!\left(\left\lceil \frac{B_{\text{target}} - \mathcal{C}_t}{\bar{b}(\hat{p}_t, N_{\text{peers}})} \right\rceil,\; K_{\min},\; N_{\text{peers}}\right)$$

  8. $\beta = 0.20$: $10.3\text{ bits}$ ($K_1 = 24$) / $13.9\text{ bits}$ ($K_1 = 32$, locking in 3 RTTs);
  9. $\beta = 0.24$ (near A2 limit): $7.3\text{ bits}$ ($K_1 = 24$) / $9.9\text{ bits}$ ($K_1 = 32$, locking in 3–4 RTTs at $K=32$, or 1 RTT at $K_1 \approx 96$).
  10. Stage A — Two-Phase Union (max_unrestricted_union_rounds_ = 2) & Three-Valued Phase 2 Majority Boundary Filtering (Pass 15B):
  11. 6.3 Symmetric Transitive Conflict Quarantine, Sticky Winner Promotion & Non-Self-Referential BatchId(E) Tiebreaking

Theorem 5 (Order-Independent & Incremental Confluence of Symmetric Conflict Quarantine)

Let $F(S) = (\text{Active}(S),\, \text{Quarantined}(S),\, \text{ConflictedOutpoints}(S))$ be the state produced by feeding a sequence of valid transactions $S$ into UnionEpochTransaction. Because UnionEpochTransaction retains every collided outpoint $o$ (and every created_coin of a quarantined transaction) in $\text{ConflictedOutpoints}(S)$ and retains the full transitive closure of colliding transactions in $\text{Quarantined}(S)$ rather than discarding them, $F$ is a join-homomorphism on the conflict dependency graph: $$\boxed{F(A \cup B) = F(B \cup A) \qquad \text{and} \qquad F\big(F(A) \cup B\big) = F(A \cup B)}$$ for all transaction arrival sequences $A, B$. Every peer that receives the same union of candidate transactions $A \cup B$ in any permutation or incremental wave partition arrives at the exact same conflict-free core $\text{Active}(A \cup B)$ and exact same quarantine set $\text{Quarantined}(A \cup B)$.

  • Strictly Causal, Non-Self-Referential BatchId(E) Resolution & Sticky Winner Protection (ResolveQuarantinedTxsWithBatchId): Epoch $E$ freezes and finalizes only the conflict-free core $\text{Active}(E)$, producing canonical $\text{BatchId}(E)$. The transactions in $\text{Quarantined}(E)$ never re-enter Epoch $E$; instead, once $\text{BatchId}(E)$ is fixed, $\text{Quarantined}(E)$ (plus deferred_next_epoch_txs_) are scored deterministically via: $$\text{Score}(E, T) = \text{BLAKE3}\big(\texttt{"SNOWSTORM\_CONFLICT\_TIEBREAK"},\ \text{BatchId}(E) \;\|\; T.\text{tx\_hash}\big)$$ and resolved topologically in dependency waves into Epoch $E + 1$ (the next epoch's working overlay). To prevent continuous contention on a shared-state UTXO (such as an AMM liquidity pool) from repeatedly quarantining the promoted winner in Epoch $E + 1$, the winning transaction $W(C_m)$ of each quarantined conflict component is marked sticky (conflict-immune) for Epoch $E + 1$: any newly arriving transaction in Epoch $E + 1$ that conflicts with a sticky promoted winner is deferred directly to deferred_next_epoch_txs_ rather than quarantining $W(C_m)$. This guarantees that every contended shared-state UTXO commits at least one winning state transition per epoch (4–10 transitions/sec at 100–250 ms epochs, or higher when combined with keeper batching or sharded pool UTXOs).

6.4 Avalanche Batch Finalization: Uncontended Single-Poll Fast Path vs. Multi-Round Snowball

Once a node's active epoch layer reaches hypergeometric confidence $\mathcal{C}_t \ge B_{\text{target}}$ (mempool $\to$ frozen), a staking node registers a MempoolBatchAnnouncement (MSG_AVA_MEMPOOL_BATCH) for Avalanche polling (tryFreezeAndRegisterNextEpochBatch).

  1. Why Contention & the "$N$ Distinct Initial Roots" Bootstrap Stall Vanish Before Voting Begins: If $N$ nodes begin an epoch holding $N$ slightly different transaction sets with distinct opaque roots $R_0, R_1, \dots, R_{N-1}$ (for example, 10 nodes holding 10 distinct roots where each root has only $1/N$ initial support), pure Snowball polling over opaque root hashes stalls indefinitely because no single root can cross a supermajority polling threshold $\alpha$, and advisory similarity sketches (such as 1 KiB MinHash) only estimate set distance without reconciling the sets. Snowstorm eliminates both problems in Stage A: a single 913-byte RatelessMiniblock both provides an exact signed symmetric-difference count estimator ($\sum_{c=0}^{31} |\Delta c|$) and algebraically decodes the missing transactions across $K_t$ peers simultaneously, while Phase 1 union + Phase 2 symmetric minority-support demotion (§6.2) and symmetric transitive conflict quarantine (§6.3) drive all honest nodes to construct the exact same BatchId(E) (subtree_a_root, utxo_root, tx_count) before Stage B root confirmation or Avalanche voting begins.
  2. Uncontended Hypergeometric Fast-Path (setFastPathConfidenceThreshold) vs. Contended Snowball (AVALANCHE_FINALIZATION_SCORE = 128):
  3. When an epoch slot (prev_block_hash, epoch_seq) has zero competing proposals (!hasEpochConflict(prev_block_hash, epoch_seq)) and 100% unanimous 0 (accept) votes across a hypergeometric sample achieving $B_1 \ge B_{\text{target}}$, it finalizes on the uncontended fast path (setFastPathConfidenceThreshold), whereas any competing MempoolBatchAnnouncement at the same (prev_block_hash, epoch_seq) or any non-zero error vote (v.GetError() != 0) immediately calls markMempoolBatchConflict(batchId), disables fast-path credit, triggers AIMD settling-window backoff (m_adaptiveEpochController.recordMissOrConflict()), and requires full multi-round Snowball (AVALANCHE_FINALIZATION_SCORE = 128) to break symmetry.
  4. Unweighted P2P Sampling vs. Intentional Sybil-Weighting by Bonded Stake (peering.md & consensus.md):
  5. Layer 1 (Unweighted P2P Snowstorm Reconciliation): Because set reconciliation is a pre-consensus optimization rather than hard consensus, SelectSnowballPeerSample samples across the node's P2P peer neighborhood (250 outbound + ~250 inbound per peering.md). An adversary on P2P links cannot forge valid transactions (ProcessTransaction), cannot forge SubtreeARoot, and any poisoned sketch triggers immediate on-link shunning (MarkPeerFraudulent). At worst, an eclipse of a node's P2P links can delay that node's FrozenEpoch convergence so it falls back to cmpctblock (Stage 2) without affecting consensus safety.
  6. Layer 2 (Intentional Sybil-Weighting by Bonded Stake in Avalanche MSG_AVA_MEMPOOL_BATCH): Rather than being "anti-Sybil," stake-weighted Avalanche performs intentional Sybil-weighting by coin amount: virtual voting identities are allocated in direct proportion to cryptographically proven UTXO value (ProofId proofs registered in avalanche::Processor) rather than free IP socket creation, while Proof-of-Work remains the sole hard-consensus authority.

6.5 Theorem 6 (SnapBlock Unconditional Soundness & Conditional Completeness)

Why can a receiving node reconstruct and validate a full Lotus V2 block $B_h$ from a compact SealedHeader (SnapBlock = 134-byte V2 header $H$ + serialized coinbase transaction $C_{\text{cb}} = vtx[0]$, or 240 bytes on legacy 84B-header benchmark frames) and a cached FrozenEpoch layer $L_k$ without re-executing the ordinary transactions $vtx[1..n-1]$ or recomputing the UTXO Sparse Merkle Tree?

  1. Coinbase UTXO Maturity Decoupling (consensus.md C03, C12, C17, C26) & $O(1)$ Monetary State Evaluation (C16, C25): In Lotus V2, coinbase outputs created in block $B_h$ ($h \ge 1$) do not enter the UTXO Sparse Merkle Tree at height $h$—block $h$'s UtxoRoot inserts parent block $h-1$'s coinbase outputs and applies $L_k$ under two-phase outputs-then-inputs CTOR resolution (C12), while delaying block $h$'s own coinbase outputs to height $h + 1$ (C17). Consequently, the post-block UtxoRoot(L_k) at height $h$ is 100% invariant to Miner $M$'s coinbase transaction $C_{\text{cb}}$. Meanwhile, MonetaryState at height $h$ (88 bytes: 56-byte core monetary state plus 32-byte HistoryRoot_h) depends on the pre-cached ordinary-transaction aggregates $(F(L_k),\, B_{\text{fee}}(L_k),\, C(L_k))$ together with the newly arrived coinbase's cost $C(C_{\text{cb}})$ and payout $\text{ValueOut}(C_{\text{cb}})$, which evaluate in $O(1)$ time from $C_{\text{cb}}$ alone!
  2. Two-Leaf TxRoot Decomposition (consensus.md C07): $$\text{TxRoot}(B_h) = H_{\text{txroot}}\big(\texttt{0x03} \;\|\; \text{CoinbaseLeaf}(C_{\text{cb}}) \;\|\; \text{SubtreeA}(L_k)\big)$$ Thus verifying $\text{TxRoot}(B_h)$ for a new coinbase $C_{\text{cb}}$ requires one BLAKE3 evaluation combining $\text{CoinbaseLeaf}(C_{\text{cb}})$ with the pre-computed 256-bit $\text{SubtreeA}(L_k)$.
  3. Unconditional Soundness ($\implies$) and Conditional Completeness on Layer Match ($\impliedby$): Let $L_k$ be a local FrozenEpoch layer anchored at parent block $P = B_{h-1}$ whose ordinary transactions $vtx[1..n-1]$ were all validated against $S_{h-1}$ (with UtxoRoot(L_k), total native fees $F(L_k)$, mandatory token and 50%-remaining-fee burn $B_{\text{fee}}(L_k)$, burned fee share $\text{BurnedFees}(L_k)$, and ordinary cost $C(L_k)$ pre-computed). Let $C_{\text{block}} = C_{\text{envelope}} + C(L_k) + C(C_{\text{cb}})$ be the total block cost including the coinbase (C25), $K(C_{\text{cb}})$ be the coinbase byte floor (P05), $R(C_{\text{block}}, E_{h-1})$ be the parabolic block burn floor (C25), and $U_{\text{req}}(C_{\text{cb}}, L_k) = \max\big(K(C_{\text{cb}}),\, \max(0,\, R(C_{\text{block}}, E_{h-1}) - \text{BurnedFees}(L_k))\big)$ be the required C16 underclaim. Define the fast-path predicate: $$\text{FastPathAccept}(H, C_{\text{cb}}, L_k) :\iff \begin{cases} \text{CheckBlockHeader}(H) \land \text{ContextualCheckBlockHeader}(H, P) \land \text{CheckCoinbase}(C_{\text{cb}}, h, P) \\ \text{ValueOut}(C_{\text{cb}}) \le S_h + F(L_k) - B_{\text{fee}}(L_k) - U_{\text{req}}(C_{\text{cb}}, L_k) \\ H.\text{tx\_root} == H_{\text{txroot}}(\texttt{0x03} \,\|\, \text{CoinbaseLeaf}(C_{\text{cb}}) \,\|\, \text{SubtreeA}(L_k)) \\ H.\text{state\_root} == H_{\text{state}}\big(\texttt{0x00} \,\|\, \text{ChainID} \,\|\, u64(h) \,\|\, \text{UtxoRoot}(L_k) \,\|\, \text{Bytes}(\text{MonState}(P, H.\text{nBits}, C_{\text{block}}, \text{HistoryRoot}_h))\big) \end{cases}$$ Then:
  4. Unconditional Soundness ($\implies$): $\text{FastPathAccept}(H, C_{\text{cb}}, L_k) \implies \mathcal{V}(\text{Assemble}(H, C_{\text{cb}}, L_k), S_{h-1}) = 1$. The fast path never admits a consensus-invalid or overclaiming block.
  5. Completeness Conditioned on Layer Match ($\impliedby$): Conditioned on $\text{SubtreeA}(B_h) = \text{SubtreeA}(L_k) \in \{L_k, L_{k-1}, L_{k-2}, L_{\text{spec}}\}$, $\mathcal{V}(B_h, S_{h-1}) = 1 \iff \text{FastPathAccept}(H, C_{\text{cb}}, L_k)$. Any consensus-valid block $B_h$ whose transaction set matches no cached layer is a fast-path cache miss that routes to the Stage 2 cmpctblock fallback validator without being rejected.
