# Explicit V2 transaction calls

`@lotus/v2-payment-compiler/transaction-runtime` exposes `prepareTransactionCall(intent)` and `finalizeTransactionCall(plan, signatures)`. The maintained Python peer is `python/lotus_v2_transaction_runtime.py` (`prepare_transaction_call`, `finalize_transaction_call`). Both require every input coin, selected path, witness method, output, ChainID, and a caller-selected candidate `dustLimitAtoms`. They perform no RPC, signing, VM execution, lock or maturity check.

An intent has ordered `inputs` and `outputs`. A spend input gives its outpoint, sequence, resolved `coin`, `pathIndex`, and one `{artifact, methodName, args}` witness per index in `coin.paths[pathIndex]`. A mint input gives a token artifact, mint method, and witness args. Its token ID comes from the artifact root, and its positive delta is derived from checked per-token input/output sums. A mint Amount parameter is node-pushed and is absent from witness args. Each `Signature` arg is `null`/`None` at preparation. A caller attaches 64-byte FULL signatures by request key `inputIndex:witnessIndex:argumentName` at finalization.

Outputs carry explicit `flags` (`0` native spendable, `1` token spendable, `2` native burn, `3` token burn), a `bigint`/checked Python `int` value, `tokenId` for flags 1 or 3, and `branches`/`paths`. Spendable outputs require ordered nonempty paths; burn outputs require `paths: []`. Amounts on wire are u64; per-asset sums use checked u128. Mint deltas must also fit signed int128 because the VM pushes that width. The native fee must cover both the projected complete-wire byte floor and `2 * dustLimitAtoms * tokenOutputCount`. The dust parameter is explicit because its genesis value is not frozen. The projected size counts every pending FULL signature as 64 bytes.

The planner validates canonical framing, selected proof roots, positional witness counts, output policy grammar, asset accounting, duplicate outpoints, mint coverage, and fee floors. The tool candidate caps each script and argument at 8192 bytes, each proof at 64 siblings, each call at 32 arguments, each output at 16 branches and paths, and input/output counts at the u16 wire maximum. These are tool bounds; the full network parameter manifest remains to be frozen. Plans report signature, VM invocation, contextual and block stages as `unavailable`. A required rules branch or successor path covenant becomes valid only when a validator executes every branch and applies chain context.
